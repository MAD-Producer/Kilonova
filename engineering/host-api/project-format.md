# 工程 JSON：单一当前版本

工程文档必须显式包含 `version: 25`，代码以 `motion_model::CURRENT_PROJECT_VERSION` 为准。每个图层显式保存 `shy` 列表组织标记，不影响 `visible` 或渲染。每个合成显式保存 `work_area: { in_frame, out_frame }`，起点包含、终点不包含，且 `0 <= in_frame < out_frame <= frames`。只接受当前版本；过去版本与未知未来版本均返回格式错误。`Project::migrate()` 已删除，打开工程不升级、不修复、不覆盖原 JSON。工程版本不再取决于用了哪项功能。

`Project::new` 写入当前版本，`Project::validate` 只做一次版本相等检查，其后仍执行现有数据、资源、引用与范围校验。加载与编辑器初始化调用 validate，错误沿原有 Result/宿主信道返回；失败不替换当前工程。命令修改摄影机、音频、矢量、采样等功能时不会重新计算版本。

必填设置必须在 JSON 中存在，包括构造器的初始值：3D、旋转顺序、混合与采样设置、摄影机创建状态与胶片宽度、曲线插值、蒙版参数、音视频播放设置等。序列化不会因值等于初始值而省略这些设置。缺失表示文档不完整，不能静默推断。

None、空内容集合、可选 LUT 覆盖及命令的部分修改参数仍按它们原本的语义处理。具体逐字段清单位于 [当前工程格式契约验收](../validation/project-format-contract.md)。

本契约取代其他宿主 API 历史文档里的逐特性工程版本门槛和自动迁移说明。效果包 `.msfx`、节点文档、SDK、帧包和 MCP 协议拥有独立版本；本次不修改它们的格式、字节身份或渲染语义。

`set_work_area` 命令接受必填的整数 `in_frame`、`out_frame`，可通过既有 `composition` 路由编辑指定合成。范围独立于图层区间和关键帧；修改支持批次原子性、手势取消、撤销及重做。合成设置改变时，全范围跟随新时长；自定义范围按原有 `preserve_frames` / `preserve_seconds` 策略调整，再限制到新合成内至少一帧。缩短合成不会因范围越界产生空区间。

导出作用域在冻结文档上解析，整段合成仍为默认。选择工作范围时，画面按原合成的绝对帧求值，MP4 从零开始计时，音频使用两个绝对边界的 `floor(frame * 48000 / fps)` 样本位置，避免对每帧样本数或区间长度取整造成累计误差。改变工作范围不限制普通场景采样。
