# 插件作者窗口：软件内入口与关闭流程

主工作区“窗口 → 插件编辑器…”打开已有 `.msplugin`；命令行
`--plugin-editor <path>` 继续支持独立启动。二者共用 `window.rs` 和作者工作区，
不复制布局、节点、源码或教程逻辑，也没有新建作者工程向导。

软件内工具复用主事件循环，在独立原生窗口中运行。按 WindowId 优先分发事件，
工具输入不进入主时间轴、主窗口拖放或浮动面板；工具关闭只结束自己的生命周期。
工具不能设置宿主事件循环的退出/等待策略。大型作者状态由 Box 持有，
避免增加本已较大的 Shell 在 Windows 主线程栈上的占用。

## 生命周期与草稿

文件选择、预备引擎和资源回收由专用工作线程处理。任务与回复队列容量各为 1，
控制器只允许一个在途请求；重复点击聚焦已有窗口或等待已有打开操作。
工作完成后主线程创建窗口。正常关闭先把工具资源交给工作线程回收，
主界面不 join GPU 清理。临时目录属于工具状态，在引擎和 surface 析构后清理。

关闭主软件时先处理作者草稿，再进入原有主工程关闭流程。“继续编辑”取消主软件关闭；
“保存并关闭”等待现有保存事务和资源回收；保存失败保留草稿。
异常预览退出但存在草稿时保留作者状态，关闭工具时提供原生保存/放弃/取消恢复流程。
这条异常恢复的完整按钮矩阵尚未验收，不应视为已验证的故障恢复保证。

每个生命周期请求带独立的 request/phase/start，发布在途状态并记录 Info start 后才进入
阻塞操作；完成清除状态，故障记录原始原因和耗时。panic 沿用原进程 hook，
捕获后通过错误回复回传；没有静默重启、超时重试或隐式替换返回值。
系统文件选择或驱动调用不返回时，线程及在途状态仍保留；当前不强制终止线程。

## 当前边界与下一阶段

同一进程不等于共享实际插件实例。工具目前仍有隔离的示例引擎；底部明确显示
未连接宿主，不读取主窗口选中效果、动画值或播放状态。

下一步先完成最小 `.msfx` 布局发布（M5a），保留包身份、公共参数契约和 NativeLayout；
再以受控 session 接真实实例（M4b），处理身份/revision、断连、取消和输入归属。
不得用参数显示名称匹配绕过包身份，也不得把示例渲染称为宿主实例预览。
粒子目标样例所需的通用多对象能力属于 M5b，不恢复原有内置粒子预设。

实际检查与剩余限制见 [验收记录](../validation/plugin-editor-host-entry.md)。
