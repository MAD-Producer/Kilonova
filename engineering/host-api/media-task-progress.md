# 媒体任务的可确定与未知进度

`DecodeAudio` 和 `Platform::decode_audio` 的取消回调接收 `Option<f64>`：总量已知时是当前阶段的比例 `Some(0..=1)`；总帧数未知时是 `None`。每个检查点都要调用回调，未知总量不能跳过取消检查，也不能用零、NaN 或负数冒充未知状态。

音频 `TaskStatus` 和视频 `VideoTaskStatus` 都保留 `progress` 字段。序列化为数字表示当前阶段的比例；序列化为 JSON `null` 表示尚无可计算的总量。字段不会被省略。排队、打开、无总长度的复制、探测和波形阶段可以是未知；进入下一阶段时进度不保证单调。只有任务状态才能判断失败、取消、待提交或最终成功，不能根据比例判断终态。

成功完成准备/探测/缓存时，进度为 `1.0`。取消或失败保留最后一个合法进度及现有状态语义，不伪造成功。解码供应方提交 NaN 或无穷大时，任务通过已有 Result 和任务错误信道失败；不会将非法比例静默变成未知状态。有限比例继续限制到 `[0,1]`。

这是媒体任务协议的状态说明，不是工程 JSON 版本或渲染语义变化。工程文件、PCM、波形和效果包格式不变。项目打包任务按字节数计算的 `PackageTaskStatus.progress` 保持既有数字协议；导出和采样任务也不在本次修改范围内。

消费者应在 `progress` 为 null 时显示不确定进度，并保留取消入口。本次按用户安排只推进后台契约；桌面导入状态目前仍有 `unwrap_or(0.)` 的显示回退，显示层后续处理，不能据此声称用户可见的固定 0% 已经整改。Android 已停止迭代，本次仅同步 Rust trait 签名，不宣称完成设备或 Kotlin 界面验收。
