# 插件编辑器：节点、界面与调试统一方案

状态：M1 工程格式、绑定与逻辑编译已完成本地验收；可视化编辑器尚未实现。
数据契约与无窗口检查入口见 [作者工程](plugin-editor-source.md)。用户已确认结构化布局、拖拽与尺寸调整，
并将原来的 UI 编辑器扩展为「插件编辑器」，要求软件内与独立启动两个入口。
现有属性面板整改已单独提交 [PR #557](https://github.com/MAD-Producer/Kilonova/pull/557)，
该 PR 未加入插件编辑器代码；本地相关检查 69 项与 FFmpeg 构建通过，远端 CI 另行确认。

## 1. 目标与工作流

作者通过同一份插件工程完成：搭节点或编写 WGSL → 暴露公共参数 → 设计参数面板 →
实际操作预览 → 打包 `.msfx`。布局设计预览与最终插件面板使用同一个原生渲染器，
不能用另一份 HTML、截图或手工拼装面板充当预览。

粒子编辑器是目标样例，能力目标来自用户指定的
`engineering/host-api/plugin-ecosystem-capabilities.md`。该文档目前只在另一个
本地工作区中存在，其能力矩阵含历史 Android、迁移和未实现能力描述；本方案
以当前代码核验为准，首期只推进桌面，工程格式只接受当前版本并保留版本字段。
不恢复已经移除的内置粒子、光效预设，不承诺重建被参考软件的参数或像素结果。

## 2. 已有能力与缺口

| 项目 | 当前代码 | 本轮处理 |
| --- | --- | --- |
| 节点图、公共参数 | `motion-graph::GraphDocument`、`PublicParameter` 与桌面 `node_editor` 已有 | 复用图模型、校验、编译和交互，不另写节点画布 |
| 插件原生 UI | `motion-effects/src/native_ui.rs` 为协议 1 的分组/槽位描述 | 新增结构化布局契约，不能把现有槽位当作已有可视化设计器 |
| 参数编辑与撤销 | `motion-core/src/plugin_editor.rs` 的 scoped session、revision、参数/颜色手势已有 | 编辑真实插件实例时沿用这些受控事务 |
| 桌面插件专属编辑页 | 当前桌面没有可复用的完整实现 | 增加宿主适配，复用现有 UI 与引擎 |
| 多发射器子对象 | `SceneSettings` 仍是固定结构，没有通用 `ObjectAction` | 作为粒子样例的明确前置，单独补齐状态与命令后再接列表 |
| 独立工具连接运行中的软件 | 当前没有直接可复用的连接入口 | 设计本机显式连接与受限会话，不能宣称现有 MCP 已提供此功能 |

## 3. 两种入口与运行上下文

第一版优先在同一程序中提供两种启动模式，共用编辑器控制器和原生控件。
独立快捷方式进入插件编辑器模式，不要求先打开主编辑工作区；是否另行分发
独立可执行文件属于打包选择，不影响工程或运行时契约。

- **软件内**：从窗口入口进入，可新建插件，或为当前支持编辑的插件实例调试。
  预览复用当前合成与时钟，不创建第二个播放源，也不让后台时间轴重复处理输入。
- **独立启动**：打开插件源工程，编辑节点、布局和资源，使用明确标注的示例参数
  预览控件；无需宿主即可保存和重开。真实效果预览须有本地预览引擎或显式连接的
  宿主上下文；未具备该能力时应禁用并解释，不能显示假成功。
- **连接宿主**：固定目标工程、图层、插件实例、包版本/hash、参数契约和 revision。
  断开或目标变化保留作者草稿，停止向旧实例写入，提示重新绑定。

`AuthoringContext` 管理可编辑插件源，`PreviewContext` 管理示例值或真实宿主绑定。
界面设计与交互预览为显式切换的模式：设计拖动只改布局，交互拖动只改参数。
宿主适配器是共享编辑器的依赖边界，不让单独启动入口依赖主窗口对象。

## 4. 三个工作区与共同状态

- **逻辑**：每个效果选择节点图或 WGSL 源码作为权威来源。节点模式保留现有图操作，
  维护公共参数及其逻辑引用，并可只读查看生成的 WGSL；源码模式直接编辑 WGSL。
- **界面**：左侧组件库/结构树，中间原生面板，右侧布局与绑定检查器；顶部提供
  设计/交互预览、宽窄尺寸、撤销/重做和保存。拖拽使用明确的插入提示。
- **预览与调试**：查看实际效果、操纵生成面板、定位校验与运行错误，执行打包。

三者共享当前作者工程、选择目标、脏状态、诊断和公共参数表。节点图或 WGSL、面板布局、
公开参数与资源一起保存；不把工程真实动画烘焙进插件默认值。
第一条纵向流程只需简单图/着色器和真实参数面板，不以先补齐全部粒子模拟为前提。

WGSL 源码与图编译产物不得同时成为同一效果的可写权威；切换来源必须显式处理草稿。
不承诺将手写 WGSL 反向还原成节点图。首批源码编辑提供原生文本输入、语法高亮、
编译检查、错误行列定位和预览；保留现有 IME、选择、快捷键和文本撤销行为。
源码依照现有宿主 shader ABI 与公共参数表编译，不能任意声明新资源绑定或入口协议。
编译在工作线程进行，使用已有 Naga/效果包校验和预算，不阻塞输入；过期编译结果不能
覆盖较新草稿。解析、验证、管线创建与渲染失败分阶段显示，保留原始原因与来源行列。
自定义 WGSL 节点、代码反向生成节点图和断点调试器暂不纳入第一版。

## 5. 结构化布局契约

布局树支持行、列、分组、标签页及可调整分栏；控件采用宿主认可的类型集合。
首批参数控件为数值、向量、颜色、布尔、枚举；预览、时间轴、素材和对象列表为
明确的宿主槽位，逐项接入，有缺口的槽位在校验/编辑器中直接指出。

- 组件有稳定 ID；绑定目标另用公共参数 ID，不能绑定显示名称、列表下标或节点坐标。
- 可拖动排序、跨组移动，调整分栏比例、列宽与对齐。间距/密度选择引用宿主语义 token，
  不允许插件另设一套颜色、字体和交互状态系统。
- 分栏先满足控件最小命中要求；不足时滚动，不压小命中区域。折叠、页签与滚动位置
  属于视图状态，不修改参数。窄宽预览必须走同一布局计算。
- 属性控件遵循 `DESIGN.md` 单行契约：不因面板变窄把同一属性拆成额外行，
  枚举用下拉、布尔用复选框、非编辑数值背景透明，沿用实际拖动容差。
- 尺寸由布局约束与 token 解析；设计器的选择框、拖动提示、分隔条也使用语义 token。
- 对组件数量、树深度、文本和文档字节数设上限；拒绝循环引用、重复 ID、未知控件、
  非有限尺寸、错误参数引用及错误类型。错误指到组件与字段。

## 6. 参数连接、源工程与发布物

公共参数契约决定类型、范围、单位、动画标记、默认值与绑定 ID。
控件从契约生成，布局不重复定义一套可与逻辑冲突的参数类型/范围。
改名保留 ID；删除仍被控件或节点引用的参数时列出引用并要求显式处理。
类型变化若使绑定失效则阻止预览写入与打包，不能自动改成其他参数。

插件源工程保存版本号、元数据、带来源标签的逻辑文档（节点图或 WGSL）、
公共参数、布局文档和资源清单；记录当前版本，
不提前建设迁移系统。保存后重开必须保留图、绑定、尺寸与精确参数默认值。
未保存草稿在失败、关闭检查和断连后仍可恢复；保存失败不能清除脏标记。

发布 `.msfx` 包含编译产物、公共参数、原生布局和必要资源；作者画布选择框、
临时预览值、连接信息和撤销历史不进包。现有协议 1、锁定的包 hash 与渲染基线
不因增加新作者文档而重写；新布局运行契约单独版本化，打包时检查所需宿主能力。
不提供任意宿主命令字符串或插件动态注册原生代码的入口。

## 7. 历史、错误与资源边界

- 作者撤销覆盖节点、布局和公共参数改动；一次拖拽/连续调整合为一步。
  复用已有节点历史的事务边界，明确与布局变更如何组成同一作者操作，避免两栈顺序冲突。
- 真实实例的参数/颜色手势通过 scoped session；一次拖动一项工程撤销。
  作者工程撤销与宿主合成撤销明确分开，不能让 Ctrl+Z 同时写两份历史。
- 设计模式独占设计拖拽；交互模式控件、弹窗和时间轴按现有输入优先级处理。
  Esc/失焦只结束当前所有者的手势，不重放给下层节点或合成。
- 读取、保存、图编译、布局校验、打包和宿主连接均有请求/阶段/耗时与原始原因。
  使用现有 log 与错误信道：默认级别可诊断，Error 进文件和 stderr，stdout 留给协议。
- 阻塞命令进入处理前发布 start/in-flight；健康 Present 路径保持安静。
  过期请求、正常取消和未连接示例模式不是错误，不增加隐式重试或重启。
- 失败保留草稿与主要原因；验证 Err、panic、不可返回处理及退化返回值，
  不能仅凭绿色计数宣称所有失败路径已验收。

## 8. 粒子目标样例

默认结构为左侧发射器列表、中间真实合成预览、右侧选中发射器的分组参数，
底部复用同一时间轴。发射/运动/外观等分组由布局描述，字段通过稳定对象 ID 与字段 ID
绑定；切换发射器不会串写另一个对象。

多发射器先完成结构化子对象、可动画字段及 Add/Remove/Duplicate/Reorder/Set/Enable
受控命令，含容量/出生预算校验和一次手势一次撤销；再接列表与字段控件。
节点负责其已有能力可以表达的效果逻辑，宿主负责确定性粒子、资源、时钟与渲染底层能力；
不将所有模拟强行重写为着色器图，也不把固定内置效果当作第三方插件样例。

## 9. 施工顺序与验收

| 阶段 | 交付 | 必须看到的证据 |
| --- | --- | --- |
