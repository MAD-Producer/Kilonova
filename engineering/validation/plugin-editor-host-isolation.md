# 插件编辑器：宿主状态隔离验收修正

本轮接续 #566，基线为 `2b5d7629`。用户已明确确认：允许修正诊断计数的
测试范围，同时保留其他完整状态比较、检查计数单调性并补充负对照。

## 契约与修正

原生生命周期测试要证明作者窗口不修改宿主工程、帧、revision、历史或其他状态。
但 `Engine::call_with_timeout` 的同步等待计时与 worker 完成计时都调用诊断记录器；
该记录器使用既有 `try_lock` 契约，正常竞争也可能增加 `droppedRecords`。
因此“整个 State JSON 字节语义相等”包含了与隔离契约无关的并发观察量。

本次仅修改测试，生产逻辑、诊断阈值、计数、日志与线程策略均不变：

- 仅 `/desktop/diagnostics/droppedRecords` 按非负整数单调性比较。
  不接受字段缺失、错误类型或回退；比较相邻检查点，不能只与初值比较。
- 其余完整 JSON 仍严格相等，包括诊断配置、其他计数和未知新增字段。
  不仅挑选 `project` 或 revision；不修改被测 Engine 的返回值。
- 单元负对照逐项替换字段、删除字段及向对象加入字段；原生用例对真实完整
  State 的副本执行同样检查。负对照修改的是快照副本，不是向真实宿主派发编辑。
- 在判定前保存未经处理的完整 State；报告另行记录每段的计数。

此前的整快照失败仍保留在 `plugin-close-reviewed/native-host`，不覆盖或重新解释
为产品功能修复。当前记录取代先前文档中“HOST-STATE 待完善”的测试契约状态，
不抹去其当时失败的事实。
