# 不同标签的有界排版工作集

对应 #129，基线 `e2dd04ab032598f977555bdb934177baab0a55f4`。
开始前核对开放 PR、近期本地分支和工作树；本批避开其他 agent 的跟踪、抠像与
后台预渲染，只修改 UI 框架中的排版/截断缓存和独立验收。

## 功能与内存边界

原缓存同时受 128 条及 1 MiB 限制，即使字节预算充足，200 个不同属性标签也会
逐帧淘汰。现在保留原有 LRU 与两个各 1 MiB 的预算，由最小条目成本推导最大
条目数，不再因固定 128 条门槛提前淘汰。

字节权重补计键 Arc 头、表内键/值条目、LineLayout 对象及其 Arc 头；三个 Vec
继续按 capacity 计入。两个缓存即使共享布局也各自全量收费，不以共享引用数
推断其生命周期。LayoutCache 重复写同一键时扣除旧权重，避免累计虚假用量。

这是缓存保留数据的准入权重，不是分配器实测总内存：HashMap 空闲桶、分配器
元数据、外部调用者保留的 Arc、字体/图集/塑形器和冷排版暂存都不在 1 MiB
数字内。正的最小权重仍给条目数和表容量提供独立上界。工作集超预算、全新文字
和新增宽度可能正常淘汰和分配，不声称无限标签或整个应用零分配。

## 实际分配与正确性

新增三个分配测试分别测完整布局、截断布局、plain/styled 控件实际绘制路径。
工作负载为 200 个含组合符、中文及阿拉伯文的不同标签，以及 1,000 个不同短标签。
所有文本创建在测量外；只允许一次工作集预热，随后连续三轮，每轮遍历所有标签。
截断/完整宽度分别测试；只统计执行线程上通过 System 的真实 alloc/realloc 请求。
字体、PaintList 容量和缓存都使用产品路径，不替换成功 mock。

原 128 条实现下，200 个复杂标签的首轮完整布局 6,000 次分配、截断布局 10,400 次、
实际绘制 10,400 次，三个新增断言全部失败。初步修复后三项全部通过，两个工作集
及全部已测宽度均为零。最终源码的负对照、完整回归和 GPU 结果另行填写。

独立冷图集逐一复核排版字段：advance、字素边界、缺字数及每个 glyph 的 face/id/
cluster/source/position/advance。另以实际 GPU 比较预热工作集和独立冷参考，覆盖
五种 DPI、两种宽度、左右对齐和两个工作集；错误标签必须产生不同像素。
这不代表整窗截图、彩色 emoji、完整 IME 或全帧零分配验收。

## 测试开发中发现的边界

新增预算测试初次编译的 `sum()` 存在类型歧义，显式声明 `sum::<usize>()`；没有
更改产品行为或断言。随后两个新增 clear 测试错误地把有删除墓碑的 HashMap
`capacity()` 当作底层分配容量，与 clear 后无墓碑状态比较。保留失败原文，
只调整新夹具：预留同一张表，并在首次空表时记录容量，使 clear 后与相同的
无墓碑状态严格相等；原相等断言保留，并增加中途容量不超过初始值的检查。
既有测试断言、预算、超时及忽略项均未修改。
