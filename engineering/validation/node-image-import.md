## 已实现的底层能力

- `UvMapping` 明确接受归一化 UV、UV 平移、角度旋转、二维坐标缩放和 UV 轴心；缺坐标必须报错，不隐式连入 Position。顺序是先绕轴心缩放、再旋转、最后平移。
- 默认平移 0、旋转 0、缩放 1、轴心 0.5。旋转单位是度，Y 向下时正角度顺时针；变换的是采样坐标，较大缩放会缩小纹理，负缩放镜像，零缩放固定一个轴。
- 所有数值仍可由图端口连接，复用已有有限值、精确类型、单位与公开参数校验。数值编辑继续用既有 shader data 通道，不因改变映射数值重编 shader 源码。
- 模型、导出和编译器已支持此节点；尚未加入节点库或快捷键，当前没有新增可见控件。只在可达依赖包含映射时追加 WGSL helper。

## 后续必须完成

1. 图像引用的独立可携带表示、大小和解码预算、资源去重及精确 Image 端口；禁止只保存外部绝对路径或在 UI 线程解码。
2. 文件拖入主窗/原生浮窗后按真实画布位置创建节点；固定工程/图层绑定和图文档版本，取消、过期与失败不能留下半个节点或孤立文件。
3. 编译资源打包和图层绑定：沿用 SDK 已有四个 PNG 资源绑定，明确与 resource0 的数值溢出纹理共用的容量；静态导出、运行时数据和独立预览必须使用相同图像。
4. 当前独立预览只上传数值资源纹理，其余资源槽绑定宿主占位图，必须在支持文件图像时补齐真实上传和内容变化后的缓存失效。不能仅完成编译器而宣称预览可用。
5. 支持目标与已有输入替换规则明确的 Ctrl+T，一次事务创建 UV／映射／图像采样链；无目标、预算不足和非法端口明确反馈，不产生无用链。
6. 覆盖保存重开、脱离源文件的离线工程、导出包 GPU 像素、撤销/重做、失败与默认错误信道；最后提供中英文主窗/浮窗截图。完成全部验收后再与 #227 / #228 一起提交 PR。
