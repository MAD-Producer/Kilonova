## 已实现的底层能力

- `UvMapping` 明确接受归一化 UV、UV 平移、角度旋转、二维坐标缩放和 UV 轴心；缺坐标必须报错，不隐式连入 Position。顺序是先绕轴心缩放、再旋转、最后平移。
- 默认平移 0、旋转 0、缩放 1、轴心 0.5。旋转单位是度，Y 向下时正角度顺时针；变换的是采样坐标，较大缩放会缩小纹理，负缩放镜像，零缩放固定一个轴。
- 所有数值仍可由图端口连接，复用已有有限值、精确类型、单位与公开参数校验。数值编辑继续用既有 shader data 通道，不因改变映射数值重编 shader 源码。
- 模型、导出和编译器已支持此节点；尚未加入节点库或快捷键，当前没有新增可见控件。只在可达依赖包含映射时追加 WGSL helper。

## 图像资源与预览阶段（底层验证通过，非 issue 完成）

`GraphImage` 仅保存自身拥有的、经过完整解码验证的 PNG 和 SHA-256 身份，克隆与图历史共享不可变字节，不保留外部绝对路径。调试格式只显示尺寸、哈希和字节数，不输出 PNG 内容。导入先限制文件读取和解码预算，再编码自有 PNG；PNG 原生解码错误保留为原因链。

`.msgraph` v3 增加内容索引和 `ImageAsset` 节点，Image 端口仍是不可参与数值计算的图像句柄。没有图像的既有图不升级版本，也不改变生成的 shader 或清单。源文件最大 24 MiB，其中 metadata 仍独立限制为 4 MiB，图像压缩数据累计 15 MiB、解码尺寸累计 128 MiB、最多 32 个内容身份；按已打开文件句柄限量读取，元数据增长不能借用图片额度。编辑器的 metadata 预算检查不进行 base64 编码。

可达图像去重后与数值溢出纹理共用既有四个资源槽，超出时明确拒绝。输出包包含 PNG，导出的源图包含图像内容，脱离原文件仍能重开。采样在图像自身尺寸下计算像素坐标，先把四个 texel 转换为图工作空间和预乘透明度，再双线性过滤；图像范围外透明。静态编译、可编辑数据编译、Image 端口预览与真实宿主 GPU 使用同一资源顺序。

独立预览现上传全部声明资源，保留 RGBA8 原始存储，使用已有 GPU 准入和所有权设施；代码缓存不持有图片纹理。分组的根快照和离开分组保留图像池与源版本。剪贴板只带所选子图的图像闭包，粘贴按内容去重；切除或删除最后一次引用释放当前图像池，撤销恢复原内容，其他作用域仍引用的图像保留。

没有新增第三方素材。新增 motion-graph 的 base64 0.23.1 和 sha2 0.10.9 直接依赖均为仓库已经锁定、记录来源的未修改依赖，仅扩展 ATTRIBUTION 中 base64 的使用范围。本阶段没有修改工程 JSON、效果包格式、既有渲染 kernel 或任何像素基线。

最终同一批源码验证：`cargo test -p motion-graph --locked --offline` **95 passed、0 failed、0 ignored**；`cargo test -p motion-desktop --features ffmpeg --locked --offline node_` **229 passed、0 failed、0 ignored**（主测试程序 228 项、集成测试 1 项）。合计 324 项，不重复累计早期和单项运行。包括新增 7 项图像核心、3 项效果包 GPU、4 项剪贴板、3 项独立预览和 1 项真实文件 worker 测试。现有图节点、原生窗口剪贴板、图层绑定、数据纹理、准入拒绝、四精度及默认错误信道回归均保留原断言。

真实文件 worker 在隔离子进程、不设置 MOTION_LOG 的条件下打开损坏 PNG 和非法 base64 源图。验证 Info start 在失败之前，Error 在文件和 stderr 各出现一次，记录请求 ID、Open、epoch/revision、耗时、源文件与图片哈希；完整 PNG/base64 字符串不进入日志，stdout 不混入错误或 Info。两次失败保留原图、历史版本和源路径，随后显式打开有效源成功，不自动重试。源读取另行验证原生 PNG/base64 原因链可向下检查。新编解码失败不再通过 serde 的通用 custom 字符串丢失原始原因。

没有新日志 sink、线程、Present 记录、阈值计数、超时或重启。沿用既有 Open worker 的 start 和 pending/完成路径；本轮并未通过受控阻塞验证新导入 handler 的 in-flight 发布，也没有对未来导入事务的 panic 或取消作完成声明。GPU 预览的资源解码目前仍在既有引擎 worker，后续接入导入时需完善 NodeInstall 前的 CPU 准备。

结果、源码与测试程序哈希见 [阶段结果](node-image-import-images-results.json)，早期失败、最终输出和实际默认日志/stderr/stdout 见 [阶段证据](data/node-image-import-images-evidence.zip)。来源守卫、样式消费守卫和 diff 检查通过。测试所生成的 PNG 均为本项目的数值像素夹具，没有引入第三方图像。上述本机 Windows/MSVC 证据不等同于跨平台 CI 或新导入流程的原生输入与视觉验收。

### 失败记录和证据边界

- 首轮新增核心测试错误地直接向下转换 boxed 原因链，4 项成功、1 项失败；按现有 native_effect_causes 的 Box 类型修正新增夹具，保留原有“原生原因必须可检查”断言。
- 首轮桌面编译发现新测试访问私有测试 helper 并假定 CompiledGraph 可克隆。仅扩大测试 helper 到父模块的可见性，并重新编译真实候选；没有改生产 API 以迎合夹具。
- 首次桌面运行 10 项通过、1 项失败：缺资源的新增夹具同时留下了旧 execution template，因此更早被清单校验拒绝。夹具现按新资源表重建 template，并先断言清单有效，保留缺资源错误和旧画面不变断言。原始失败日志保留，不调整生产校验或绕过清单。
- 既有“拒绝未来源版本”的夹具从字面量 3 改为 `IMAGE_ASSETS_FORMAT_VERSION + 1`：3 已成为本轮定义的有效版本，仍用原来的拒绝断言验证真正未来版本，不删除断言或放宽版本检查。
- 这些是底层真实 codec、包导出和 GPU 的证据，不是系统文件拖入、Ctrl+T、工程轻量引用、导入 worker 默认错误输出及中英文原生窗口的完成证据。两项 issue 保持打开，尚未为本分支提交完成 PR。

### 后续持久化约束

工程绑定必须保存轻量引用，不能把便携源的 base64 PNG 或整个 runtime hex 继续塞进每次复制的项目快照。独立 `.msgraph` 保留自身完整内容；工程内图片与编译运行时应是由工程拥有的不可变文件，并被工程保存、离线打包、图层剪贴板和动画预设的依赖收集一起追踪。资源暂存后须在编辑失败、取消或过期时清理本次拥有的文件；已有共享文件及撤销仍使用的资源不得误删。这部分尚未实现，也没有使用放宽工程 4 MiB metadata 限制的方法绕过它。
