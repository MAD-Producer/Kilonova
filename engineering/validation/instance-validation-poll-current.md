## 问题与功能改动

`prepare_instance_data` 在当前数值纹理变化时创建绑定；此前每次在 Validation scope
之后执行 `wait_indefinitely()`。它会等待最近的队列提交，因而不只影响冷编译。
当前固定 wgpu/wgpu-types 30.0.1，仅使用 Vulkan/DX12/Metal 原生后端：原生
`pop_error_scope` 返回已就绪的 scope error，读取该结果不要求已提交画面执行完成。

现在只执行一次 `Poll`，仍检查原生绑定校验结果及设备轮询错误。绑定失败保持主因，
轮询同时失败作为附加原因；只有轮询失败时仍返回错误。相应诊断阶段由 wait 改成
poll，program/pass 和原始 wgpu 原因保留。成功之后才追踪上传、提交数值及替换缓存，
既有事务次序不变。没有清空错误、吞 panic、添加重试、超时或 worker 重启。

将原有创建/校验块提取为私有函数，生产调用直接将请求转交 `device.poll`。
测试闭包检查该函数实际选择的 PollType 后仍调用真实 device，而不是模拟成功返回。
该函数不对外导出，不增加产品设置、面板或热路径日志。

依据：[固定原生后端源码](https://github.com/gfx-rs/wgpu/blob/v30.0.1/wgpu/src/backend/wgpu_core.rs)
及 [PollType 语义](https://docs.rs/wgpu-types/30.0.0/wgpu_types/enum.PollType.html)。
本地锁文件版本、checksum 与实际依赖源码 SHA-256 随证据记录。
这里不声称原生对象创建已经异步化，也不声称已解决十秒 GPU 操作期间的全部 UI 响应。

## 新增实际用例

四条用例使用真实 GPU 和完整八槽资源绑定：

1. 合法绑定必须发出非等待请求，再转交真实设备；scope 成功且 owner 健康。
2. 故意缺少一个 sampler，捕获真实 `Device::create_bind_group` 原因；program/pass/
   bind 阶段保留，同一设备随后接受合法绑定且保持健康。
3. 真实非法绑定加上显式合成的第二个 PollError，验证主因与附加原因都保留。
4. 真实合法绑定加上显式合成的 PollError，验证轮询失败不会被当成成功丢弃。

后两项的 PollError::Timeout 是测试注入，不冒充同时发生的真实硬件故障。所有错误
用例还严格检查 RenderError::Invalid 类型、完整 `GPU validation:` 显示包装和内部
原因，既检查结构也检查外部诊断文本。

## 失败与负对照

第一次保留原 Wait 的红灯运行，四项均被非等待策略断言拒绝。改成 Poll 后健康绑定
通过，另外三项暴露新夹具误把内部原因等同于完整 Display 字符串。仅改新夹具的
取值边界：分别验证既有错误变体、完整显示包装和原来的内部原因断言，并增加
原始输出；没有改产品错误类型/包装或放松既有断言。原始两轮失败完整保留。

最终四项通过后，不修改最终测试源码，临时恢复 Wait 再执行：四项均在实际 PollType
断言失败；随后按原始字节恢复 Poll 源码并校验 SHA-256。该负对照不依赖机器时间阈值，
也不能被“本次队列刚好空闲，所以 Wait 很快返回”误判为通过。

`gpu_failure_observation`、`wgpu_upgrade` 三个集成目标：分别 311、2、1、2 项通过，

真实帧导入用例继续覆盖四种精度的资源拒绝、恢复与输出，不用健康 mock 替代。

带 FFmpeg 的桌面程序另执行既有两项默认日志信道父测试，均通过；其余桌面测试
被名称过滤，未声称执行完整桌面/FFmpeg 套件。父测试启动 portable/native 的冷、热
四个真实子进程场景；MOTION_LOG 未设置，每个场景的故障记录在文件/Error stderr/
stdout 中分别为 1/1/0，并验证 Session 解锁后记录、重复故障抑制与恢复像素。
