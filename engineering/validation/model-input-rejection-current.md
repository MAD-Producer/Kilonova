# 模型输入拒绝与事务不变性

关联 #138。本批补充公开输入边界的执行证据，没有改变工程格式、生产校验规则、错误返回值或既有断言。不是对全部可能输入的穷举证明，也不单独关闭整个 issue。

## 验证范围

- 当前工程的 16 个必填字段分别缺失或为 null，五项错误类型/帧率/动画维数输入，以及跨 UTF-8 和嵌套动画的截断字节输入：返回 serde 原生错误，完整合法工程仍可重开并构造 Engine。
- 21 项能够正常反序列化但语义非法的输入：工程版本、尺寸、帧率、时长、工作区间、名称、图层身份/尺寸、不透明度及重复/乱序关键帧。直接校验和 Engine 构造都保留模型错误类别与原因；校验前后序列化字节相同。另验证重复图层和缺失图片资源的拒绝。
- 三种非有限数值、三种坐标分量、静态/关键帧两种存储，共 18 项直接内存输入。它们不经过会将非有限值表示为 null 的 JSON 路径；原生校验和 Engine 构造都返回错误。
- 六种失败批次后缀：不存在的对象、非有限位置/缩放/不透明度、重复图层、倒置工作区间。每批先执行真实有效改名，再验证失败后整个工程、revision、完整历史诊断和撤销/重做可用性精确不变。最后实际遍历两条历史分支确认内容，没有删除动态字段或规范化快照。

## 原始执行与负对照

在独立工作树临时将 `Project::validate` 旁路为 `Ok(())` 后，保持测试断言不变，实际运行语义输入检查：退出码 101、零通过、一失败，失败原因为原生错误检查收到 `Ok(())`，不是编译失败。`finally` 恢复生产文件，恢复后 SHA-256 与原文件相同。原始命令、stdout/stderr、两种源码和恢复收据均保留。

完整 `cargo test --locked -p motion-model -p motion-core -- --test-threads=1 --nocapture` 已结束：142 个目标，894 通过、零失败、零过滤；1 项既有 `history_accounting_large_document_measurement` 手动性能测量忽略，未更改忽略配置。耗时 782.016 秒，整个 crates 冻结清单的执行前后 SHA-256 一致。上述四项专项包含在完整结果中，不重复累计。跨平台 CI 和整合后的原生桌面信道验证尚未完成。

## 边界

这是独立测试补齐，不是新增生产故障观察。畸形请求的正常拒绝仍走既有原生 `Err`；本批没有新增计数、重试、超时或日志等级。默认级文件/错误 stderr/stdout 隔离的真实桌面信道证据由同一 #138 的 #619 验证，不能由本批 core 测试替代。

没有新增依赖、资产或面板样式。DESIGN §0.7 的视觉整改项全部保留，原因是没有编辑面板代码或外观；不声称截图、物理输入、任意深度递归、全部插件模型或任意命令的完整验收。

原始命令、退出码、stdout/stderr、冻结清单、旁路负对照与恢复源码见 [证据归档](model-input-rejection-evidence.zip)；归档逐成员 SHA-256 已读回核验。
