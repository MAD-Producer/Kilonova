# 原生 OCIO 目录声明核验

## 功能范围

#83 此前会验证配置原文件的字节身份和工程所选名称，但工程清单中的空间、
角色、显示及视图声明仍可能与这些原文件实际声明不一致。本批在原生程序返回
宿主前核对完整目录，包含当前变换未引用的条目。失败不发布 CPU/GPU 程序，
Rust 所有权守卫释放已准备的原生句柄，不重试、不选择默认配置。

固定 OCIO 2.6.0 的实际配置 API 提供规范空间名、encoding、场景/显示参考域、
Data 标志、解析后的角色目标和活动显示/视图。空间枚举显式包含非活动空间；
活动显示和视图来自配置文件，已有环境覆盖拒绝边界保持。原生桥接快照在
配置封闭检查、原生 validate 后建立，不执行外部文件回退。

原生与清单双向核对空间、角色和显示集合，逐项比较空间声明、角色解析目标和
每个显示的视图集合。视图排列顺序可以不同，不改变声明语义。清单自身的字节
身份仍包括排列顺序，因此重排后的选择必须显式使用新的 config_key。

桥接目录最多 512 个空间、128 个角色、32 个显示、每显示 64 个视图，合计
2,720 行；每个名称/值最多 256 UTF-8 字节。错误携带字段、条目名、预期及
实际值，各项有界。查询只借用原生 Program 持有的不可变字符串；Rust 在句柄
存活期间读取。无效索引和空句柄经既有异常边界返回 Admission，输出行及计数
清零，不返回部分数据。新查询符号在初始化全局回调前解析。

这是**声明一致性**检查，不是 primaries、白点、传递函数数学或 ACES 版本的
独立证明。Builtin 来源/ACES 声明仍需后续验证。普通 managed Session、视频、
矢量、效果、蒙版及其余 #83 范围没有由本批自动启用。没有 UI 改动。

## 验证与证据

证据目录为 `artifacts/issue-goal-current/color-native-catalogue/`。本机采用
Windows x86_64；复用已验证且哈希不变的 OCIO 核心，重新编译当前生产桥接、
独立 C++ 边界程序及资格测试专用初始化故障库，再发布并核验运行时清单。
这不是一次重新下载和完整重建第三方核心的证据。

- 真实 C++ 配置行可读；无效索引、空句柄均拒绝，错误不发布部分输出；原先
  六类初始化故障、空回调及恢复控制保留。
- 12 项结构合法的清单变异保留同一原始配置字节，并更新选择身份以越过身份
  前置条件：未选中空间的 encoding/参考域/Data 标志、未选中角色目标、增加/
  移除角色、增加/移除空间、增加/移除显示、增加/移除视图。全部必须返回具体
  `Catalogue` 字段错误。每次拒绝后重新准备正确配置并实际执行 CPU 像素转换，
  结果精确等于同一原生配置的先前输出；合法视图重排亦保持该输出。
- 原有 20 个程序、240 个外部 CPU 参考样本继续比较；身份、结构、整数、
  运算符精确比较与九项严格变异负对照不变，原数值参考和容差不改。
- 使用当前新桥接实际生成这 20 个程序，在本机 Vulkan 上绘制并读取 240 个
  像素，均符合原 CPU 参考；已有错误着色器/查表的实际 GPU 负对照继续通过。
- 新桌面子进程在默认 Info 级别经实际宿主准备路径触发未选中空间 encoding
  错误；检查原 typed cause、工程完整不变、在途状态清除以及后续正确配置恢复。
  文件必须先有 Info start，再有包含 request/target/字段/预期/实际/耗时的
  Error；相同 Error 进入 stderr，Info 不进入 stderr，诊断不进入 stdout。
  四项捕获日志负对照分别破坏级别、stderr、字段和 stdout 隔离。

首轮新默认信道测试先遇到夹具资源路径错误：完整清单身份改变后，资源目录也
改变，夹具却只在原目录写入配置。首轮日志和失败输出原样留存；新夹具现在把
相同配置字节写到重新计算后的明确路径，从而实际到达原生目录核验。没有改变
既有断言、资源解析规则或生产错误行为。

最终原生集成七项通过，默认桌面信道八项通过；日志捕获确认目录失败只有一条
Error，携带 request=8921、DefaultInput、encoding、条目名、预期/实际及耗时，
同一条进入文件和 stderr。恢复请求 8922 没有 Error。工具测试 144 项中 143
通过、一项原有可选跳过；70 项工具库存和 6,379 个跟踪路径来源门禁通过。
格式检查及工作流八条原生资格命令的 YAML 解析核验通过。
当前桥接下的宿主集成 15 项通过，包含真实创作颜色/静态图片 GPU 合成、16 位
原文件输入、默认输入与创作输入分离、明确拒绝边界，以及受控阻塞/原 panic
展开的在途状态验证。测试中的原始 provider panic 由既有 unwind 对照故意触发
并保留，不是被吞掉或作为成功返回处理。

远端按各平台重新准备原生程序并做真实 GPU 像素比较的门禁保留，新增默认信道
测试进入同一原生资格步骤。跨平台结果需与实际提交和 run 对应，不能以本机
测试或此前提交的绿色状态代替。

## 错误处理审计

| ID | 类别 | 处置及限制 |
| --- | --- | --- |
| NCC-01 | 功能修复 | 原生目录与清单不一致返回 typed Catalogue；原生已分配程序由 RAII 释放，无部分发布、默认值或重试 |
| NCC-02 | 复用已有观察 | 宿主仍在进入原生处理前发布在途状态及 Info start，原错误沿 Provider 因果链进入默认 Error 双信道；既有受控阻塞及展开退出测试不改 |
| NCC-03 | 新失败证据 | 实际未选中 encoding 失配经默认桌面 logger；完整工程不变、清除状态、健康恢复及四项捕获日志负对照 |
| NCC-04 | 原生边界 | 实际配置、无效索引、空句柄通过 checked；输出失败清零；桥接源码身份、固定库及许可证核验继续生效 |
| NCC-05 | 正常分支 | 视图重排正常；不为每行、每帧或健康查询新增日志和文件访问；准备之外不增加热路径工作 |
| NCC-06 | 明确边界 | 直接 effects 调用返回类型供调用者处理，不另装 logger；原生元数据核验不证明空间数学/ACES 来源，也不完成普通 Session 接入 |
| NCC-07 | 待验证 | 当前改动尚需远端原生矩阵资格验证；原有原生访问冲突没有根因结论，本批通过不视为修复 |

不增加依赖、第三方资产或兼容层，固定 OCIO 的原有来源和许可记录保持。
`catalogue-evidence.zip`、输入清单和独立归档收据保存实际桥接字节、当前源代码、
首轮失败与最终输出、运行时哈希及原四份数值参考的身份；核心库和上游构建
暂存不重复打包，以已核验的来源清单与原生构建收据标识。
