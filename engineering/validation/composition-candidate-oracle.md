# 合成候选图的独立展开对照

关联 #132 的候选图假设与 #135 的模型覆盖。基于 main `7a61233a`，开始前核对 #400 的资源预算和 #402 的依赖审计范围；本分支只新增模型测试和本记录，不与它们的生产实现重叠。

## CG-01：不把未复现假设当成已经修复的缺陷

原 issue 认为：把候选边算入 memo 会使共享祖先重复计数。实际契约按引用实例展开，重复来源应按每次引用计数，不按唯一来源去重。一次检查中候选边固定，memo 只属于这一张候选图；节点高度和展开实例数因此仍是节点的固定摘要。祖先复用子节点摘要正是在计算各条引用路径的实例数。

路径上下文有一项不能省略：命中 memo 后仍须检查“当前前缀深度 + 缓存子树高度”不超过 16。现有实现保留该检查，也在命中缓存前检查路径环。此次不移除正确的 memo、改变预算或添加替代性默认值；没有新增产品修复或日志观察。有限测试不是所有可能文档的形式证明，但能独立验证列明范围及原假设所指的共享／重复引用结构。

## CG-02：独立对照与正常分支

新增测试先在单独的邻接表中实加候选边，再对每个根逐次展开，不使用缓存、Project 校验器或生产的假想边分支来计算预期。独立规则拒绝环、17 层路径和超过 1024 的展开实例；无引用及空节点是正常分支。

- 枚举四个有标号节点的全部 4096 张无自环有向图，保留其中 543 张 DAG；对每个活动合成、正反库顺序、每对 source/target 比较完整候选列表，共 69,504 次判断。
- 16 层链和共享深子树分别包含 17／18 个节点，轮换每个活动合成和正反库顺序，共 21,490 次判断。验证缓存子树不能绕过当前路径的剩余深度。
- 重复引用图的根展开为 1023；根添一叶达到 1024 必须允许，共享底部添一叶产生 512 次实例增加必须拒绝。11 个活动视图、两种库顺序共 2,662 次判断。

三项专项通过，0 失败、0 忽略，3.43 秒。合计 93,656 次候选判断，同时检查返回列表顺序和查询前后工程 JSON 不变。没有依据这些测试宣称保存断电、GPU、默认日志或 UI 验收已经完成。
