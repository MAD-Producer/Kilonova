# 图像准备允许集合复用验收

分支 `perf/image-allowed-sets`，推进 #126 的场景资产集合分配子项；合集
其他 GPU 对象、缓存和性能验收保持开放。初始基线为 `27315a57`，随后
同步主线 `e6576504b7b68a31ce863a5ede011bc264170232` 并重新验证组合。

## 改动与保持的契约

`Renderer::prepare_scene_assets` 原来每次都构造预取候选集合及允许集合，
即使预取未启用、没有候选，或候选全部已是当前需求。现在未增加源 ID
时使用 `Cow::Borrowed` 借用本次需求集合；确有额外候选时才复制并扩展。
需求收集和活动集合副本仍保留，不宣称整段准备流程零分配。

启用条件仍为预览缓存开启、异步准备且没有缺失需求；先过滤当前需求，
再截取原 `MAX_PREFETCH_IMAGES` 数量，最后去重。重复候选仍消耗原有
预取槽位，不越过重复 ID 去寻找更多候选。允许集合始终与原规则相同，
保持排序；新增 ID 数不超过既有上限。目前该上限为两个资源 ID，不是
像素尺寸。所有集合只在本次准备内使用，没有新增跨帧缓存或资源引用。

解码取消仅同步检查允许集合，不保存借用；处理完已完成解码后结束该
集合的生命周期，再继续原需求准备。源码对照确认只改变允许集合构造
与该生命周期，原解码、上传、预算、错误及观察点代码保持原文。

## 查重与实际验证

实施前核对 390 个分支引用、59 份不同相关源码、113 个工作树及开放 PR。
三处相关文件的未提交工作分别为 pipeline 等待计数、wgpu API 适配、
viewport 适配，均不修改允许集合构造；没有编辑这些工作树。同步后的
主线仍保留原集合逻辑，未重复实现已经合入的功能。

新增实际 GPU 回归创建 64 张原创纯色 PNG、64 个图层、真实 Scene 和
Renderer，完成解码/上传并预热后测量 20 次准备。原实现在 Full 同步
模式记录 600 次成功分配/重分配请求，实际触发新回归失败；单次需求
收集及活动集复制的独立参考值为 20 次，二十次共 400 次。

修改后 Full 同步与 Preview(32) 异步两种已就绪场景均为 400 次请求。
Full 样本减少 200 次，即三分之一；未把未经旧版测量的预览计数描述为
同样的前后差值。需求和活动集的 400 次仍存在。计数器只观察当前测试
线程，不把请求次数等同于峰值内存、VRAM、发行耗时或 FPS。

同一 GPU 回归还验证连续准备前后，完整 readback 字节、解码次数、
上传字节和纹理总量相同，64 个资源尺寸保持，空闲纹理字节为零。这是
同一回归内的状态/像素比较，不冒充原、新二进制的全面像素基线。

三个新增纯集合测试覆盖空/相同/禁用候选时借用原集合的引用身份、
截断先于去重、需求不变，以及 512 组输入 × 两种启用状态的 1024 个
场景与原候选/union 规则的完整有序集合对照。没有弱化上限或断言。

初始及同步新主线后，均运行 19 项不同测试，0 失败、0 忽略：三个新
集合测试、一个新真实 GPU 分配测试，以及 15 个既有图像预取、工作集、
解码预算、原生错误身份、资源拒绝与准备回归。重复阶段不累计。当前
测试默认启用 GPU，缺少设备会失败，没有以忽略或伪造成功代替执行。

最初新夹具把文件放在包根目录，触发既有 assets 路径校验；只修正夹具
目录后才取得上述分配负面对照。该原件为 `test-fixture-path-failure.log`，
不把路径错误算成本次产品缺陷，也未绕过目录校验。

消费者检查覆盖 motion-host、motion-desktop-media 和 motion-desktop；
三个消费者检查全部通过，保留 20 项既有桌面警告，没有新增警告。结果
记录在 `consumer-check.log` 和 `final-verification.json`。来源、格式及
差异检查通过。五项必需 PR CI 及最终合入组合仍需各自结果。

## 错误、边界与来源

| 审计项 | 分类、证据与限制 |
|---|---|
| IA-SETS | 新优化：未扩展权限时借用，实际 Full 样本 600→400；活动集合原复制保留。 |
| IA-POLICY | 功能保持：原启用条件、过滤/截断/去重顺序、排序与上限有对照。 |
| IA-STATE | 实际 GPU：连续准备的像素、解码/上传计数及纹理记账保持；不宣称全部资源峰值不变。 |
| IA-FAULT | 既有真实故障：预取源失败转为当前需求后才传播、解码预算拒绝、原生原因与资源拒绝回归通过。 |
| IA-NORMAL | 正常取消、轮询未完成、空候选和缺失需求的原行为保留，没有新增 Warn/Error。 |
| IA-OBSERVE | 没有新增观察、worker、锁、重试、超时或 respond 变化；原失败原因/退化通路逐字保留。原生错误测试不冒充默认文件日志、全部阈值或受控阻塞验收。 |
| IA-PENDING | 精确提交 CI、最终合入组合、发行帧率、完整性能合集与其他调度/缓存范围仍待验证。 |
