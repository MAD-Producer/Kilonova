# Windows 原生验收失败证据

## 问题与边界

#365 的相同提交 `ed25e65c` 在两个 Windows 作业出现不同失败：`39354305267/118405459906` 的 PNG 验收等待 Present 回复 10 秒后超时；`39354311795/118405479593` 的采样播放验收在相邻完成帧号递增断言失败。两次对齐功能测试均通过，但不能因此把这两个失败称为环境噪声或认定整个 PR 已通过。

既有采样测试使用 100 秒工程，生产 `playback_frame` 按工程时长循环。原失败输出没有帧号，正常循环是待验证原因，尚不能据此认定远程失败原因。PNG 失败原输出没有 GPU、执行中命令或队列状态。这一批只补测试失败证据，不改产品功能、断言谓词、时间预算、GPU 后端、重试或跳过策略，也不声称修复两个根因。

开始前复核开放 PR 和本地工作树。#364 修改 macOS Intel 作业预算，本次只在桌面单测步骤增加两个证据目录环境变量，保留该作业的原始时间预算；集成时仍需复核同一工作流。#357 / #362 的设置及快捷键实现不修改本批两个测试文件。新分支基于主干 `b31b828f`；没有第三方依赖、资产或兼容名称。

## 证据路径

- 采样验收在原断言前写当前模式的 60 条完成记录、实际播放时钟时长、工程帧数和帧率；断言保留原谓词，并输出失败相邻记录及模式。父进程在检查子进程退出状态前保留已有结果和 stderr；失败子进程尚未生成的后续模式不是文件丢失故障。成功子进程仍须提供全部既有及新增验收文件，任何缺失都使验收失败。证据复制失败同时保留子进程原始错误。
- PNG 验收子进程接入现有默认 Info 日志器。父进程失败时输出末尾最多 32 行；Present 回复超时仍在原 10 秒截止点失败，同时输出无需请求工作线程的 in-flight、队列深度和 GPU 信息，并保存现有有界诊断快照。保存诊断失败附在原始超时之后，不替换主失败。
- 工作流将这些文件写入既有 `artifacts/desktop/**` 的 `always()` 上传目录。即使单测失败、后续打包未执行，也可取得证据。没有新增上传服务或完整用户负载日志。

## 验证与限制

验证目录为 `artifacts/native-ci-diagnostics/`：

- 正常路径初验：PNG 原生验收 1 通过（12.29 秒）；四模式采样验收 1 通过（27.70 秒）。
- 真实循环受控对照：仅临时调整测试中的生产播放时钟，让它跨过原有 100 秒边界。原递增谓词以退出码 101 拒绝约 `2970.427689 → 30.351096` 的相邻帧；父进程在失败后保留 `baseline-costs.json` 的全部 60 条记录、默认文件日志和 stderr。该结果证明正常循环可触发原断言，不证明远程当次一定为此原因。
- PNG 初次阻塞探针未触发超时：现有 TestWait 闸门 5 秒后自行返回，原 10 秒 Present 等待成功，未将该运行称作超时验证。修正外部验证夹具，串联三个现有闸门，原 10 秒等待失败，子进程与父进程都保持失败退出。输出包含 `test_wait` 和仍排队的 Present；`zh-present-timeout.json` 保留有界 GPU/时间诊断，默认日志实际存在。
- 受控脚本在 `finally` 中恢复原始源码字节，不提交注入代码。恢复并整理缩进后重跑最终正常路径：PNG 1 通过（12.08 秒），四模式采样 1 通过（23.68 秒）；最终成功报告、模式记录、图片与日志均留存。没有放宽既有谓词或超时，没有把故障注入运行算作成功。
- provenance（1,524 个既有受跟踪路径）、样式消费者检查与 `git diff --check` 通过。本批只针对改动的 Windows 原生测试执行上述正常/失败对照，不称作完整桌面或跨平台回归。实际 GitHub 上传需随后 CI 验证；诊断文件写盘二次失败的原始错误保留通过代码路径复核，未声称执行该二次失败对照。
- 提交前后复核补回成功子进程的严格产物完整性检查；只有失败子进程允许缺少尚未生成的后续模式文件。最终该路径再运行采样原生测试 1 通过（24.08 秒），所要求的完整报告、四个模式报告、四张图和文件日志全部存在，记录在 `sampling-required-artifacts.log` 和同名目录。失败子进程路径保持前述已验证条件不变。

本批未改任何用户可见界面、布局或样式，DESIGN §0.7 的属性树、效果列表和时间轴基线均 retained with reason：不属于测试证据改动范围。没有新增生产观测点；复用现有日志、in-flight 和诊断报告，健康 Present 路径仍保持安静。远程两个失败的实际根因及完整跨平台复验继续待办。
