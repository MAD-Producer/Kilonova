# 子菜单并排展开与行对齐修正

实现源：`dbaea61cef7d00410634a44f7e2c99a2207c7b7b`，PR #540 / #276 的后续修正。以下结果取代原共享菜单验收中“窄窗口允许覆盖父菜单”的布局结论；原始结果与证据保留，不改写历史日志。

## 问题与修复

原布局把子卡片的外边缘对准父菜单行，导致子菜单首项多偏移一层 padding；窗口放不下两张完整卡片时，又把子菜单钳制到父卡片上。用户要求悬停后在旁边展开，不能叠盖父菜单动作。

- 根卡片在绘制前预留相邻级联空间，普通情况下向右展开；右侧不足而左侧可用时向左展开。两侧均不足时选择位移较小的位置，避免展开后父菜单突然换位。
- 用子卡片首行与触发行对齐，补偿 `context.menu.padding` / `menu.popup.padding`；靠底边时才因窗口约束上移。
- 窄浮窗把可用宽度分给两列，不覆盖父动作。横向宽度会压缩，纵向行高、整行命中、原有点击语义保持；先隐藏放不下的快捷键提示，再对长标题省略。可见行的绘制与点击使用同一矩形。
- 顶栏工作区分支同步采用相同几何规则。复用全部现有 token、图标与动作，没有新增依赖、资产、工程格式或 worker。

## CI 后续：自定义主题夹具

首次 CI run `40672404453` 的 Linux job `122762755690` 实际为 1238 项通过、1 项失败、1 项忽略。失败发生在 `optional_row_class_uses_required_framework_selection_in_custom_themes`：它删除可选 `row` 及所有派生类时，也删除了共享菜单现已必需的 `context_menu.row`，主题加载因 `missing framework style context_menu.row` 先行拒绝。不能以此前本地过滤组通过代替完整 CI。
