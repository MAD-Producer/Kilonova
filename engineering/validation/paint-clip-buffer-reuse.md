# 裁剪时复用图形与颜色缓冲区

关联 #129 的逐帧临时分配项；本次不关闭合集。
基线：`d07b8b13a493892ec75e35945d728c08e5527446`。
分支：`perf/paint-clip-buffer-reuse`。

## 问题与实现

`PaintList::clip_to` 原来取走整个图形和颜色向量，为保留的内容新建
两个向量；连续裁剪会重复分配和扩容。现在在原向量中按原有顺序压缩，
保留其存储空间，仍用原索引映射更新混合图形/文字的创建顺序。

只修改 `clip_to`。折线/描边裁剪边界、过程图形、三角形和四边形的几何
计算，以及字形裁剪、UV 修正和顺序映射算法保持原有语义。公开缓冲区
长度不相等时，仍按旧 `zip` 行为截断到较短一侧；非法顺序索引仍丢弃。
没有新增错误处理、重试、线程、日志、样式、交互、工程状态或协议变化。

复用的是当前 PaintList 已有的容量，没有引入全局缓存。`clear` 后容量
继续由该对象保有，到对象释放时回收；不声称容量会随裁剪结果立即缩小。
两个索引映射仍可能分配，三角形裁剪结果及部分越界四边形的转换仍分配。
这不是零分配或帧率提升的承诺。

## 可复现证据

三个永久测试位于 `desktop/ui/tests/paint_clip_buffers.rs`：

- 实际调用裁剪接口，对 256 个内部矩形连续裁剪 20 次，测量成功分配和
  扩容请求，并确认图形/颜色向量的地址和容量、颜色与顺序不变。使用
  独立测试进程中的线程局部计数器和一次实际分配作为探针；统计期间
  不构造输入、不输出日志。测试要求最多保留每次裁剪一次索引映射分配。
- 混合裁剪覆盖剔除的四边形、过程图形、折线、三角形、描边及字形，
  验证颜色对应关系、精确 UV/位置/尺寸、图集尺寸和创建顺序。
- 公开图形/颜色缓冲区长度不等及非法顺序索引，保留既有截断行为。

原实现实际运行结果是 2 项通过、1 项失败：20 次裁剪产生 300 次分配
请求，性能断言失败。修改后 3 项全部通过、0 失败、0 忽略，同一样本
只有 20 次分配请求，减少 280 次；两个存储地址和容量均保持不变。
这是 20 次调用的请求数量，不是单帧次数、请求字节或峰值内存。
原始记录为 `before-tests.log` 和 `after-tests.log`。

另有一次性原始/最终实现对照，使用固定种子的 256 组混合几何输入，
覆盖全部 Shape 变体、字形、嵌套裁剪、空/倒置/非有限边界、三角形尾项、
缓冲区长度不等和非法顺序索引。每组连续裁剪两次，完整调试格式的
图形、颜色、字形和顺序记录共 1,535,421 字节，前后逐字节一致，SHA-256：
`f29a0c7d9cd4d5efa03880ae9a5a08e5e7a96723a2c0b2030646251c08bf1a3b`。
这是 CPU 绘制命令对照，不是 GPU 像素截图；NaN 调试文本不证明载荷位一致。
探针保留在本地证据目录，临时绝对路径测试入口已移除。

移除临时入口后，完整无 GPU 特性的 UI 测试 134 项通过、0 失败，25 项
既有 GPU 测试按特性配置忽略，未把忽略计作通过；其中包含 3 项新增
测试和 1 项既有的预期编译失败文档测试。后者输出的 E0597 正是其契约。
桌面产品 `cargo check` 通过，有 20 项既有桌面警告；不修改断言消除警告。
记录为 `ui-tests.log`、`desktop-check.log` 和 `checks-receipt.json`。
随后启用 GPU 特性运行 `analytic`、`path_antialiasing`、`retained_text`，
12 项通过、0 失败、0 忽略，其中 10 项是真实 GPU 像素回归，另外 2 项
是前述 CPU 测试的重复执行，不重复计数。GPU 适配器缺失会使这些测试
失败，不存在成功跳过路径。两阶段共 144 项不同测试通过，前述 25 项
中其余 15 项 GPU 测试未在本地执行。记录为 `gpu-tests.log`。
最终提交的五项 CI 和合并仍待核验。
来源检查、面板样式检查、差异检查与新增测试文件格式检查已通过。
源码核验确认 `clip_to` 之外的产品代码不变。
