# 蒙版准备阶段成员集合复用

Refs #126。基线 `6bdb692a7f6878dc8c78742a80561ee28937d145`。即使蒙版网格和输入绑定已命中缓存，`MaskGpu::prepare` 仍每次从头分配图层与网格成员集合。本批复用这两个 CPU 表，完成成员查询后立即清空；每张表最多保留 capacity 4096，超限丢弃，空蒙版和显式 clear 释放存储。GPU 纹理、网格、删除顺序与既有预算逻辑保持。

新增的常驻内容是有界空 CPU 表容量，存在以存储换分配的取舍；不保留旧成员 ID。网格/输入绑定缓存是既有能力，本轮只回归验证，不认领为新增修复。

## 实际对照

在相同基线分别构建原实现和仅修改一个文件的实现，使用同一独立编写的 fixture 与计数程序。每组画布 128×128，预热 3 次后计量 20 次实际 Renderer capture；随后减少图层、恢复、清空全部蒙版图层，以及 clear_assets 后再次恢复绘制。最大组达到模型上限 128 图层 × 16 蒙版。

| 场景 | 20 次 capture 的 Rust 分配次数 | 分配请求字节 |
| --- | --- | --- |
| 1 图层 × 1 蒙版 | 3018 → 2979 | 1758596 → 1755908 |
| 64 图层 × 1 蒙版 | 30284 → 30259 | 6673988 → 6607268 |
| 128 图层 × 16 蒙版 | 159980 → 159939 | 42016260 → 39885668 |

三组原图/删除后/空图共 9 份完整 RGBA 缓冲、589824 字节在前后实现间逐字节相同；恢复绘制也与各自原图相同。按文件名排序拼接 SHA-256 为 `23162c692e922e83491e1c7c940efd47411275b82e96c7536c29ab9c598355bc`。每组健康重复帧的显存总账和分类账稳定，删除后总账前后一致，空图只剩原有 4 字节默认资源。

计数只包含 capture 内当前线程的 Rust alloc/alloc_zeroed/realloc 请求，采用相同 dev 构建；包含整个绘制链的其他分配，存在小幅波动。上述原始计数不证明每帧固定减少某个次数，不测量原生驱动全部分配或帧率收益。原始报告保留逐帧累计值，没有挑选重跑结果。

## 回归与边界

既有蒙版复用/预算单元测试 13 项、layer_masks 3 项、mask_error_boundaries 1 项，共 17 项通过，0 失败/忽略。本轮新增的是独立前后对照，既有断言保持。回归覆盖动画羽化、实际绑定身份、尺寸/槽位变化、空蒙版、纹理和 buffer 拒绝、回滚、释放与像素恢复；错误身份测试属于既有覆盖，不是本轮新增日志或故障修复。没有增加重试、线程操作或改变返回值。

分支检查读取 401 个引用、110 个工作树及 14 种源文件版本，全部仍有局部集合构建。旧 egui 工作树只改图形 API 兼容调用，与本批区域无重叠；开放的图层剪贴板 PR 未改本文件。未修改其他工作树。业务源码变化只有 mask_gpu.rs；计数程序和可执行留样用于验收，不进入产品。

本轮无面板、token 或呈现规则改动，DESIGN.md §0.7 既有条目保留，§12 不据此认领新的视觉验收。没有新增依赖或第三方资产；几何 fixture、像素和计数程序独立编写。#126 其余渲染分配、GPU 对象及整体验收继续开放，不以这两个集合完成整个合集。
