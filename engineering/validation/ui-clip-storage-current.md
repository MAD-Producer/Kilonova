# 绘制裁剪与字形删减缓冲复用

本批属于 #129，合入数值读数优化的同一 PR。部分越界的拥有型三角形、保留图片的裁剪，以及删减 Shape/Glyph/Image 时的索引重映射，原先会重复创建向量。现在复用原三角形存储，并将临时映射存入绘制顺序向量的空闲尾部；渲染前原地压紧，回调 unwind 时由守卫移除临时条目。公开绘制接口、颜色、UV、绘制顺序和控件布局不变。

## 错误处理处置

| ID | 类型 | 证据与边界 |
|---|---|---|
| CLIP-01 | 正常分支 | 空裁剪、完全移除、普通越界和未出现的索引按原行为处理，不新增逐帧告警或文件 IO |
| CLIP-02 | panic 边界 | 受控字形回调在映射已建立后 panic，测试确认原 panic 传播、临时条目清除，下一帧可正常绘制；不承诺失败事务的全部字形状态原子回滚 |
| CLIP-03 | 既有非法输入 | 不重映射和发生重映射两种路径，公开缓冲中的非法字形索引仍 panic，未变成静默成功；测试确认无临时元数据逃逸 |
| CLIP-04 | 既有错误信道 | 完整 UI 回归包含 `source_failures_keep_default_file_stderr_evidence_without_text_or_reopening` 的实际默认级别文件、Error stderr 和 stdout 隔离检查；不将该字体错误测试冒充新的裁剪故障信道 |
| CLIP-05 | 功能/协议边界 | 本批没有新增 Result、等待、worker、超时、重试或 panic hook；保持原 Vec 分配及索引 panic 边界，没有注入真实 OOM，也没有宣称新的故障观测已完成 |

`final-focused.stderr` 中三个 panic 分别来自有意的回调探针和两种非法索引控制，均由测试确认传播，不是未解释的成功运行异常。独立 CI 工具首次因本地未加载现有 PyYAML 依赖而出现两个导入错误，加载已有依赖目录后 111 项中 110 过、一个既有跳过；这不属于产品红绿证据。

内存成本必须保留：拥有型三角形裁剪期间同时容纳原输入和追加输出；绘制顺序向量会保留原顺序和最多三类映射的容量，Vec 可按原增长策略扩容。本批没有新增全局池、缓存预算或持久字段，但不声称峰值内存下降。重新创建拥有型几何、Quad 首次转三角形、冷缓存和整个窗口绘制仍可能分配，未测端到端延迟改善或全帧零分配。
