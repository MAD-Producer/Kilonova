# 最小窗口预览与效果截图验收完成记录

900×600 原生验收存在两处覆盖问题：普通 Nodes 预览按现有控件空间门槛隐藏，验收仍要求其出现；1200×760 的效果时间轴场景画入 900×600 捕获目标后再裁剪，超出区域丢失。此 PR 补充已有展开路径，并让效果截图先使用可容纳测试场景的 GPU 目标，完成或失败后恢复真实窗口尺寸。尺寸检查与原有最终工程、叠加层断言保持原样，不降低 135px 门槛，也不改变产品布局、样式或命中区域。

## 结果与源码边界

完整组合原生程序基于 `302a15bf`，包含 #495 的两份缓存源码及本 PR 的验收补充；验证提交 `ca2e0398`，二进制 SHA-256 `2f246f1500e6381d59892d4692762735bf352430bd3c4d9b43b40390160c2e7b`。八个 Windows 场景全部通过：900×600、1600×1000 × 中文、英文 × 工作区、属性窗口，合计 438.9 秒。每个场景执行原有设计截图检查，报告分别包含 46 张工作区或 96 张属性设计截图；并检查六次预设切换、项目恢复及最终主窗口截图尺寸。最小场景真实展开预览 232×232、GPU 帧计数 0→3；默认布局沿用普通预览，不触发展开路径。

效果时间轴的主窗 1200×760、浮窗 900×760 截图仍满足原尺寸断言。没有缩放已捕获的 PNG 来通过检查；捕获前由真实 GPU 目标容纳完整绘制，之后恢复实际主窗口目标。

四项展开/恢复回归与八项变造证据拒绝检查见[首轮记录](minimum-workspace-preview-progress.md)。新增真实 Windows/GPU 文件写入失败测试通过（1 passed，0 failed，0 ignored）：用目录阻止 PNG 写入，返回原始“拒绝访问”原因；随后实际捕获为 900×600，工程、修订、Undo/Redo 状态不变。默认 Info 文件日志与 Error stderr 均记录捕获失败，stdout 没有日志。该测试在隐藏窗口拥有者持续派发事件时运行，没有模拟成功返回。

完整矩阵之后，捕获文件只增加了 Windows `cfg(test)` 模块声明，生产方法与矩阵源码逐字一致（仅规范化换行）；新增测试的实际二进制及五份源码散列另行记录。代码提交 `c18b700b` 之后只添加文档和归档，不改测试通过的源码。

## 原失败与审计处置

- 普通叠加层：未改动 `7b2aff0c` 在 13.25 秒内同一断言失败，首轮归档保留原始记录。紧凑布局正常缺席预览不是产品故障，补充已有展开操作的真实呈现证据。
- 效果截图：旧组合程序和不含 #495 的 QA 程序均正常退出，但原尺寸检查拒绝 900×600 图像；QA 对照耗时 59.66 秒。未经 QA 修正的老基线先在叠加层断言失败，不能用它证明后续截图问题；该提前退出也保留记录。
- 功能边界：新增 resize 只在验收截图阶段使用既有命令；保持原生窗口实际尺寸，并恢复 GPU 目标。新增内部等待各为 5 秒，不改变产品命令处理、重试或工作线程生命周期。捕获与恢复同时失败时保留主因并附加恢复原因。
- 观察边界：正常缺席、真实呈现与实际 GPU 计数分开记录；保留既有错误日志基础设施。实际写入失败证明默认文件/Error stderr/stdout 隔离；尚未注入设备丢失、resize 阻塞或捕获与清理同时失败。
- 来源与设计：未新增第三方依赖或资产；图片均为本仓库程序的原创测试输出。已核对 PROVENANCE、ATTRIBUTION、NOTICE。DESIGN §0.7 十二项均按首轮表逐项保留及说明，不把本次验收补充认作视觉整改完成。
