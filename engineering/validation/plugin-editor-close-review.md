# 插件作者窗口：取消保存关闭与无目标诊断复核

后续：用户确认测试范围后，HOST-STATE 已按完整业务状态严格比较、诊断计数
单调性检查和逐字段负对照完成验证，见 [后续记录](plugin-editor-host-isolation.md)。
以下保留本轮当时的原始失败与结论。

本轮接续 PR #566。基线为 `92bd8c09`，包含 main `ab779cee`。
PR #575 的原生预渲染仍由另一活跃分支处理，本轮不改其调度、冲突或验收结论。

## 问题与修正

1. 作者窗口的“继续编辑”原本只收起提示，没有撤销已经设置的保存后关闭标记。
   用户在保存完成消息被消费前取消关闭，消息随后仍可能令窗口退出。
   修正只撤销关闭授权；已经派发的文件保存继续完成，不重试、不丢弃其回复。
2. 诊断记录没有本地报告位置，也没有有效上传端点时，慢调用仍派发自动报告。
   该报告没有输出目标，却会持有记录锁进行 JSON 构造，造成无意义的记录争用。
   自动报告只在存在输出目标时派发。内存记录、争用丢弃计数、显式 checkpoint/export、
   默认日志和已配置报告目标的行为保留。

原窗口生命周期验收的整状态相等断言全部保留。没有改写诊断计数来制造相等，
没有禁用记录、清空错误、修改阈值或增加重试。

## 验证

修正前的测试构建通过（7 分 31 秒），两个负对照均实际失败，退出码均为 101：

- `close-negative.log`：真实“继续编辑”按钮被点击后，关闭标记仍残留；
  失败点为 `!close_prompt && !close_after_save && !close_ready`。
- `diagnostics-negative.log`：没有目标仍派发自动 checkpoint，
  失败点为 `last_checkpoint.is_none()`。

`negative-tests.patch` 保存原基线上的新增用例；`negative-metadata.json`
记录基线、负对照程序与补丁的 SHA-256。既有断言没有修改。
修正后的 Windows FFmpeg/GPU 测试构建通过（1 分 50 秒），保留 27 个既有告警。
插件常规回归 14 通过、7 个显式验收仍 ignored；诊断回归 14 通过。
原生作者验收另行通过（18.70 秒），新增保存中取消关闭的真实按钮操作和两张 GPU 截图，
保存后窗口保留、文件重开与草稿一致。无目标记录、真实显式文件导出、
已配置自动文件报告、原有争用丢弃计数和错误信道均有实际回归。

**原生宿主生命周期仍失败**（13.49 秒）：严格整状态断言的唯一差异为
`/desktop/diagnostics/droppedRecords` 从 0 到 1，详见 `native-host/state-diff.json`。
本轮去掉了无输出报告，但不能因此声称整快照的不稳定性已解决。
同步 `Engine::call_with_timeout` 的 `blocking_wait` 记录与 worker 完成记录也会争锁，
无需 reporter 即可令计数递增。原断言仍保留，未覆盖原始失败记录。
原宿主受控阻塞、panic 与状态中毒验收另行通过（0.10 秒），验证默认 Info 开始记录、
in-flight 发布、Error 文件与 stderr，以及 stdout 隔离；本轮没有新增日志观察点。

## 边界

- 本轮没有修改布局、颜色、图标、命中范围或面板代码。DESIGN §0.7 的十二项
  均保留，原因与 `plugin-editor-host-entry.md` 的逐项表相同。
- 原生截图用于核对现有关闭提示与取消后的窗口，不能代表新增视觉设计或完整 DPI/IME 验收。
- 具备报告输出目标时，记录争用仍按现有非阻塞契约计数；没有承诺所有并发情形都无丢弃。
- 真实插件实例连接、发布向导、异常 GPU 恢复与完整跨平台交互属于后续阶段，
  不用本轮局部通过替代，参见插件编辑器阶段文档。
