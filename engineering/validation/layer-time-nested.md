# 图层时间映射：嵌套视频与曝光方向阶段

接续 `a5806a0a` 的根合成视频接线，继续实现 #257。此阶段仍不关闭 issue，
不添加可见入口，也不宣称音频、预取、深度和完整编辑器已经接通。

## 本轮功能

- 连续来源坐标及其带符号导数一起经过嵌套。引用层先应用属性时钟与素材 remap，
  再保留原有 `CompositionClip::source_frame` 的 fps 换算顺序。中间不减帧、不挪动
  合成坐标，也不提前量化；最后视频叶子才按最终方向减一个解码微秒。
- 非零反向输入在 remap 键处选择左侧区间；正向和静止输入保留原来的精确点值。
  Hold 左极限与跳变后的右值分开，不能把跳变当成巨大的有限播放速度。
  连续区间的精确末键直接返回存储的双精度值，避免大起点与小终点相减的抵消误差。
- 反向连续坐标使用 `(in, out]` 的进入区间，正向与静止使用 `[in, out)`。
  因而父层倒放可以从子合成 end 进入，连续 subframe clip 的边缘也不靠 epsilon 修补。
- Scene、局部上下文、嵌套曝光任务保存传入来源导数。曝光重新构建子场景时沿用
  方向；同一引用实例的媒体准备与普通采样使用一致的来源时间。
- 无映射的正向 fps 算术、素材 PTS/颜色语义、Present 日志策略和 worker 协议不变。
  本轮没有新增依赖或素材，没有修改已有测试断言。

## 实际验证

模型定向用例检查 remap 首/中/末键、负向属性时钟、Hold 左值、静止点值，以及正反向
连续区间的精确边缘。渲染用例覆盖单次/两次倒放、24→48 fps、24→30→48 fps、
非单调转折、冻结和精确 subframe clip；采样不重写工程。

真实媒体验收使用既有 CFR 和 VFR fixture。四组固定来源时刻先在 Scene 中精确
核对，再分别运行冻结 PNG 与独立平铺来源 PNG，对完整 32×32 像素精确比较。
另外用公开 GPU 曝光路径重新构建子合成，实际 `ExposureMedia` 解码回调必须出现并
给出相同来源时间；四组完整曝光像素也与平铺 PNG 相同。曝光验收为单 phase、无
shutter 的真实嵌套路径；不能将它表述为新增映射的多采样模糊已经完整验收。
原有根视频 34 点和两组冻结 PNG 的原生用例一起重新执行。

最终测试计数、执行程序、源文件身份和原始输出见
[证据清单](layer-time-nested-evidence/manifest.json)。编译检查不计入执行测试数。
本轮最终完整模型 **206 项**、渲染选定回归 **45 项**、原生媒体 **3 项**通过，
共 **254 项不同测试，0 失败、0 ignored**。四项定向模型用例与六项嵌套渲染用例
已经包含在上述计数中；中间阶段和重复执行不重复累计。
最终全工作区 all-targets 检查通过：排除已退役 Android，启用桌面 FFmpeg 与宿主
diagnostics，保留既有告警。原编译器异常退出仍作为单独失败记录保留。

## 原始失败与处置

- 旧模型在反向输入的 remap 首键报告错误导数，在负向属性时钟的末键误报冻结；
  两项实际行为失败原断言保留，修正选段后通过。
- 旧 Scene 两项倒放用例丢失末端子合成；非单调 remap 用例实际给出子帧 16，
  固定预期 64。修正嵌套输入后通过，未改预期值或比较范围。
- 新增反向末键的位级对照实际复现 `1e9 + (0.0001 - 1e9)` 的抵消误差。直接返回
  存储末键后保留同一位级断言；没有增加容差或将时间降为单精度。
- 本机首次链接使用默认临时目录遭遇 LNK1104，设置既有专用 TEMP/TMP 后才取得
  模型行为失败；不是产品错误。另有 rustc 与 rustdoc 以 STATUS_ACCESS_VIOLATION 终止，
  确认进程结束、检查资源后重新执行；未查明该次编译器退出根因，不声称已修复工具链。
  事件记录显示故障模块为 `rustc_driver` DLL；最终原生构建也在该模块异常退出，
  补跑只针对尚未完成的原生验收和工作区检查。终止日志与 Windows 事件均保留，
  不当作通过或产品负对照。
