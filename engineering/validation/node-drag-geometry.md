# 持续节点拖动的同帧卡片复用（#134 增量）

下述节点专属证据包是提交 `55ebd886e1f50459bbf3638265db75dd571f4ae6` 的快照。后续整工作区计数入口、当前源码及最终 208 项定向回归另见 [workspace-frame-costs.md](workspace-frame-costs.md) 与其证据包；不将旧快照哈希当作后续源码哈希。

基于 #601 堆叠。开始前核对开放 PR、其他分支近期节点变更及根工作树的节点目录状态；#575、#587、#599 的完整文件清单未修改 node_editor。没有编辑其他工作树或审查他人 PR 代码。

此前即使工程身份、修订和视口都未变化，只要处于节点拖动中，一次 draw 仍会重建整套 Card、端口规格和字符串。现在仅在“进入和离开画布输入时都仍是已有节点拖动，且完整几何 stamp 未变”时，校验本帧所有 Card 与当前节点的数量、顺序、ID 和指针身份，再用已保存的世界高度与端口行坐标重新投影位置。

保存的原始指针只比较身份，从不解引用；所有卡片仍只在当前 draw 内存活，不建立跨帧缓存。先验证全体身份，再修改坐标；身份不匹配沿用原重建，是正常复用拒绝，不是错误或静默故障。按下、释放、取消、历史提交、结构/视口变化仍走原重建逻辑。本批没有修改既有 >=2 重建断言，也不宣称这些变化帧只构建一次。

内容绘制也复用本帧世界高度，避免 `node_height` 再次解析端口和计算控件数量。仅在 Card 与实际查到的 Node 指针身份相同时复用；重复 ID 查到首个节点或其他身份失配继续原计算，忽略失配 Card 的高度。原始指针仍只比较身份，不解引用。没有缓存到后续帧，也不改变失配时的原错误/回退路径。

每个 Card 新增一个世界高度 f32，每个 Socket 新增一个世界行坐标 f32，可能受结构体对齐产生额外字节；它们有当前图大小的界限，不积累历史。不会将构建次数减少称为整个 UI 零分配或 FPS/内存峰值结论。

最终节点编辑器回归 183 passed、0 failed、0 ignored，其中 6 项新增、177 项既有：中英文、两种区域、三个缩放、折叠/展开下连续 12 次拖动，每次只构建一次 Card 集合，并独立重建全部几何比较，释放一次提交、一次撤销恢复原文档；另验证失配/乱序/缺失卡片在任何修改前拒绝更新。19 个内置示例 × 折叠/展开 × 三个缩放，共 114 组卡片和端口几何逐项一致。带 FFmpeg 的测试程序与正式 dev 程序均编译通过。

两个新增内容绘制测试对 19 个示例 × 中英文 × 折叠/展开 × 三个缩放，共 **228** 组完整画布 shapes/colors/glyphs/order 作对照。身份匹配的真实 paint_canvas 不再调用 node_height；相同卡片强制走原计算时实际累计 2,172 次调用，两边完整绘制一致。独立验证重复 ID 保留第一匹配节点的原高度，失配卡片即使高度为 NaN 也不影响任何绘制指令。以上是该样本可见卡片的高度解析计数，不是整帧端口解析、分配次数或 FPS。恢复原高度计算后，真实画布断言实际失败（exit 101，首组 14 次而非 0）；之后逐字节恢复 canvas.rs，再重新编译。

恢复原重建路径后，新持续拖动断言实际失败（exit 101，构建次数 2 而非 1）。新旧程序分别在独立测试进程运行相同完整绘制记录器：24 组 × 按下/移动/释放，共 72 帧的完整 shapes/colors/glyphs/order、响应及完整编辑器快照和 undo 长度一致；24 组移动负对照均实际改变绘制/状态。原路径试验结束后逐字节恢复生产源码，再重新编译并复跑节点套件。

首次比较误将旧程序单测与新程序全套测试的记录比较，72 帧均因进程级 epoch 分配序号不同而失败。证据保留两次记录；最终比较两边相同独立进程条件，未删除/归一化任何快照字段、修改生产 epoch 或放宽断言。

草稿 PR 在最后验收前已建立。最终提交的精确 SHA CI、全部 #134 性能验收与其他分支运行时集成仍开放，不以该增量关闭整个 #134。完整命令、日志、源文件及负对照保存在 node-drag-geometry-evidence/evidence.zip，manifest.json 记录源码与压缩包 SHA-256。
