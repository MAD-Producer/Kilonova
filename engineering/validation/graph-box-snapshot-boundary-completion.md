# 曲线拖动关键帧时间边界验收

Refs #134。基线 `9dbdf75f6b6c800b52bed95b00bcf02db8ed3b71`。该合集继续开放；本项只修复旧曲线框选拖动开始时，从浮点时间读取转为整数读取造成的 panic。

## 触发与修复

普通轨道损坏已有 `animation_data::track` 解码校验，不能据静态 unwrap 推断全部路径都缺少防护。本次从真实 Core Engine 的 timeline snapshot 出发，保留合法 `local_frame=20`，只把对应合成 `frame` 改为 JSON 浮点数 `32.0` 或 `32.25`。局部时间足以完成正常采样，但框选拖动会在 `graph_box.rs:234` 的整数 unwrap panic。两个新增回归在原产品代码实际编译后均触发该 panic，0 通过、2 失败；原始日志和默认信道子进程输出保留。

现在保持既有可见时间过滤，在创建 Drag 前完整检查其全部 seed 时间以整数编码且落在 u32 范围内。任一非法时间均拒绝整个开始操作，清除旧曲线框选、显示中英反馈并占有该次输入，不能回落到其他拖动。没有发出 History 或编辑动作，也没有四舍五入、截断或只编辑剩余合法 key。合法操作的采样、位置、命中区、事务、撤销及既有过滤保持原路径。
