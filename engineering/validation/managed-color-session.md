# 普通 Session 的原生色彩安装与事务边界

本批接在 [原生程序独占移交](native-ocio-ownership.md) 和
[创作矢量合成](authored-vector-composition.md) 后。#83 仍未完成，本批不把
低层合成验收记作完整桌面显示、导出或 ACES 能力；完成 #83 后按用户要求停止。

## 功能变化

Platform 显式报告随软件分发的 OCIO manifest 路径。桌面沿用打包器已有的
Windows/Linux `native/ocio` 与 macOS `Resources/ocio` 目录；读取、身份校验、
原生加载都在明确准备操作中执行。没有能力的宿主保留原有拒绝，缺失文件保留
原始 IO 错误，不选择默认配置、不重试、不重启 worker。

普通 Session 创建、替换工程、编辑和历史恢复可安装完整的原生程序所有者。
颜色声明和静态图片声明不变的编辑复用原程序，采样不再访问配置文件。
改变声明时先完成全部候选准备，再提交模型与程序；失败不改变工程、历史、
修订或文档身份。撤销、重做与取消手势通过 Engine 的准备回调完成同一事务。
准备回调的 Err 或 unwind 在历史栈发生变化前退出；空历史和提交手势仍走原语义。

`prepare_color_sources` 与 `draw_color_frame` 是明确的无窗口消费者：调用方
保留来源集合、工作目标及同一 Session 分配预算，不允许通过另一 renderer
的预算身份绕过准入。Scene 私有颜色标记随克隆和视图上下文保留，旧渲染、
计划缓存及流水线准备不能误把工作区颜色再次按 sRGB 解码。

此处仍未接入普通 surface、多视图呈现和导出。它们遇到 managed 工程时返回
明确的消费者错误；不伪装成正常显示。工作采样会克隆 Scene 供现有状态查询，
此成本尚未经过应用播放性能验收。效果、蒙版、嵌套、视频、三维仍受原准入限制。

## 观察变化与命令边界

新增 Session 调用边界复用现有锁外观察模式。颜色准备在 Session 回调内产生的
记录先保存，正常退出、Err 与 unwind 释放 Session 锁后才交给日志 sink；
TLS 借用也在调用 sink 前结束。最多保存 64 条普通记录和另留 4 条 Error，
保留原发生顺序，每条最多 2048 字节；溢出计数饱和增长。仅普通阶段记录被省略
时汇总为 Debug，丢失 Error 才汇总为 Error，不把正常的大型准备误报为故障。
这些上限按一次最外层 Session 回调重置，不是按秒或整个进程累计。

延后的是内部阶段记录，不是命令开始信号。桌面串行 worker 在进入 Session
之前已发布真实请求的 in-flight 并写入、刷出 Info start。受控阻塞验收须在
原生能力调用尚未返回时读取这两个信号，不能用操作结束后刷出的记录代替。
独立 `prepare_project_colors` 等调用不在 Session 边界内时仍即时记录开始，
其 Observation 在 provider 进入前设为 running，在返回和 unwind 后清除。
实际默认文件缓冲区的阻塞前可见性缺口由后续
[不透明显示准备](opaque-display-preparation.md) 暴露并修正；本批测试 logger
接收记录的证据不能代替磁盘已刷出的证明。
Session 本身不是另一个串行 worker；其他嵌入宿主仍须在自己的命令入口承担
同样的开始/在途发布。内层 request 当前对应文档代次，桌面外层 request 才是
该次命令编号；不能把二者当成同一请求空间。

健康 Present 仅进入空观察范围，不新增日志、文件 IO、重试或观察事件。
原有表达式降级、last_error 持续观察及 panic hook 协议保持原样。

## 验证记录

原始输出目录：`artifacts/issue-goal-current/color-session-installation/`。

- 普通 Session 实际 Vulkan 合成通过原 CPU 的 4 个像素比较。移走配置后
  仍可采样、调色和取消允许的手势；显式恢复文件后重新准备成功。
- 5 个实际旧消费者拒绝带工作颜色标记的 Scene，已经预热的计划缓存也不能
  绕过检查；拒绝后提交空编码器，目标完整像素保持不变。
- 替换、声明编辑、重新启用与重做的真实缺失文件错误保持完整工程、历史及
  文档代次。跨线程注册表拒绝、关闭和资源所有权沿用原协议。
- Engine 准备回调的 Err 和 3 条原始 panic 载荷均保持项目、栈、计量和
  手势状态不变；两个新历史测试通过。
- 新 Session 锁边界测试通过真实 provider Err、unwind 和 80 次失败，日志
  回调实际尝试取得注册表、Session 与观察范围，验证没有锁内调用 sink。
  边界恢复后空操作安静，容量汇总和 UTF-8 长原因保持有界。
- 宿主最终集成共 26 项通过，其中颜色准备 21 项、原无能力宿主 2 项、
  注册表并发 3 项。加入锁外观察后四种子进程模式通过，包含仅正常 Info 超量
  时不产生 Error 的负对照。桌面默认颜色信道 10 项通过。
- 工具发现 144 项，143 通过、一项原有可选跳过；工具库存 70 项，来源门禁
  初次通过 6386 个已跟踪路径，新增文件纳入索引后再次通过 6394 个路径。

首轮新夹具没有给旧计划预热加载索引 0 的图片，实际预热因此拒绝；改用真实
加载的图片来源。第二轮试图在手势内改变项目颜色声明，模型按现有协议返回
Gesture；保留这个拒绝，并用允许的调色手势验证取消。未改变生产手势约束。

原桌面颜色日志测试要求 `edit_prepare` / `scene_create` 拒绝，这是尚未接入
原生 Session 的旧功能边界。本批实际执行已进入资源和原生 manifest 准备，
原失败输出保存在 `desktop-contract-before.txt`。新测试使用受控缺失路径，
检查当前真实 typed Resources / Native IO 原因、NotFound、完整状态和磁盘
字节不变；仍要求恰好四条 worker Error、Info start 在前、Error stderr 与
stdout 隔离。没有删除错误内容、降低数值容差或把真实失败改成成功。

首次桌面 worker 新夹具已完成安装、阻塞信号、缺失文件拒绝和恢复，但最后
误用不存在的 `colorManagement` JSON 键而读到 Null；保留失败，按实际必填
字段 `color_management` 修正新夹具。另保留一次旧可执行文件的零匹配输出，
它不计为测试通过。新颜色命令原因链测试已在重新编译的二进制中实际运行通过。

桌面颜色命令的外层 Error 原先只显示 preparation 包装文字，虽有内层记录，
却不能单凭命令请求号取得原生 IO 原因。本批单独修正颜色命令的观察格式：
最多 8 层 source，每层沿用已有短原因限制，整体沿用 2048 字符限制。
原 typed 错误及回复协议不变，其他命令仍使用原格式。另补颜色采样的模型和
原生错误 Display，使 renderError 与错误回复包含 source 原因；这属于错误
呈现内容修正，不改变基础帧降级、健康采样、布局或控件样式。新增真实表达式
在后续帧抛错、完整工程不变及恢复的桌面验证，以及长路径原因链负对照均通过。
后续帧错误在默认文件、Error stderr 和 renderError 中保留原原因；回到正常帧
后 renderError 清除。长路径负对照证明旧外层格式会丢失原生原因，完整 typed
错误中的路径、IO kind 与原因并未被截断。旧二进制零匹配没有计入这两项结果。
