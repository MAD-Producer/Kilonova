# 原生 OCIO 来源准备阶段诊断

## 修正范围

此前原生配方只观察 CMake/验收子进程。下载、归档检查与解包、复制许可证及
发布清单时，没有对应开始和在途状态，长时间不返回就无法从证据判断阶段。
本批沿用配方现有 `events.jsonl` 和 `in-flight.json`，在来源目录准备、每个
来源的下载/检查、解包，以及最终清单发布前写入 Info 开始与运行状态，完成后
清除状态并记录 Debug 耗时；失败向文件和 stderr 写相同的有界原始类型/原因。
stdout 继续仅供最终成功的清单 JSON，不写诊断。

不改变固定来源、SHA-256、解包路径约束、原有下载 60 秒参数或编译选项；不增加
重试、进程重启或生产看门狗。路径上下文限制 1024 字符，原因限制 2048 字符，
原异常对象仍原样抛出。阶段数量只随固定的 7/8 个来源增长，不在帧热路径运行。

状态清理或事件文件再次失败时，记录次要故障并继续抛出主错误。Python stderr
流不可用时，降级到原始 fd 2；两个诊断出口均不可用时不能保证输出，但仍保留
主异常，不把诊断写入 stdout。显式取消与零退出的 SystemExit 记录 Debug；
非零退出仍是故障。既有子进程信道和非零退出语义保留。

## 实测证据

- 本地独立 HTTP 夹具实际阻塞响应。进入真实 HTTP handler 后，主线程检查
  下载 Info 已存在、阶段为 source_download 且 running=true；解除阻塞后，
  实际归档校验、解包字节和最终状态均正确。再次用同一已验证缓存离线准备，
  HTTP 调用数保持一次，无 Error。不是用模拟成功回复验证开始信号。
- 真实下载字节与声明不符、真实归档路径越界分别在 download/extract 阶段
  报错，原异常、耗时、来源和路径保留；stdout 无日志，不发布成功清单，下载
  失败的 partial 文件保留。真实未完成边界验收的 publish 拒绝有独立阶段。
- 真实文件系统故障覆盖在途状态清理和事件日志写入：把对应文件改为目录后，
  主 FileNotFoundError 对象保持同一身份，次要清理/日志故障可见。正常处理后
  才出现的清理失败本身抛出，不记录虚假完成。
- 真实独立子进程关闭 Python stderr 流，实际原始 fd 2 收到与文件相同的错误，
  stdout 为空；子进程仍按原 FileNotFoundError 退出。没有模拟 logger 成功。
- 8 KiB 受控错误与路径验证有界保留，同时调用者仍获得完整、同一异常对象。
  显式中断、零退出不记 Error，非零 SystemExit 保留 Error。
- 实际运行完整配方 CLI 的 `--offline` 缺源故障，固定 OpenColorIO 来源在
  source_download 阶段拒绝，文件与 stderr 的结构化记录逐字段相等，退出码
  为 1，stdout 空、running=false。该调用未执行原生编译，不能算新原生资格。

首轮两个新增故障检查直接在 JSON stderr 中搜索原始 Windows 路径，被合法的
JSON 反斜杠转义阻止；改为解码对应记录并严格比较完整原因。首轮输出保留，
没有修改已有验收断言、配方功能、原生数值参考或容差。
