## 行为和协议

现有 `anchor_at` 的 frame 从 u32 升为 f64 合成时间，目录 schema 同步为 number，
没有另造一套命令。变速／倒放图层的动画锚点入口保留原播放头，不再先向下取整。
未映射图层面板原先的取整行为、静态锚点的全局补偿命令保留；静态全局补偿仍拒绝
将连续空间动画烘焙为整数键。

锚点与补偿位置复用 TrackAt 的时钟解析、精确投影往返、分离维度和稳定空间键
寻址。两个通道先构造候选，再一起安装。普通整数轨道遇到无法表示的局部时刻，
在改动任何通道前失败。空间轨道的准确投影沿用已有键 ID，非整数时间不取整。
效果的源时间重映射不参与属性时钟。

补偿计算保持原有局部坐标、三维旋转顺序和缩放规则；父级仍由渲染场景应用。
固定时间的连续空间键支持本次补偿。浮动键会随几何变化重新计算时间，候选若不能
在当前时间采到要求的锚点和位置，明确报错并保持所有通道与浮动策略不变。没有为
通过验收关闭浮动、固定时间或接受画面跳动；更完整的浮动键补偿仍是后续边界。

锚点数值编辑以及真实合成控制器在开始时捕获 NumericTime；工程、合成、generation、
播放头、偏移或时钟改变会正常取消／回滚。手势自身产生的 revision 变化不取消编辑。
数值编辑保留原有主窗、浮窗、时间轴／属性面板布局；合成手柄保留命中范围。

源码／二进制 SHA-256、命令、逐项结果和日志见

核心覆盖正放／倒放、有符号局部帧、父级、三维旋转和镜像缩放、分离维度、精确
关键帧之外的数据不变、空间 ID、第二通道失败、取消／单步撤销／重做和保存重开。
面板验收覆盖两个宿主、主窗／浮窗、中英文；合成控制器核对实际投影角点不移动。
原生 GPU 图仅验证实际控制面板和输入生命周期，不将其冒充合成内容的像素基线。
两组原生输入用例共保存四张前后截图；提交后的实际窗口为
[中文主窗属性](layer-time-anchor-compensation-evidence/properties-main-zh.png) 和
[英文浮窗时间轴](layer-time-anchor-compensation-evidence/timeline-floating-en.png)。

原有回归发现静态分离维度的位置补偿失败：共用编辑器写了合并值，却未更新实际
采样的轴值。修正静态轴值写入，不创建整数关键帧，并以原有回归及新增小数局部
时间的静态分离维度用例验证；没有删除原有失败断言。
另一条原有回归确认静态、未映射的全局锚点操作不需要播放头；新保护明确限定到
需要时间的路径，保留只含工程数据的局部视图，而非给缺失时间伪造一个有效帧。

保留首轮错误证据：新增 integration test 模块路径遗漏；测试中的非 const Rect
构造；测试 ParentLink 类型及 model 模块命名空间写错；新时间轴测试最初用完整
面板宽度计算属性控件命中，改为真实属性区宽度；固定空间轨道夹具最初错误调用
要求非空选区的浮动操作，改用真正的固定时间空间轨道转换。均未改生产返回值来迎合测试。
原有 AnchorAt 的三个 Rust 整数实参改为同值 f64，原断言仍精确检查 frame=45；
这是协议类型升级所需的机械调整，不改变原成功／取消或不变性要求。
