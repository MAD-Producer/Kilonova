# 桌面启动只加载当前内置包（#64）

正常桌面应用过去在 Session 初始化时调用完整历史包目录，首次进程会解析并经
Naga 编译七个版本。现在桌面打开工程和插件安装时的并发刷新使用当前版本入口；
精确匹配的六个历史包只识别原始字节，不展开、不编译、不自动恢复到运行目录。
首次新建的插件目录只写入当前 2.0.0 包。SDK 的显式历史目录／注册接口保留。

正常桌面 SurfaceTarget 构建也改为显式空注册表，随后由 Session::attach 安装已有的
已验证注册表，再配置资源／进行首帧呈现。Renderer 新增显式注册表构造入口；默认
SDK 构造仍保留历史目录语义。EffectGpu 接收注册表，不在窗口线程重复展开历史包。

外部插件继续完整校验；已知历史内置包的桌面安装在解析 shader 和写盘前拒绝，
避免成功安装后下次启动又不可用。不能仅凭文件名跳过历史包：损坏的包及当前缓存
仍保留原始错误，并在注册表诊断中补充具体路径。未新增日志轮询或改变错误回复协议。

## 冻结源码与实际验证

- 最终冻结源码执行实际 GPU 注册表安装测试、既有历史/当前包像素对照、29 项效果包
  测试和 1 项宿主观察测试（内部四个独立子进程模式），
  全部通过；效果包测试包含 6 项新入口／负对照及既有包身份、shader、资源预算验证。
- 正常 FFmpeg 应用构建和 desktop all-targets 编译检查通过，仍有既有 warning。
- 八个正常应用 PID 使用真实窗口、Session、私有缓存 Restore/Save 和 MCP 协议，
  无测试专用 Engine 或注入缓存回调。四组各自比较两个独立进程：含反相工程启动、
  无效果启动后首次／移除再加反相、目录有六个历史包、目录中一个历史包损坏。
- 八个进程均正常退出 0，cold 为 missing，warm 为 restored。含效果的准备状态必须
  installed、已呈现 revision 匹配且 preparing=false；capture 不得新增原生管线创建。
- 历史包缓存逐字节保留；无历史包目录只新增一个当前包，有历史包目录保留六个旧文件
  并只新增当前包。损坏目录的 Error 实际出现在默认文件日志及 stderr，stdout 仍是
  JSON-RPC，坏文件不被覆盖。损坏的旧包不能被误报为正常退休。
- 首次添加和重加的原生效果管线创建数相同，完整像素相同；四个基础场景与旧提交的
  初始工程字节及全 64×64 RGBA 哈希也相同。没有改包、shader 或渲染像素语义。

源码以证据包中的 `tested-source-identity.json` 为准，各命令前后及命令间一致；
`working.patch` 和两份新测试源码衔接基线 `624c79e2`。三处既有内部 EffectGpu 测试只
补入同一 renderer 已有注册表参数，所有既有断言、ignore、等待预算保持不变。

## 保留的中间反证

第一轮仅修改 Session 时，其初始化约从 5–6 秒降至 1.3–1.4 秒，但当轮完整画面仍需
7.4–13 秒；同期旧版复测为 6.2–8.9 秒。该证据不能支持端到端提速。进一步定位到
EffectGpu::new 在窗口线程再次初始化所有历史包；当前源码同时消除了这条重复路径。
证据包 historical-partial-fix 保留当轮 8 个进程，未用最终结果覆盖。

新增 GPU 测试首轮错误地期待禁用效果静默旁路，实际得到既有“layer 1, effect 1:
plugin ... is disabled”错误。修正新测试以核对该精确拒绝、移除效果后的完整原图恢复，
保留失败 stdout/stderr，未修改产品禁用语义或既有断言。
