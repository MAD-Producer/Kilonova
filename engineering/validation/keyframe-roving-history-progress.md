# Roving 派生缓存的历史预算

这是 #260 在轨道接入后的内存约束阶段，基线为 `59373178`。没有开放桌面菜单或更改 UI
布局，没有新依赖、外部资产或像素采样语义变化。前一阶段记录的 RT-10 由本阶段接续。

## 实际政策

原有每份快照的精确工程 JSON 字节计量保持独立。预算追加计入 undo 与 redo 联合持有的
空间预计算分配；同一份 Arc 只算一次，值相同但重新准备的分配分别计算。活跃工程、
外部冻结快照和手势过程的瞬时准备不属于撤销历史预算，仍受已有单份几何节点数量上限
约束；不能把这一政策宣称为进程总 RSS 上限。

计量覆盖区间、每个区间的节点表、累计长度、作者槽、有效时间和稳定 ID 数组的实际
capacity，以及 PreparedSpatialTiming 和 Arc 控制头的保守对齐开销。它不等同于平台
分配器的 size class／元数据、通用模型堆容量或 GPU／图像资源。缓存大小在准备完成时
计算，记录读取为 O(1)，Present 取样不增加计量遍历或 IO。

资源记录按合成和所属图层缓存，覆盖位置、锚点、合成摄影机位置／目标和摄影机图层。
普通修改只更新所涉及的所有者；结构变更重建。历史移动复用记录，缓存句柄本身持有
对应 Arc，身份不会因为原分配先释放、地址复用而混淆；不设置永久全局注册表。

撤销后执行新命令或提交手势，先丢弃已失效 redo，再依现有顺序裁剪历史，避免为即将
丢弃的缓存提前驱逐可用 undo。128 项数量上限及默认 32 MiB 字节预算不变；容量计算和
合计溢出饱和为 usize::MAX，不允许回绕成小值。

作者数据相等的命令恢复修改前的工程分配，回到原位的手势恢复基线工程和计量记录。
仅比较模型相等不足以维护分配身份：一次无改动的准备也可能分配新缓存。如果沿用旧
计量记录却让工程持有新缓存，会额外保留旧分配并漏记新分配；本轮补充了身份级测试。

## 观察与功能边界

| 项 | 分类及证据范围 |
| --- | --- |
| HM-01 | 功能修复：将遗漏的派生空间分配加入真实历史裁剪，而非只新增日志 |
| HM-02 | 功能修复：联合历史按实际共享身份去重；分叉时先清理 redo |
| HM-03 | 新的运行时诊断：history_diagnostics 增加 modelBytes、spatialCacheBytes、retainedBytes；不记录地址、用户文本或路径 |
| HM-04 | 正常分支：没有空间动画的所有者不产生缓存记录，正常驱逐、空撤销、手势取消不是故障，不增加 Warn／Error |
| HM-05 | 既有覆盖：实际编辑拒绝仍由原核心事务及桌面 EditorAction 错误信道返回；本轮未新增命令 handler、线程、超时、重试或 panic hook |
| HM-06 | 计量边界：暂存工程和准备期间的峰值、外部快照、一般模型堆／分配器开销及 GPU 不属于此历史预算，不宣称全局内存验收完成 |
| HM-07 | 待完成：#260 的稳定 ID 桌面选择、拖动、菜单、曲线与实际 GPU／编码输出及跨平台验收 |
| HM-08 | 功能修复：无改动命令和回到原位的手势保持工程／缓存记录的实际分配身份一致；不增加历史或改变既有 revision 规则 |

本轮只改模型与核心预算，DESIGN.md §0.7 的面板基线全部保留原处置，没有声称修复视觉
违规。前一阶段 worker 原始日志仍只证明其所属提交的错误信道，不冒充本阶段重新构建
的桌面验收。纯核心错误断言也不冒充默认日志与 stderr 的新证据。

## 核验

实际专项先后发现两处新增夹具构造错误：摄影机图层的 Transform 锚点必须静态，因此
将动画锚点放到普通图层；编辑合成摄影机前必须显式设为已创建。保留两次失败输出，
未改动产品校验或已有断言。另保留首次 CLI 参数重复 `--lib` 的启动拒绝，它未运行测试。

最终冻结源码共 67 项不同测试通过：完整核心单元 39 项、模型空间缓存单元 2 项、核心
空间关键帧集成 6 项、空间调度 11 项、实际 Track 7 项、无分配取样 2 项。1 项既有手工
性能测试保持 ignore。专项中的 7 项核心测试已包含在完整 39 项中，不重复累计。
命令、源码哈希与原始输出见[证据清单](keyframe-roving-history-evidence/manifest.json)。
原始构建、失败与成功输出也保留在本机 `artifacts/issue-goal-current/spatial-history-budget`。
