# 连续矢量动画的上传复用验收

对应 #126，基线 main `e314cc92232dcd366b01e10454ae1100d4e24d63`。
开工已检查开放 PR、最近本地分支和工作树；跟踪、抠像与后台预渲染由其他分支推进，
本批只补既有矢量上传实现的持续动画验收，不重新实现已合入的缓存。

## 验收场景

新增 `animated_geometry_and_group_opacity_reuse_uploads_across_sixty_sampled_frames`。
工程含一个圆角连续变化的矩形和两个独立的嵌套矢量组；各组子级不透明度为 50%，
根级分别按线性关键帧从 100%→10%、10%→100%。使用真实 Scene、Renderer、GPU
上传、呈现和 readback，未模拟成功返回。

先完整执行 60 帧预热，再执行同一动画的 60 帧验证。圆角几何的最大曲率不等于
最大三角形数量，不能假定第一帧已覆盖整个动画的容量要求。两个周期均逐帧保留
上传计数；测量周期仍保留实际几何采样、变动上传、绘制和同步回读。

- 第二周期目标和 staging 缓冲创建总数不再增长；实际上传字节持续增加，且上传
  增量具有多种大小，排除静态纹理重播与恒定几何。
- 纹理字节、admission 总额恒定，已完成上传的 pending 字节/数量归零，空闲池
  不超过原有数量与字节上限。结束后清理资产、丢弃 target/Renderer，验证精确释放。
- 两组中心像素的 alpha 直接按 `0.5 × 根级线性不透明度` 计算，误差最多 2/255；
  不调用产品的动画采样逻辑生成该期望。
- 相邻帧完整输出必须不同。在 0、1、15、30、45、59 帧另建 Scene、Renderer 和
  target，验证完整输出逐像素一致，覆盖独立缓存与实际几何变化。

## 原始失败与负对照

保留三轮新夹具失败：角数使用线性关键帧，被现有离散参数校验拒绝；改为保持
关键帧后，星形边界变化使“纹理字节恒定”的前提不成立；换成固定外边界的圆角
矩形后，第一帧并非最大 tessellation 容量。最终使用完整周期预热。以上均为新
夹具假设修正，未修改任何既有验收断言，未修改生产容量或资源策略。

最终测试原文不变，分别临时修改生产源码执行两个负对照：

1. 禁用 ReusableBuffer 命中，每次都新建目标缓冲：第二周期第 1 帧创建总数从
   305 增至 310，原计数断言失败。
2. 跳过 frame > 0 的矢量绘制/上传：第二周期第 1 帧“动画必须上传变化几何”
   断言失败，不能靠返回静态画面伪装资源稳定。

两次故意变更均按原始字节恢复，校验 SHA-256；最终生产源码与 main 完全一致。
负对照失败是预期结果，不计入通过数。最终测试文件 SHA-256 为
`76cd2473e3039a4c654779e9c540ad10ff2364f43e8692df5108a3bbc759f8c2`，
两条负对照与最终通过运行使用相同测试文件。

## 最终执行结果

在本机 NVIDIA RTX 4070 Laptop / Vulkan 上执行以下命令，默认 `gpu-tests` 开启：

```text
cargo test --locked -p motion-render --test vector_upload_reuse --test vector_groups --test vector_error_boundaries --test vector_budget_alignment --test vector_adjustment -- --test-threads=1 --nocapture
```

五个目标共 **26 passed / 0 failed / 0 ignored / 0 filtered**，194.11 秒（含编译）。
其中矢量调整 9、预算边界 5、错误边界 2、嵌套组 5、上传复用 5；新增连续动画项
包含在 26 项内，不将中间重复运行再计入。

测量周期目标缓冲累计创建数恒为 3、staging 恒为 6；admitted 字节恒为 1,432,944。
逐帧实际上传增量出现 1,552、1,840、2,128、2,416 四种大小。上述数字只描述
本夹具，不是整个桌面的工作集或每帧分配量。

原有工作流策略 15 项通过，未修改断言。合计 41 项不同测试通过；两个真实负对照
按预期失败。最终源码身份稳定，所有生产源码与 main 原文一致，`git diff --check`
通过。尚未把本地结果称作最终提交的跨平台 CI 或整个 motion-render 回归。

[证据包](vector-animation-reuse-evidence.zip)：44 个成员、69,526 bytes，SHA-256

已逐成员读取并核验清单，含原始成功/失败输出、逐帧记录、命令、源码身份、两条
临时退化补丁及恢复前原文。文档不放入证据包，避免自身哈希循环。
