# 冻结读者锁隔离与错误边界验收

## 范围与协作

本批同时推进 #130 的冻结读者全局锁范围、#138 的宿主媒体错误类型保留，不关闭这两个聚合 issue。基于 #381 的 `fix/media-teardown-cleanup`（`54b7f4b5476100536a6dbb582aacb77252bec0e3`）建立 `fix/frozen-reader-isolation`，通过堆叠 PR 复用其中已经改为类型化结果的 `VideoFrames`，避免在主分支上重复适配相同行段。开始前检查开放 PR、所有 worktree 在 `ops/media.rs` 的提交差异和未提交内容，没有该文件的未提交占用；相关未合入修改属于 #381，因此没有修改其分支或管理其 CI。

这是共享宿主 SDK 的冻结快照接口修复。现有生产调用者包括保留的 JNI 接口，当前桌面导出走独立路径；不宣称解决桌面播放卡顿，也不新增 Android 功能、构建或 CI。没有用户可见 UI 修改。

## 功能及协议边界

- 全局登记表只保护句柄查找、插入、删除和容量预留。混音器构造、同一读者上的混音/帧准备、资源析构移到全局锁外；每个读者保留独立操作锁，同一读者仍串行。
- 关闭句柄阻止后续查找；已经取得读者所有权的操作可以结束。正在构造、关闭后仍被操作持有、正在析构的读者继续占原有配额，避免并发关闭/新建绕过 8 个音频、4 个视频上限。
- 读者字段先析构，容量凭证最后归还。视频原生 worker 仍由既有解码器/回收配额约束，本凭证不代表已经 join 原生 worker。
- 构造失败或 panic 通过 RAII 归还容量；读者 panic 只中毒本读者，不清除中毒状态、不吞掉 panic、不重启线程。另一个健康读者可继续工作。
- 新增公开类型化入口 `ops::media::frozen`，保留原生 `motion_media::Error` 及模型错误。父模块旧入口仍在最终边界转成文本，原有 JSON 格式和音频字节输出保留。句柄为不透明值，失败构造可以消耗编号，不保证连续编号。
- 会话层仍返回 `String`，以 `Session(String)` 显式标注；`PreparedVideoFrame::decoded()` 的混合结果仍是文本，`BlendRead` 保留句柄、对象、序号和原始文本，不伪造原生 source。全宿主的错误类型迁移仍待完成。

登记表计数覆盖构造至最后一个读者所有者析构的生命周期，并在最后所有者释放后归零。等待数饱和计数，在取得操作锁或取消排队时递减；不是按频率升级的故障计数，不使用“60 次等于一秒”的解释。诊断条目按原有读者容量限制，操作名均为静态值，不存用户文本；`occupied` 和逐读者状态是并发采样，不承诺全局原子快照，构造中及关闭后仍在工作的条目可能只体现为占位数。诊断本身没有文件 IO，也不自动逐帧轮询或输出。
