# OCIO 配置内容身份与明确选择

关联 #83，基于 LUT PR #643 的堆叠交付，不使用关闭整个 issue 的关键字。
开始前按各工作树 merge-base 核对独有提交及脏文件：其他 agent 正在做 UI、
深度、跟踪、多视图；本批未改这些实现或项目格式，未审查其他 agent 的 PR。

## 可使用的底层能力

`ColorConfigManifest` 保存固定 OCIO 版本、明确的内置 ACES 版本或作者标识、
配置正文/全部资源摘要、明确上下文、编码/reference/data 声明、角色与显示/视图。
没有“最新配置”或默认角色替代。目录有独立版本；未知字段、重复名称、坏引用、
非规范资源名、超限内容均拒绝。允许 OCIO 未声明的空 encoding，不猜测传递函数。

`VerifiedColorConfig` 先限制实际字节与目录，再校验整个内容集合；缺少、增多或
改动资源均失败。不可变 Arc 字节保持准备时身份，磁盘位置不参与摘要。SHA-256
覆盖有版本命名空间的确定性清单，清单内再约束所有正文/资源字节；不将原生
OCIO cache ID 当内容摘要。`ColorSelection` 明确输入、工作、显示/视图、输出与
配置/ACES 身份；解析失败不重选或修改已有配置。数据空间不作为色彩变换使用。

这不是 OCIO 语法解析器或认证机制：运行时层验证字节和目录引用，信任外部
准备器的语义目录。此边界在模块与使用说明中明确，不能由合法摘要推导出任意
作者声明都与 OCIO 正文语义相同，更不能将目录解析当成实际像素变换。

## 官方运行时与外部准备

沿用已记录来源、BSD-3-Clause 许可和 wheel/原生模块摘要的外部 OCIO 2.6.0，
不增加产品依赖或默认配置资产。工具显式选择三份 CG 配置：ACES 1.3、2.0、2.1。
目录、正文和资源信息来自真实原生 API；独立 Rust 校验每份实际导出内容，Python
按公开身份编码独立计算的摘要与 Rust 相同。角色解析还与原生明确命名处理器
身份比较。三个目录不同，过期身份、改动字节及缺角色明确拒绝。

原生 OCIO 在配置创建时缓存全局 active displays/views 覆盖；创建后移除变量
仍失败。外部单线程工具在排除三项全局覆盖的作用域内，从显式正文重新创建
配置，再恢复环境。未变更原有环境隔离断言。显式上下文变量和 FileTransform
均拒绝，包含隐藏空间、未使用命名变换；一般配置资源闭包导入仍待实现。
此工具不能嵌入编辑器/宿主进程，不能把它的环境操作带入应用线程。

## 故障与观察账本

| 编号 | 处置、证据、边界 |
|---|---|
| CONFIG-PARSE | JSON Err 保留原生 serde_json::Error 及行列；外层 Display 只显示有界行列，不展开超长未知字段 |
| CONFIG-CONTENT | 正文/资源改动、缺资源及未声明资源真实字节拒绝；失败替换不改变已验证目录 |
| CONFIG-BOUND | 实际输入先限额后哈希；验证正文、单项、资源数、总字节及清单上限；超长选择名称不进入诊断正文 |
| CONFIG-SELECT | 缺角色/空间/display/view、配置或 ACES 不符、数据空间误用均 typed Err；没有重试或默认替代 |
| CONFIG-MISS | 独立资源查询的 Option::None 是正常未命中，不记录故障；必需资源缺少则在构造返回 Err |
| CONFIG-CLI | 真实目录已存在时原生 FileExistsError 保留在 stderr、stdout 为空，已有全部字节保持；Python -O 同样拒绝 |
| CONFIG-OBS | 没有新增 worker/handler/日志站点；库返回 typed Err。宿主接线时仍需已有非 Present start/in-flight/错误信道，本批不冒称完成新的桌面日志端到端验收 |
| CONFIG-PENDING | 工程字段、一般配置闭包、原色/白点/范围声明、CPU/GPU 处理器导入、显示/输出接线与设备资格未完成，#83 保持打开 |
