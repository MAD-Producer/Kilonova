# 棋盘格尺寸和 UI 缓冲容量复核

2026-11-04，基于 #605 的 f69358b1，继续完成 #129。
开始前读取全部七个开放 PR 的完整分页文件清单；其他 PR 没有 desktop/ui 改动。
本批只添加回归与证据，未修改绘制、着色器、面板或样式代码。

## 已有实现与本次证据

- C1：checkerboard 对零、负值、NaN、正负无穷返回空列表。六种尺寸的
  shapes、colors、order 均为空；五种 DPI 下共 30 张实际 GPU 读回图全透明。
- C2：正尺寸只发出一个程序化图元，不再按 CPU 方块数量生成顶点。
  七种尺寸（含最小正次正规数、最小正规数及最大有限数）和两种画布范围
  共 14 组保持一个图元。已有 WGSL 将单元尺寸下限限制为一个逻辑像素；
  四种小于一的尺寸在五种 DPI 下共 20 张图与一像素参考逐字节一致。
  参考图包含黑白两色，排除空图通过；整数 DPI 的四种尺寸另有八张全图
  与独立 CPU 棋盘格栅格逐字节对照，包括画布外透明像素。
- B1：已有 buffer_tests 实际在旧容量 5,767,168 字节的 GPU 缓冲写入
  5,856,576 字节，捕获对应验证错误作为负对照；正常路径扩容并保留末尾
  图元像素，多帧和空帧不重复扩容。字形增长保留末尾文字与交错绘制顺序。
- B2：设备上限不足时在上传前返回 PaintError，包含类型、顶点数、所需容量
  和限制；下一张正常帧恢复。非二次幂设备上限、索引与字节溢出也有断言。
  相关六项原测试通过，没有修改它们的断言或错误返回语义。

使用标准 cargo test 执行容量目标与路径目标，默认 MOTION_LOG=info。
完整 UI 库 91 项、最终路径目标 12 项通过，均无失败或忽略，共 103 项不同测试。
容量六项包含在 UI 库 91 项中，不能额外相加。前一轮直接 rustc 的十项结果
仍保留历史身份；本轮标准 Cargo 结果补齐这两个目标，不等于全 workspace 回归。
