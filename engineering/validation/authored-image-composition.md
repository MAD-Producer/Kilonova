# 原始图片进入工作区合成

## 功能与边界

#83 本批在既有创作颜色合成接口中接入二维静态图片。宿主的
`PreparedNativeAuthoredProject::prepare_images` 对每个被图层引用的静态素材准备
一次原文件输入变换；`Renderer::prepare_authored_images` 保留 Float32 工作纹理和
一次创建的采样绑定；`draw_authored_scene_with_images` 使用真实工程采样与既有
平面几何合成。没有向旧 sRGB 图片缓存插入工作纹理，也不重新编码工作颜色。

工作空间仍要求完整范围、预乘 Alpha、Float32。原图通过已经准备好的原生
OCIO GPU 输入程序进入该空间；图片层的白色 tint 保持单位乘数，不把白色作为
创作颜色再次送入 OCIO。图层不透明度仍在实际合成时应用。显示和输出沿用
显式端点程序。普通 managed Session、视频、矢量、效果、蒙版、嵌套及三维
消费者尚未接入；原有拒绝边界继续生效，#83 不关闭。

工程素材声明在 sampler 创建时冻结。声明的 ID、路径或尺寸变化需要重新准备；
每帧不复制整个素材目录，不访问文件。绑定保留实际工作纹理的 Arc，源文件被
外部修改时，文件观察者必须显式准备新集合。本批不声称已接入文件观察者，
也不声称能在没有刷新请求时识别磁盘内容变化。

绑定检查设备所有权、完整颜色契约、声明尺寸、非零唯一 ID 和最多 128 项的
容量限制。绘制在创建编码器及写入 uniform/顶点前，检查缺失/陈旧来源、设备、
目标契约、尺寸、源目标纹理别名及降低后的来源预算；缺失来源不回退到旧缓存。
来源容量按纹理身份去重，同时沿用全局实际分配预算。提交包含来源及目标账本，
现有分配编码器保留实际分配直至队列完成。这里不是物理显存统计。

## 数值验收

本机 Windows x86_64 Vulkan，复用已经验证的固定 OCIO 2.6.0 核心及当前桥接库。
新测试读取原有 `source_reference.json`，实际写入 16 位 PNG，再经原文件准备、
原生输入 GPU 程序和真实平面合成；参考字节及原绝对 `0.0001`、相对 `0.0002`
容差均未改变。

- 14 条既有链，共 168 个工作区像素，包含直通/预乘输入和相邻 16 位码值。
- 根据每条参考链的真实阶段和输出 Alpha 选择显示或输出端点，不将不同端点
  或不同 Alpha 的结果混为一个参考。
- 直通端点的零 Alpha 参考保留不可见 RGB，而预乘合成必然丢弃它。该分支检查
  输出有限、Alpha 精确为零、预乘后覆盖为零；所有非透明样本仍按原始、未加权
  的逐通道容差检查。工作区全部样本仍比较原 CPU 参考的正确预乘表示。
- 准备后删除原 PNG 与配置文件，连续采样三个小数帧并实际绘制，期间没有中间
  CPU 回读。图片采样绑定只在准备函数中创建，绘制函数直接复用。
- 同一合成器实际执行 14 组漏输入转换和 14 组重复输入转换的错误 GPU 路径，
  全部与正确参考产生超容差差异；错误生产者契约只存在于负对照。
- 小数帧图片不透明度符合原参考乘积；缺少集合、陈旧声明、纹理别名、错误尺寸、
  重复 ID、错误 Alpha、错误设备和降低后的来源预算均拒绝。检查失败保留目标
  像素；两个声明引用同一纹理时账本只计一次。
- 素材声明变化不发布新帧；取消准备返回原取消类型并清除在途状态，随后正常
  准备可以成功；数值 Data 图像作为颜色图层被明确拒绝。

首轮新测试的失败原样留存：别名对照误用了另一个纹理集合；直通零 Alpha 的
不可见 RGB 与预乘合成直接比较；将输出阶段误作显示阶段；以及遗漏参考中的
交叉 Alpha 端点。这些均修正本批新测试的场景构造，没有修改既有参考、既有
断言或生产端点行为。最终 15 项宿主集成测试全部通过，其中六项创作合成
包括此前四项回归。宿主准备单测三项、真实解码阻塞/unwind 回归一项通过。
七项桌面默认信道测试通过；首轮新日志匹配遗漏每源 start 的 `asset=1` 上下文，
该新测试的匹配构造已纠正，原始捕获文件及失败输出单独保留，生产 logger 未改。
