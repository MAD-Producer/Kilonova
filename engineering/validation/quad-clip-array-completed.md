2026-10-25，基线 `7bd4d86003b21dd02483e73cbccac730df7036a7`，关联 #129。本次只删除 `expand_quad` 后的一次 `to_vec()`；六个展开顶点改用定长数组，继续借用为切片交给原来的裁剪函数。输出三角形仍按原逻辑分配，不改变算法、几何、颜色、顺序或 API，不宣称裁剪零分配。

## 实际对照

相同独立临时程序分别在未改与修改后的源码运行，每组 64 个新建四边形，夹具、断言与序列化在计数区间外；线程局部 System 分配计数器只覆盖一次实际 `PaintList::clip_to`。记录为 Rust alloc / alloc_zeroed / realloc 请求，不是全桌面帧率或全部原生分配。

| 场景 | 原请求数 | 修改后请求数 |
| --- | --- | --- |
| left | 192 | 128 |
| corner | 192 | 128 |
| outside | 128 | 64 |
| rotated | 256 | 192 |
| contained | 0 | 0 |
| max_edge | 0 | 0 |

四种需要进入裁剪分支的场景各减少 64 次请求，即每个四边形少一次临时分配。完全在内和恰好接触最大边界的两组对照原本已为零，保持零。六组的全部顶点、颜色及绘制顺序逐项完全相同；检查裁剪顶点有限且位于矩形内。完整输入/输出和计数见 [结果记录](quad-clip-array-results.json)。
