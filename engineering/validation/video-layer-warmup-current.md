# 视频片段进入前预热验收

实现源：`6ee2ceb2a644ae0e21936bc9f8379fab444e0426`，基于 main `ead8ce0c`。归档中的九个源文件 SHA-256 与完整测试前后及提交后工作区一致。本阶段推进 #257 的视频连续播放边界，不关闭整个 issue。

## 功能和资源边界

借用工程拓扑检查随后最多四个输出帧，计算即将可见的视频实例和源时间。处理嵌套合成帧率、起点、反向、独立实例及遮罩依赖；使用与实际场景采样一致的实例身份，不再次运行表达式或生成栅格化场景。当前必需视频先请求，随后才用空闲配额预热。四个解码器的原有上限包括退休中的 worker，预热不增加该上限，也不让当前帧等待未来片段。

精确读取和导出不启动新预热；查找范围、候选数和保留错误均有界。离开范围与清理沿用现有生命周期，不新增重试、重启、线程超时或缓存预算。新增拓扑登记本身会占 CPU 元数据，不能宣称总堆内存没有增长。

## 报错信道与审计

V1：规划失败复用 FailureCounter，首次 Debug、第 60 次 Error，成功或正常空结果重置。测试实际注入 120 次缺失资产、穿插成功、再注入 60 次，验证两条 Error 和原始对象/阶段原因；不是每帧 Info，也不把缓存未命中当错误。

V2：首次预热准备在可能阻塞的索引加载前记录 Info，包含实例、资产、源时间。准备失败记录一次 Error，有限保留原始类型化原因；之后当前需求抵达同实例时返回原错误，不通过重开掩盖故障。改变资产身份或显式 clear 才清除该状态。实际缺失索引测试验证重复轮询、文件恢复后不自动重试，以及 clear 后恢复。

V3：原生打开/解码继续由既有 worker 发布在途状态与错误记录；受控阻塞和 worker 故障测试验证当前读取不被未来失败阻断、失败只打开一次。这属于既有覆盖，不宣称新增了所有底层原生异常观察。

默认 Info 子进程的真实 events.log 有两条规划 Error、一条准备 Error和对应 Info start；stderr 仅三条 Error；stdout 无应用日志，日志不含测试私有图层名。记录和上下文有界。该子进程使用 log 接收器验证输出分流，未启动完整桌面日志宿主，不能替代整窗日志验收。原类型化准备原因保留，既有 worker 字符串错误边界未在本批重构。

## 未解决范围

- Stream::new 仍同步读取时间索引；预热提前原生打开/解码，尚未消除所有文件 IO 阻塞。
- 四帧预测不覆盖导入时已经可见的冷视频、冷 GPU 管线及任意远距离跳转；满配额时可能无法预热。
- #257 的保存/撤销/导出及其余整窗场景仍独立验收，不以本阶段关闭。
- main 的 libav 跟踪夹具帧率类型编译失败在另一 agent 分支已有修正；本分支不重复修改或声称 main CI 已绿。
