# 矢量创作颜色进入工作区合成

## 实现与范围

#83 的创作颜色合成接口现接受二维矢量填充、描边和分组绘制。
`AuthoredSceneSampler` 对采样后的画笔颜色执行已保留的原生 OCIO 输入程序，
先按明确的输入 Alpha 和码值范围解码，再保留直通工作 RGB。几何准备明确区分
原有 sRGB 画笔与已经转换的工作画笔；后者不再执行 sRGB 解码，在顶点颜色中
只预乘一次。负值和高于一的 RGB 不截断，工作栅格使用既有 Float32 格式。

转换只操作采样副本。工程轨道、路径、描边宽度、虚线、修剪、组隔离及不透明度
的模型语义不变。普通与分组绘制复用现有几何、栅格、来源预算和分配账本，
没有新增着色器、第三方依赖、资产、UI 或旧工程兼容代码。

每层最多缓存两个原始采样身份及其转换结果，以覆盖 sampler 的两个 Scene。
缓存随图层移除而清理，sampler 生命周期内原生程序、范围和 Alpha 契约不可变。
几何缓存同时检查画笔解释，GPU 栅格指纹也区分工作画笔；因此同一个 renderer
在旧路径和工作路径之间切换时，不会把相同数值误认成相同颜色。

实际 GPU 编码提交前保留栅格守卫。错误返回或 panic 展开会使下一次显式绘制
重新生成栅格，避免把未提交的命令误记为已完成；成功提交才解除守卫。
守卫不重试失败操作，不吞掉错误或 panic，不自动返回旧帧。来源预算包含当前
工作图片集合，与矢量来源共同计量；全局分配预算及在途资源保留仍由现有账本管理。

## 本机数值与状态验收

Windows x86_64 Vulkan，复用固定 OCIO 2.6.0 核心和已经核验的当前桥接库。
所有比较沿用原 CPU 参考及绝对 `0.0001`、相对 `0.0002` 容差。

- 三份配置、直通/预乘输入、填充/描边及普通/分组共 192 个实际 GPU 采样点。
- 将原参考输入用二进制精确的有限范围编码放进合法矢量颜色控件，再执行原输入
  解码：另 288 点通过，包含 72 个负通道和 216 个 HDR 通道。没有修改模型颜色
  控件范围、原参考或像素容差。
- 准备后删除配置文件，两个备用 Scene 连续采样绘制；常量画笔的栅格上传计数
  不再增加。产品采样过程不加载原生库、不访问配置文件、不回读工作图片。
- 动画保持关键帧对应原 CPU 色样，图层小数不透明度和组不透明度实际相乘。
  同一 renderer 执行 24 条漏输入转换或重复 sRGB 解码的真实错误 GPU 路径，
  全部被原参考检出；随后恢复工作路径，像素仍正确。
- 降低来源预算真实拒绝绘制，目标像素不变；显式恢复预算后可正常绘制。
  陈旧颜色契约不发布新采样帧，完整工程 JSON 保持不变。
- 普通和分组栅格分别覆盖正常放弃编码器与 panic 展开，原 panic 载荷不变，
  未提交命令不更新目标；后续显式绘制正确。故意提前解除守卫的错误生产者
  确实留下旧像素，证明缓存恢复的像素断言能检出缺失守卫。

首轮编译错误原样保留：遗漏生产蒙版对几何函数的调用、新 GPU 测试误用目标类型，
以及旧预算测试的私有函数签名变化。保留原测试调用接口并修正新辅助函数，
没有修改既有断言来通过验收。
混合来源的新夹具首轮将不透明图片放在矢量前景之上，像素对照因此检出覆盖；
夹具已按既有图层顺序放置图片背景，未修改生产排序或预期合成公式，失败原样留存。

相关矢量回归 25 项、CPU 几何准备 5 项、此前与本批宿主集成 18 项、默认颜色
信道 8 项均通过。默认测试实际检查日志文件、Error stderr、stdout 隔离、受控
阻塞与 panic 退出；原渲染模块两条及桌面模块 26 条编译 warning 保持原状。
标准工具发现 144 项，143 通过，一项原有可选跳过；工具库存为 70 项。
来源门禁通过，共 6,383 个跟踪路径；四份原数值参考的字节身份仍由归档脚本核验。
另行新增的图片与矢量混合预算一项通过：普通与分组首次栅格化均计入原文件
工作图片的占用，少一字节即拒绝且不写目标；显式恢复预算后合成符合原 CPU 公式。
