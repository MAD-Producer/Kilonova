# 发布整数检查策略（#125 阶段交付）

开工核对开放 PR 的文件清单及近期本地分支：有理帧率、跟踪、原生预渲染均由其他分支推进；本轮只修改工作区 release profile、独立的算术策略回归及说明，不改这些分支。工作区基线为 main `6ab57829`。

## 改动

工作区 release 显式 `overflow-checks = true`、`strip = "none"`；原有行号调试信息、thin LTO 与单代码生成分区保留。移除只覆盖 `motion-effects` 的冗余特例。详见[策略说明](../release-profile.md)。

新增算术策略用例用运行时输入检查有符号、无符号的加减乘共六种溢出，正常算术仍保持原值。它必须在实际 release 下运行，不能用 debug 下通过代替；显式关闭最终测试 crate 的溢出检查作为负对照时应失败。没有修改既有断言。

发布版现有时间映射、极值、资源尺寸与总量边界回归正在执行，最终结果与实际 Cargo profile 尚待归档。首次正常 release 编译在第三方 `image` 的 rustc 中以 `STATUS_ACCESS_VIOLATION` 退出，未执行测试；原始命令、诊断与退出 101 保留。不能据此声称产品缺陷已复现或验收通过。

额外的工作流路由测试未能启动：本机此 Python 缺少 PyYAML。没有工作流改动，不把缺依赖当成路由回归失败或通过；原始输出保留，不额外安装或修改依赖。

原始记录位于本次本地 artifacts 的 `issue-goal-current/release-overflow-policy/`；可移植证据包与完整退出码待检查完成后补齐。先提交草稿，避免把已可审查的改动继续留在本地。
