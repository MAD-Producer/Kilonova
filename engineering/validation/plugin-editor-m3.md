# 插件编辑器 M3 验收

范围：`feat/plugin-editor` 的节点/WGSL、公共参数和结构化布局作者工作区。
入口与操作见 [作者界面说明](../host-api/plugin-editor-authoring.md)。
独立窗口已接入；主工作区/浮动宿主窗口、连接真实实例属于 M4，本记录不将其计为已完成。

## 原始失败与修正

- 第一轮拖放测试误点相邻的参数页签，第二处错误是误判 `node_capture.fingerprint` 为整数，
  之后又发现参数声明顺序与布局顺序不同。分别依据原生页签、实际参数表及既有返回契约修正
  测试坐标/类型检查；保留三个失败日志。原有验收断言没有放宽，指纹额外检查真实 16 位字符串。
- 扩展节点回归有 1 项失败：`real_inspector_text_input_and_save_shortcut_capture_committed_value`
  在 `editor.field.is_some()` 处失败。当前二进制单独运行同样失败，M2 留存二进制也在同一文件
  同一断言失败；保存日志、二进制时间及 SHA-256。该测试使用硬编码检查器点击坐标，
  但本轮没有据此改断言或宣称已修复原检查器；175 项回归不能表述为全部通过。
- 分栏实际命中被子控件抢走：设计模式先命中分隔条/选中角点，再命中子控件；
  原生拖动与取消验证比例及恢复值。固定结构和非法自身投放在 UI 层不显示有效落点，模型校验保留。
- 后台保存与当帧编辑原本可能错序：文件命令移到内容输入之后，提交有效短文本/节点字段再取快照。
  连续输入与 Ctrl+S 的原生测试验证落盘内容。打开新文件同样先提交编辑，再检查脏状态。
- 一次产品捕获脚本只投递合成鼠标消息，未可靠切换标签，GPU 像素断言拒绝该截图。
  改为对已核验 PID、标题、客户区的窗口执行系统鼠标输入，重拍后通过相同 GPU 断言；
  失败运行日志保留，不把脚本问题描述为渲染器修复。
- 发现源码高亮借用了不相关颜色语义，改为先在 `dark.json` 定义独立 `syntax.*` token，
  不改写画笔中的颜色。尺寸和新设计辅助线全部通过语义 token。
