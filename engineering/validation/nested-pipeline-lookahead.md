# 嵌套合成与时间重映射的后台预热（#64）

本轮把嵌套边界求解接到既有 Session 准备 worker。进入新图层前，worker 根据引用链的
帧率、源起点、图层时钟和时间重映射寻找后续采样区间，准备实际使用的效果管线。
不改变已有图层采样、曲线、渲染精度或效果包字节。

## 功能与工作边界

- owner 只提交当前帧与不可变工程快照；图遍历、时钟反解与未来 Scene 采样都在原有
  单 worker 内进行。既有 `phase=plan` 状态和 Info start 先于这些工作发布，仍受同一
  panic、取消、generation、revision 和结果安装边界约束。
- 逐层组合 parent/child fps、`source_start_frame`、偏移、伸缩与方向。连续重映射使用
  [模型交点基础](nested-pipeline-time-crossings.md)，另外枚举 Hold 和映射分段的键时刻。
  先在可见本地时间窗口二分筛选键，避免远处键投影超界而拒绝附近预热。
- 在边界之后的区间内部采样，处理倒放与半开范围归属；不依赖反解浮点数恰好落在
  边界的哪一侧。无嵌套工程继续使用原有根边界快路径，既有断言不变。
- 范围仍为当前帧之后两秒，最多两份未来 Scene，加当前 Scene 共三份；不是整份工程
  的无界预编译。图工作上限 16384、事件上限 1024、每次反解与路径交点上限 128，
  复用现有文档深度限制。事件上限按去重前的出现次数计算，是保守容量边界。
- 共享工作预算包含重映射访问的键段；预算耗尽返回明确错误，不把部分交点作为完整
  成功结果。新测试验证部分结果拒绝、预算复用和独立新预算的恢复。

## 失败、取消与日志

图遍历或反解失败时，保留当前 Scene 准备，返回有类型的 `lookaheadErrors`，并将
`limited` 设为 true。记录请求、generation、revision、帧、enumerate 阶段、耗时和
最长 2048 字符的原始原因。只跳过该请求的推测性未来 Scene，不修改普通渲染预算，
不自动重试、重启或伪造完整预热成功。当前画面仍可能有效；未来效果可按原有路径创建。

正常取消、没有未来边界及无连续交点不是故障。取消前后均有检查；中途取消时不把
已失效请求的枚举错误当作当前工程故障。既有 worker 协议允许会话关闭后的弃置回复。
模型纯函数仅返回错误，由宿主边界记录，不额外创建日志基础设施。

## 验证与负对照

真实 GPU 宿主矩阵每种情况分别创建 Renderer，避免上一个用例的管线缓存掩盖遗漏：

1. 子合成 60fps、根合成 30fps、非零源起点。
2. 两级引用链，内层另有源起点、伸缩和非零时钟枢轴。
3. 加速伸缩。
4. 倒放。
5. Hold 跳变。
6. 两个键的源值都在范围外、弹性超调在中途进入子图层精确小数范围。

各情况均先在子效果尚未可见的帧完成预热，再呈现已知未来效果：完整 RGBA 必须变化，
前台 `effect_pipeline_builds` 不得增加；另一个冷 Renderer 必须创建该效果管线，且
完整 RGBA 与预热结果相同，作为预热有效性的负对照。

另用 32 个引用与 20 个未来叶图层制造真实事件预算耗尽：工程验证合法，当前 Scene
有 33 个合成节点，未放宽 64 节点渲染限制。要求错误原因和 limited 状态保留，当前
完整 RGBA 与同步冷 Renderer 相同，并验证取消返回正常取消分支。

完整宿主预热套件 16 passed、0 ignored；模型全套在新增共享预算测试后
71 passed、0 ignored。带 FFmpeg/diagnostics/ai-depth 的正常桌面构建与 all-targets
检查通过；仍有既有 warning。

最后额外重复宿主命令时，Cargo 的 `.fingerprint` 目录在写入前已经不存在，编译
以 os error 3 退出，测试尚未启动。这次失败保留，不记作通过。核对全部 2477 个
源码文件身份，成功的 16 项宿主验证与最终源码只差 `crossings.rs` 末尾新增的一个
`#[cfg(test)]` 模型测试；移除该新增测试后，文件完整字节 SHA-256 与宿主成功轮次
一致，其他源码哈希全部一致。模型新增测试已在最终 71 项中独立通过；桌面构建、
all-targets 和双进程验收使用相同最终源码。证据包保存前后原文件及差异证明，不把
失败的重复命令冒充通过，也不修改已有断言或重新创建已被清理的大构建目录。

另启动两个独立普通桌面程序进程，使用 `--mcp-ui`、各自账户目录和正常窗口，无测试
Renderer、故障注入或替代 logger。一个工程只有一个引用，另一个有 32 个引用、真实
超过事件容量。两者均成功呈现并正常退出，当前 64×64 完整 RGBA SHA-256 相同：
`afc421c2248cb70f37a306262f50d10518d5cc4a8db1dd6dd7c2c9861ecba47d`。
受限工程保留明确原因与 limited 状态，健康工程没有该错误；启动不改写工程。

未设置 `MOTION_LOG`：失败前已有同请求的 Info planning start，错误字段完整进入
文件日志和 stderr，stdout 每行均可解析为 JSON-RPC。状态回复中的错误原因是协议
数据，不能误判为日志污染。普通视口与抓图产生两个不同请求，各记录一次容量错误，
不是轮询重试。真实启动到验收完成分别约 8735 ms 和 5297 ms，包含窗口、字体与
MCP 查询，只用于确认完成，不作性能比较。运行 exe 与全部七个固定 FFmpeg DLL
保留身份；首次打包命令误按五个 DLL 检查，启动前即停止，更正为实际七个后运行。

首轮新增夹具用了不符合文档约束的 composition ID；更正后又发现弹性用例的整数
timeline 与 precise clip 不匹配。两次原始失败分别保留；只修正新增夹具，没有放宽
文档验证、已有断言、ignore 或测试预算。之后六种 GPU 情况和容量用例均通过。
