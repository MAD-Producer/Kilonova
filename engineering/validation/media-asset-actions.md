## 功能边界

- `media_asset` 是现有命令注册表中的可撤销命令，使用已有项目、原子编辑、资源验证和历史，不增加工程字段或修改版本号。
- 图片替换复用导入的探测、受限复制、解码预热及资源预检；新文件独占创建，失败由已有 `OwnedFile` 清理。既有图层尺寸、变换、时间区间及素材 ID 保持。
- 音视频替换复用已有异步导入任务，完成探测/解码前不修改工程。`finish_media_replacement` 在编辑器线程核对版本、类型和任务状态，再发布文件和一次编辑。错误由现有发布回滚处理。
- 视频和关联音频在一个模型动作内更新，保留已有音频 ID，使提取音频仍引用正确来源。没有原音频时可新增关联音频；新源没有音轨时，只允许移除未被其他图层/视频引用的旧音频。
- 删除仅移除未被引用的素材登记。引用检查覆盖所有合成，包括未被主合成引用的合成、不可见图层、文字栅格、效果图像输入、视频的关联音频。保留文件供撤销使用，不做磁盘垃圾回收。字体登记使用独立的字符串身份，本阶段未实现字体操作。
- 用户正常取消和被后续编辑淘汰的请求不是故障。新 API 明确返回 `asset_operation_cancelled=true` 和 `superseded`，媒体任务实际取消；未来版本号等非法请求、文件或解码失败仍返回原始错误。后续界面必须检查取消标记，不能把取消显示为“替换成功”。这是一项功能协议设计，不是日志层吞掉 `Err`。
- 成功发布后的采样错误单独写 Error 并通过现有 `renderError` 报告，不能把已提交的替换伪装为未提交。

## 验证与限制

原始记录位于 `artifacts/pr-ci-followups/media-assets-*`。首轮 core 编译的类型/借用错误、视频夹具无音轨的失败、空集合省略导致的新测试断言错误、测试缺少 `Project` 导入的编译失败均保留。媒体全量首次漏加串行参数，7 个包发布测试在全局两 worker 预算竞争下提前销毁尚未安装任务的 provider，触发 `Option::unwrap()`；保留 `media-assets-media-full.log`，按 `.github/workflows/ci.yml` 既有串行调用重跑后 165 项通过。没有改动包发布实现、测试断言或生产预算。

- 新核心测试：替换的身份/图层/单步历史；被引用/失效删除不破坏 redo；孤立素材删除保存重开、文件保留、撤销；非法元数据/相对路径/gesture 拒绝；未引用合成与隐藏图层的引用；效果图像输入引用。
- 桌面真实管线：PNG 像素、截断解码/缺失/非法版本/正常过期；WAV 过短、实际取消、坏解码、丢失源重链接；libav 视频关联音频及提取音频；增删未使用音轨；成功后保存重开及 undo/redo。
- `cargo test -p motion-core`：374 项通过，1 项人工性能采样忽略；包括新增 6 项素材模型/历史测试。
- `cargo test -p motion-media --tests -- --test-threads=1`：165 项通过，2 项既有人工验证忽略。
- 最终 `media-assets-host-final.log`：5 项通过，包括真实图片和音频失败的默认日志验证；带 FFmpeg 的 `cargo build -p motion-desktop --features ffmpeg` 通过。
- 没有修改面板、主题 token 或渲染采样语义，也未增加依赖、外部资产或效果包。

外部删除的旧文件无法通过撤销凭空恢复；修复丢失素材后的撤销恢复原始登记，原来丢失的文件仍然丢失。多份同时丢失的素材仍受现有全工程保存/资源预检约束，逐一修复可能被其他丢失源阻止；本阶段未放宽该规则。真实 OS 文件对话框取消、文件位置命令、主窗/浮窗焦点、中文/英文菜单、DPI/窄窗样式均属于后续界面验收。
