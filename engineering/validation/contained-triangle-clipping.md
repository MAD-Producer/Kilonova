# 完整可见三角形裁剪复用验收

本地基线：主线 `1dd366e8ccc7e1655d383f8b0db57febfd806d85`。
分支：`perf/contained-triangle-clipping`。推进 #129 的裁剪分配子项，
合集其余缺陷和性能验收保持开放。

## 改动和边界

`PaintList::clip_to` 原来为每个三角形形状重新分配输出，即使全部顶点
已经位于裁剪范围内。现在仅在顶点数是三的倍数、且每个顶点通过原有
`Rect::contains` 判定时保留原缓冲区；否则继续调用原 `clip_triangles`。
边界判定不扩大，部分越界、非有限输入、尾部不足一个三角形的数据仍走
既有路径。空输出仍移除形状，并按既有映射处理颜色和创建顺序。

源码对照确认产品只有该分支五行新增、一行替换，其余绘制、三角裁剪、
错误和协议代码保持原文。没有修改布局、字体、样式、坐标、命中区或
交互。该路径没有新增缓存、日志、错误吞没、重试、线程或超时。

保留原 Vec 容量至其原有生命周期结束，不新增跨绘制保留。原容量如果
大于长度，本次不会为了缩小容量而重建输出。部分越界数据会多做一次
完整性/包含检查；不声称所有输入更快、峰值内存下降或全部裁剪零分配。
索引映射及真正需要裁剪的输出仍可分配。

## 分支核查和实际对照

实施前检查 385 个分支引用、21 份不同绘制源码、114 个工作树与开放 PR。
没有已有的完整三角形复用实现。唯一相关文件的未提交改动位于其他
`egui-desktop-shell` 工作树，为 wgpu API 接口适配，不修改此裁剪分支；
未编辑该工作树。节点查找、最近效果菜单和查看器工具工作不重复。

新增图标回归在原实现实际失败：当前全部 54 个原生图标完整位于区域内，
连续裁剪 20 次有 1100 次分配。修改后同一测试只有 20 次，减少 1080 次；
这些剩余分配来自原有形状索引映射。每个图标三角形的指针和容量保持，
没有重新分配其存储。计数器只记录当前测试线程成功的分配/重分配请求，
沿用已有分配器与校验，不将请求次数等同于 FPS 或峰值存活内存。

第二个新增测试验证尾部 0/1/2 个顶点的原截断语义，以及不足一个完整
三角形时形状、颜色、顺序同时移除。原有混合裁剪、字形 UV、颜色、
顺序及不匹配公开缓冲区断言全部保留。

临时公共 API 探针在原实现和修改后各运行一次。256 组混合形状/字形
场景包含随机交叉、完整三角形、尾部不足、空、边界、带指定 NaN 位型、
无穷、退化/反向区域、无效顺序索引和不匹配颜色缓冲区；另外全部 54 个
现有图标 × 三个尺寸 × 三种裁剪区域形成 486 组。每组再嵌套裁剪一次，
共 742 组、1484 次裁剪。记录完整形状、颜色、字形及创建顺序，另记录
三角形输出的逐浮点 `to_bits`，避免只凭 NaN 的调试文字判断相同。

前后 4,402,530 字节全部一致，SHA-256 为
`4d7d2c51bc6afddb33f563debaac12c64a158a1a6cae46670ba7d9234a047925`。
这证明所述输入的命令和三角形输出位相同，不是全部 GPU/系统输入验收。
临时测试文件在最终回归前已移除，没有绝对路径或探针进入产品。
