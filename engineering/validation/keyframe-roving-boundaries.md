# Roving：当前时间与身份边界

本页是 #260 剩余实现的代码审计与约束，不是功能完成证明。当前分支没有启用 Roving，
也没有用整数帧重排或移动属性值代替持续约束。自动时间贝塞尔的实现继续保留。

## 行为来源与独立实现

仅以[公开速度指南](https://helpx.adobe.com/after-effects/desktop/animate-in-after-effects/speed-between-keyframes/speed.html)
核验空间属性、首尾固定键及中间键随邻键改变而重新求时的行为边界。未读取产品二进制、
资源或专有工程，未复制文案、图标、截图或算法实现。运动路径及几何计算将独立编写，
不新增依赖或第三方资产。

## 当前代码的约束

| 当前实现 | 对 Roving 的直接影响 |
| --- | --- |
| `motion-model/src/animation.rs` 的 `Keyframe.frame: i32`，键数组按此字段二分 | 此字段同时承担时间和作者键寻址；不能把有效小数时间四舍五入回此字段 |
| `Track::sample_value` 按作者帧分区，再计算局部进度 | 需要查询派生时间；仅给状态 JSON 添加一个小数显示不会改变真实采样 |
| `Track::key_frames`、`move_key`、`copy_key`、`delete_key` 以整数帧寻址 | 派生时刻移动后，旧的选择身份仍须指向同一个键；复制须产生新身份 |
| `motion-model/src/keyframe_clipboard` 的选择／数据及核心命令使用帧列表 | 剪贴板、撤销、重做和批量事务需要与新时间身份保持一致，不能只改一处模型采样 |
| `desktop/app/src/panels/key_selection.rs` 以通道和合成时间保留键身份 | 时间轴、曲线图和右键菜单的命中应使用有效位置，发命令应使用作者键身份；不能靠每帧改写选择来掩盖不一致 |
| `animation.rs` 的空间插值使用三次控制点和 De Casteljau 求值 | 路径长度要覆盖曲线和回环，不能拿端点直线距离代替；常速采样还需要弧长到参数的反解 |
| 自动时间贝塞尔目前拒绝手动空间路径 | Roving 的空间度量与时间自动端点是不同策略，不得为复用现有查询而移除空间切线或偷换度量 |

## 实施必须保留的条件

1. 先把作者身份与有效时间分开，再开放菜单。时间用有界、有限的小数计算；首尾固定键
   不参与漂移。邻键值、空间切线或首尾时间改变后重新解算，不把旧结果当永久作者时间。
2. 空间度量包含直线、三次曲线、闭合回环、重复点及零长度段；弧长误差、参数反解误差、
   样本数、迭代次数和内存均须有明确上限。不能无限细分或失败后退回直线长度。
3. 零长度段可能让两个有效键时刻相同，但它们仍是两个不同作者键；全静止路径不能
   除零。时间身份设计必须先覆盖这些情况，不能通过添加任意 epsilon 掩盖碰撞。
4. 只对空间位置、锚点和明确声明的位置控制点开放；缩放、颜色、旋转、标量、离散项、
   几何轨道和拆分轴不得因为存储为数值向量就被当成空间路径。
5. 固定化应保留当前小数时刻和路径；手动时间编辑须明确解除所选键的时间约束。
   不转换整个区间，不修改邻键的空间几何，也不恢复旧整数时刻造成跳变。
6. 类型、路径、时间以及选择变更必须是同一可撤销事务。拖动取消、失焦、工程代次变化、
   保存重开、剪贴板和后台冻结导出都要使用相同的求值定义。
7. 工程只接受当前版本；保留版本号字段。不为旧工程添加迁移分支。若调整工程结构，
   同步当前 fixture；渲染与效果包基线属于另一项成本，不借机改动像素语义。

反例：在固定时间区间 `[0, 10]` 内，空间路径累计长度为 `[0, 1, 3, 9]`，两个中间键
应落在 `10/9`、`10/3`，不是 1 和 3。若路径累计长度改为 `[0, 0, 3, 9]`，第一个
中间键的有效时刻与起点重合。当前整数帧既当时间又当身份的表示不能完整承载这两例。
