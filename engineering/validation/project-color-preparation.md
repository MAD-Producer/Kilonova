# 工程色彩程序的宿主准备

关联 #83，接续 #648 的工程契约和 #650 的图片空间身份。本文记录新增准备边界；完整色彩工作流仍未交付，不能关闭 #83。

## 本次实现

`motion_host::color_preparation::prepare_project_colors` 从工程自己的资源目录读取完整、验证过的配置快照。调用方显式提供可信 OCIO 程序准备器；接口把确切配置字节、完整选择、阶段和透明度传给它，既不搜索外部配置，也不从环境启动 Python 或选择默认运行时。

默认素材输入、创作颜色、逐素材覆盖、工作到显示和工作到输出分别准备。相同完整请求共用不可变 `Arc` 程序；数据、深度、法线等声明保留原意义，不经过色彩程序。查询不存在的素材返回正常 `None`，不会继承默认输入。结果保留完整配置快照，后续磁盘变化不会改变它。

准备全部成功才返回一个结果，失败不修改工程或安装部分程序。不同阶段、透明度、配置、策略、GLSL 或文件内容都必须通过其各自检查。当前最多保留 256 个不同程序和 64 MiB 编译 shader/数值表有效载荷；素材路由沿用工程既有的总资产上限，不另造计数规则。有效载荷不是 Rust 分配器或 GPU 内存测量。配置正文/资源另受既有 64 MiB 闭包限制。

有限范围输入/工作/显示/输出尚无归一化编码路径，本次在进入准备器之前明确拒绝，不能拿 full-range 程序执行后继续沿用 limited-range 声明。创作颜色的原色、白点等仍是工程的显式声明，不由 shader 编译成功认证其物理含义。

## 错误与观察审计

| ID | 分类 | 实现与证据要求 |
|---|---|---|
| PCP-01 配置文件缺失/篡改 | 新接线，复用验证 | 在调用程序准备器前通过 core 闭包验证；原始 IO/资源错误仍可通过 source 查询 |
| PCP-02 程序阶段/alpha/身份/编译错误 | 新功能拒绝 | 先核对阶段和 alpha，再复用真实配置及 Naga 编译检查；不返回部分程序，不替代变换 |
| PCP-03 外部准备器 Err | 新观察 | 保留 `Box<motion_host::Error>` 原始类型；日志原因最多 1024 UTF-8 字节、8 层；测试检查原始 IO 类型和完整原因仍存在 |
| PCP-04 阻塞/不返回 | 新观察 | 调用前原子发布 request/in-flight，Info 记录 start、读取、provider、compile；独立观察不需要会话锁；受控阻塞验证尚未返回时状态已发布。不新增线程、超时、重启或重试 |
| PCP-05 panic | 新观察，复用既有 hook | RAII 清除 in-flight 并记录 abandoned；不 catch 或改写 panic。测试在调用方捕获以核验原始载荷仍传播。生产 hook 仍由现有宿主负责 |
| PCP-06 非 managed/数据/缓存复用/查询未命中 | 正常分支 | 分别返回正常 None、旁路或复用；不报错。并发复用同一观察对象返回 Busy，且不清除原任务状态 |
| PCP-07 容量 | 新功能拒绝 | 超过程序数或编译有效载荷时拒绝，保留已计费状态；单元测试注入边界状态，避免制造大内存压力 |
| PCP-08 应用错误信道 | 尚未接线 | 新错误可嵌入现有 `motion_host::Error`，但尚无普通编辑器命令安装该准备结果；不能把库返回或日志验证表述为应用设置/错误弹窗已完成 |
| PCP-09 panic Error 双输出 | 单独的既有功能修复，关联 #138 | 真实默认日志验收发现：文件保留强制回溯，stderr 仅有原始 hook 文本。修复 sink，使可用文件锁分支也向 stderr 写完整 Error；持锁时仍 try_lock 后原始 stderr 回退一次，不重复该回退，不移除原始 hook |

日志使用现有 `log` 门面，无 stdout 输出、专用日志文件或第二个 logger。默认桌面 logger 的真实子进程验收覆盖 Info 文件记录、Error 文件与 stderr、stdout 隔离、原始原因和正常 unmanaged 恢复。该验收与完整 Session 安装是不同边界。
