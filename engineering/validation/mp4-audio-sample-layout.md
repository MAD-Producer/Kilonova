# MP4 样本分块与文件范围预检

关联 #131，分支 `fix/mp4-sample-layout`，基线 `dec6fec0764ccab61ecf4460c76b5f2f6b98ac97`。承接已合入 #455 的时间表校验，未更改其断言或时间语义。

## 功能修正与范围

三个真实畸形 M4A 分别在原生 demuxer 的块编号减一、区间样本数相乘及累计相加处触发溢出 panic。本批在初始化解码器和创建 PCM 前，对每个轨道的 `stsz`、`stsc`、`stco` / `co64` 做独立预检：先核对声明数量与实际长度，再检查一基块索引、严格递增区间、样本累计、样本/分块数量一致性，以及每块数据在实际文件长度之内。表项声明校验先于原生表分配，文件范围校验先于包缓冲读取。

预检不展开紧凑的逐样本向量；遍历受实际元数据表长度限制。沿用 16 MiB 元数据、4096 atom 和 32 track 限制，没有提高预算。可选/缺失表仍交给原生 reader 判断，包括分段流的空表；没有将正常缺失记录为故障或伪造成功。文件范围校验不能证明数据属于 mdat 或编码包有效，也不是对实际大文件内单包内存的完整限制。

这属于输入验证功能修复，没有新增日志观察点、阈值、重试、线程重启、依赖或素材。预检发现的是主动拒绝条件，不伪造原生解码错误；已有文件 IO 原因与 worker 的原日志信道保持。工程格式、渲染语义和可见 UI 没有变化。
