# macOS 原生 CI 的调试信息开销调整

## 原始失败

PR #602 原提交 `68e1415ea919f8215acc03801d0dbb2312f957c8` 的 run 41599656365 / job 125795521444 因超过 90 分钟被取消。GitHub 注释明确记录 `The job has exceeded the maximum execution time of 1h30m0s`。不是断言失败，也不是新提交取消旧任务。

桌面主测试集实际完成 1,626 项通过、0 失败、4 项既有忽略，耗时 3,822.16 秒；后续宿主集成测试继续推进，直到预算耗尽。构建及 FFmpeg 打包阶段尚未执行，不能把此前四项绿色检查当成全部验收完成。

## 调整和边界

Linux 原先已使用 `line-tables-only` 调试信息，macOS 仍生成完整 DWARF 类型信息。本次让 Unix 原生矩阵一致使用行表，保留回溯的源位置；Windows 继续保留原值 `2`。这针对大量隔离故障子进程的回溯符号化成本，属于配置优化假设，实际提速和整体通过仍须由新提交的 macOS CI 证明。

没有调整任务超时、测试选择、串行执行方式、特性、断言、故障次数阈值、重试或忽略属性。`Backtrace::force_capture()` 与默认日志的产品行为保持。没有新增依赖或资源。

原始完整日志、终态、GitHub 取消原因和时间间隔分析保存在 `ci-macos-line-tables-evidence/evidence.zip`，逐项哈希见同目录 manifest。时间间隔包含 harness 和相邻测试准备，不能充当独立测试耗时；其中长间隔也不单独证明符号化因果。

## 验证状态

- 已核对配置差异仅为注释和两个 debug 配置表达式；测试命令和期限没有改变。
- Linux、Windows 取值保持；macOS Intel 和 ARM 改为行表。
- 新提交的完整 macOS 运行、默认错误输出和行号可用性仍待原生 CI 验证。不能强制合并，也不能声称已解决超时。
