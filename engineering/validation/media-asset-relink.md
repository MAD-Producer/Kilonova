# 多素材重链接事务验证

接续 #222 的[素材操作](media-asset-actions.md)与[共享菜单](media-asset-actions-ui.md)。旧阶段记录中的多份素材恢复为当时的未完成边界；本记录单独验证本轮新增流程，不改写已有证据。

## 问题与实现

单份替换会对完整工程执行资源预检。三份素材在工程打开后同时被移走时，第一份替换也会因另外两份丢失而失败。不能跳过资源校验来让它通过。

新增 `missing_media_assets`、`start_asset_relink` 与 `finish_asset_relink`。图片、独立音频和视频使用各自原有 ID；关联音频随所属视频恢复。候选文件在独立目录中逐份复制、实际解码并暂存，暂存期间不改动原工程、保存文件或图层。草稿使用真实模型事务验证替换与引用，暂不进行持久化；对外的任务只报告准备/待提交，不把草稿成功当成原工程已更新。

所有候选通过后，发布独占的新素材目录和暖缓存目录，拒绝覆盖任何既有缓存，随后对整组命令执行既有全资源预检和渲染器目录更新。一次提交、一条历史；失败回滚新拥有的目录，原素材和旧缓存保持原样。提交后快照失败也不能删除已提交资源。撤销无法重建在应用之外已经被删除的旧文件；有效旧源下的单步撤销/重做另有真实混合媒体测试。

Project/Media 右键菜单新增“重链接丢失素材…”。逐份明确选择文件，显示引用图层名与旧路径；不猜测同名文件。选择阶段任意取消都不启动事务。图片、音频、视频共用后台进度与取消入口。工程版本或 document generation 失效时正常取消；文档切换后的取消任务仍可查询，调用方释放后清理旧工作目录。

桌面准备、状态推进、提交与取消均排入既有引擎，事件线程只用 `try_recv` 收取回复，不等待解码或整组提交。取消可以替换尚未返回的接收端；后台完成真实工作后返回实际快照。提交已经完成的晚到取消显示成功，不假装回滚。`cancel_asset_relink` 与 `release_asset_relink` 明确幂等：不存在的本次任务是正常取消/未释放，不能误伤另一批次；原媒体任务接口的语义保持原样。图片恢复在独立 ID 子目录中保留旧文件名，避免孤立素材变成内部暂存名称。

单次任务数沿用工程素材上限 `MAX_LAYERS * 2`，仅保留一个批次。准备串行复用现有有界音视频 worker，不新建解码器池、自动重试、超时或重启。源文件累计字节使用既有 `MAX_PACKAGE` 上限；缓存沿用各类型的已有生成和解码限制。

## 观察与失败边界

| ID | 分类 | 证据与边界 |
|---|---|---|
| R01 | 新增观察 | 批次准备/提交在进入会话处理前记录 Info，含 request、revision、数量和阶段；每份源的 ID/类型为 Debug 上下文。实际失败记录 Error 与原始原因，路径上下文限制 1024 字符，准备错误保留最多 8192 字符。终态轮询不重复报告准备错误。 |
| R02 | 既有观察 | 桌面 Media 指令继续使用原有串行 worker 的 Info start 和 in-flight；音视频 provider/decode/join 使用既有任务观察，不把完成日志代替开始信号。没有新增 Present 热路径日志。 |
| R03 | 正常分支 | 过期 revision、document generation、用户取消和缺失文件清单中的正常 NotFound 不计作故障；准备候选无法读取或解码是真实故障。 |
| R04 | 新增观察 | 暂存/发布目录均独占创建，清理前验证实际绝对路径仍位于记录的直接父目录；清理失败单独 Error，保留 request、阶段与主要失败。会话内的记录先有界暂存，释放业务锁后才调用日志 sink；单次会话最多保留 16 条、每条 8192 字符，溢出计数饱和并在结束时报告后复位。没有共享目录删除或缓存覆盖。 |
| R05 | 协议边界 | 草稿只提供准备能力；只有整组资源预检成功才修改真实模型和渲染目录。失败后需释放任务并重新选择，不隐式重试。 |
| R06 | 新增交互验证及限制 | 使用真实 `TestWait` gate 阻塞 worker，分别将准备、状态和提交排在其后，证明 UI 可以继续轮询并提交取消；在 gate 释放前不等待后台结果，提交先完成则保留实际成功。没有声称单独注入图片文件系统永久阻塞、清理 IO 错误或改变 worker join 期限。默认错误子进程覆盖新增准备错误的文件日志、Error stderr、stdout 隔离、终态抑制和正常失效静默。 |

## 验证

原始记录位于 `artifacts/pr-ci-followups/media-assets-relink-*`。首轮无 `EditSink` 重导出、闭包签名不匹配及错误使用 `--lib` 的编译失败保留。宿主验证曾误传只属于桌面包的 `ffmpeg` feature，保留失败记录，随后按宿主真实 feature 运行。原生前三轮在批量恢复完成后截取项目行时失败；现场 PNG/JSON 证明元数据正常、查询为空，但“显示使用处”在 Project 下方停靠了 Timeline，900×600 下项目概览占满了剩余高度。仅切回 Project 不能增加空间。最终截图通过既有面板最大化展示菜单，没有改布局规则或放宽恢复断言。该矮面板概览挤占列表是保留的既有界面限制，后续 UI 整改需处理，本轮不宣称修复。

同步 main `af1e7f9f` 后，以源码 `071e8de3` 完成专项 20 项通过、1 项原生专项默认忽略；随后显式执行原生 GPU 专项，1 项通过并生成 17 张截图。宿主目录所有权专项 1 项通过。已通过的专项覆盖多份源同时丢失、真实 PNG 像素、真实 WAV 和 FFmpeg 音视频、关联音轨身份、暖缓存、保存重开、有效旧源下的单步撤销/重做、准备失败、取消、过期、整组预检失败回滚和已有缓存冲突保护。

此前面板全量回归 559 项通过、2 项专项默认忽略，记录保留为其实际阶段，不声称是最后异步改动和 main 同步后的全量结果。最终源码重新通过相关 Shell/面板素材测试和原生事务验证。主题消费静态检查、`git diff --check` 与带 FFmpeg 的桌面构建通过；没有将既有编译 warning 当成零 warning 验收。原生截图子进程仍记录本机 Epic Vulkan overlay JSON 缺失的加载器日志，保留原始 stderr，不作静默过滤。

## 未完成验收

原生文件选择器的实际 OS 操作、跨平台文件位置、前台键盘/IME 仍需人工验收。字体保留既有字符串身份，不属于数字媒体重链接。此流程用于已打开工程的媒体恢复，未将严格的工程打开/存储校验改为忽略缺失资源。

文件选择前的缺失清单仍是一次同步元数据查询，原生对话框沿用既有模态行为；本轮异步改动覆盖准备/解码、状态、提交和取消，不宣称消除所有慢盘及系统对话框阻塞。

DESIGN §0.7 的 12 项均 retained with reason，沿用共享菜单阶段逐项处置：本轮只增加既有 context 行，不修改 Path、Effect 或 Timeline 的已知整改项。§12 的本轮自动化范围为中英文、默认/最小窗口、三种比例、主窗/原生浮窗菜单、输入所有权、实际渲染器配置和保存重开；没有以编译通过替代全部人工验收。#222 保持开放。
