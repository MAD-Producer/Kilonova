# 遮罩提取 uniform 合并上传

接续 #590，基线 `07718094e1e7c0b4cb08d0d25c74f5f214dbec9e`，推进 #126。
实施前核对开放 PR 与最近分支；跟踪与预渲染工作没有改动。

## 行为与资源

旧实现为每个 alpha／luma 提取项分别保留上传目标并调用 queue.write_buffer。
现在在既有 DFS 规划之后，复用 CPU 字节存储，按原动态偏移打包本次需要的
uniform，一次上传最低至最高占用槽位的跨度；空需求不上传。

不新增 GPU buffer，不改变 uniform 内容、动态偏移、提取顺序、纹理、绑定、
预算和附件操作。一个来源的两种提取模式沿用同一 uniform 槽位。
仍先取得上传目的地 reservation，由原提交／放弃生命周期保护其容量。
测试构建的旧上传路径和上传次数计数不进入产品。

CPU 存储随当前最大需求保留容量，由 MAX_LAYERS 和设备原有 stride 限制；
clear_assets 释放。跨度内未使用槽位和 padding 不会被任何提取 draw 读取，
但可能使稀疏需求传输的字节多于原来的分散有效 payload。本改动以减少上传
调用及分配为目标，不宣称降低传输带宽；GPU 目的 buffer 的大小保持原值。

## 验证与边界

旧代码实际运行新断言失败：32 层场景 28 个提取项发生 28 次上传，要求为1。
首轮 fixture 的颜色超出模型合法范围，在到达目标断言前失败；修正为合法
RGBA 后重跑，保留两次原始失败，没有改模型限制和目标断言。

- CPU 独立旧 payload 对照：1／8／128 个来源各120次，暖机后零分配；比较
  完整 uniform 字节，另验证稀疏高偏移、乱序、重复双模式、空需求和尺寸变化。
- 实际 GPU：四种通道精度，七种图层数量／场景、三次位置修改、正式与预览
  两种路径，共168个场景。与测试构建保留的逐项上传路径比较完整原生像素、
  draw_calls、纹理字节和资源身份，并验证非空场景确实发生画面变化。
  包含128层、链式四种 matte 模式、同来源双模式、隐藏来源和空场景切换。
- 内部受控非有限投影使打包返回原来的对象／阶段错误，在第一次上传前拒绝；
  旧目标像素与资源台账不变，恢复原投影后可继续上传并得到原完整输出。

错误仍通过既有 Result 进入宿主／引擎错误边界，没有新增日志信道或健康路径
日志。内部投影注入不代表驱动或文件故障，也未重新运行完整桌面日志输出验收。

最终不同测试和退出码、整帧九组各16帧的原始分配测量见
[证据清单](matte-uniform-upload-evidence/manifest.json)。完整预览测量仍包含
采样、准备、命令创建、编码、提交及完成查询，并与新 Renderer 正式输出比像素。
统计只覆盖调用线程成功分配次数，不能推出分配字节、其他线程、外部驱动内存
或 FPS 收益。整帧随层数增长的剩余分配没有消失，#126 保持开放。
