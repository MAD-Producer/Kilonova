# 多视图共享同一帧取样（#221，第三阶段）

接续 `33c68747` 的[独立相机与曝光取样](viewer-multiview-scene.md)。开始前重新核对
开放 PR 和本地分支：#575 仍由另一分支处理原生预渲染，本轮没有改它的工作树或
宿主预渲染路径。#577 继续验证自己的三维变换与几何吸附改动。

## 行为和所有权

`Scene::fork_view` 从成功取样的场景生成独立根视角，不执行 FrameEvaluator、
重读模型来源或重新取样子合成。`fork_views` 只接受 1、2、4 个视角，任何绑定
失败时整批返回错误，不发布部分更新的视图。

- 缓存该帧真正的合成活动相机，与当前被选中的根相机分别保留。从命名或观察
  视角切回合成模式，仍恢复同一时间的合成相机。
- 重用层级解析得到的相机姿态；保留导入相机的原始投影、letterbox 和景深。
  命名相机在子场景中按 authored ID 解析，再映射到该实例的 renderer alias。
- 根视图复制渲染所需的数据，重算 3D 投影和相对相机的深度，并在原有 2D／
  已栅格化覆盖层边界内重新排序。平面图层的投影不变。
- 已求值的工程使用 Arc，共享同一份表达式结果；未经过 evaluator 修改的工程
  继续沿用既有 `sampled_project(original)` 借用约定，不能据此宣称冻结了原工程。
- 子合成改为 Arc；视图共享已完成的子场景，保留各子合成自己的相机和取样时钟。
  下一次取样或 alias 写入使用 copy-on-write，不能覆盖旧视图仍引用的场景。
- 不克隆 root 的 vector/mask 历史缓存、nested spare 或 instance ID 构建缓存。
  已采样的矢量、蒙版、曲线、来源和深度资源沿既有 Arc 所有权共享。
- 最新取样或实例映射失败后禁止再从该场景派生视图，不能把旧相机与半更新的
  图层拼成成功结果。之前已经返回的独立视图仍然有效。

新派生入口拒绝非有限或退化的相机姿态，包括原正交 Observer::pose 可能返回的
非有限结果；旧单视图取样接口的观察器校验行为没有改变。

## 验证

新增 `viewer_frame_views` 8 项，包括 3 项真实 GPU 验证：

1. 带调用次数、每次产生不同坐标的 evaluator 证明 1／2／4 视图只求值一次；
   独立重新取样必须改变几何的负对照证明夹具有判别能力。各视图的已求值工程
   地址相同，原工程严格保持相等。
2. 活动、两个命名、自由、俯视和侧视视角的相机、图层顺序、深度、矩阵、
   source rect、颜色和拾取，与独立取样逐项比较。
3. 两个重复 ID 的子合成实例共享已取样 Arc；本地命名相机仍能正确解析。
   根场景进入下一帧后，保留视图的子场景、时间和矩阵不变；新旧工程快照分离。
4. 未取样、最新取样失败、缺失／非相机／未创建的零号相机、错误视图数量及
   退化正交姿态均被拒绝。批量失败不修改既有视图，随后成功取样可恢复。
5. GPU 前后相机切换翻转红蓝遮挡，拾取命中同一前景；2D 黄色覆盖层的位置
   和像素不变。每个派生视图与独立取样逐像素相等，错误替换相机必须不同。
6. GPU 保留的旧子合成输出在根场景取样新帧、渲染新帧之后完全不变；新帧
   输出必须不同，避免无效动画夹具通过。
7. 模型和 GPU 资源先准备，删除原始来源后才派生导入相机视图；其投影、
   letterbox、原生相机和 GPU 输出与原相机一致，错误替换必须产生不同像素。

既有相机／曝光专项 11、合成 5、多相机子合成 3、曝光场景 8、模型 53、
合成 bundle 边界 6 项全部通过。连同新增专项，核心测试共 94 项。
模型回归此次实际运行整个 53 项程序，而非仅导入相机过滤组，按实际结果记录。
`composition_bundle_boundaries` 只把手写 NestedScene 的 Box 构造改为 Arc，
原深度、字节、实例上限和拒绝断言均保留。

首次新增测试编译错误来自把 FrameEvaluator 从 motion_core 导入，改为它所在的
motion_model。首次执行 7 通过、1 失败：导入模型夹具未准备 renderer 资源，
原始错误为 `model object=1 source=7 not configured`。补齐既有资源准备步骤，
继续在派生前移除来源，并增加必须渲染可见几何的断言；没有放宽产品错误或断言。
初次编译与执行失败日志、最终日志和取样 PNG 全部留存。

最终源码的桌面测试程序与带 FFmpeg/GPU 的 dev 应用均编译成功，分别保留 26／36
条 app 告警；未通过 allow 隐藏未接入多视图 API 或既有告警。精确模块过滤下，
视图状态 7、Workspace 7、导航 3、合成面板 5，共 22 项通过；加上核心 94 项，
本阶段共 116 项。此前阶段的较宽 Workspace 过滤计数不并入本轮。

状态专项的独立子进程在默认 Info 下再次运行两轮各 61 次非法 Workspace 加载，
每轮第 60 次 Error 同时出现在文件与 stderr，之后抑制，中间成功加载重置阈值；
stdout 没有 workspace 故障日志，非法文件保持原始字节。原始信道输出与最终
测试程序／应用摘要见[证据清单](viewer-multiview-frame-evidence/manifest.json)。
这验证既有 Workspace 信道，不代表尚未接入宿主的新 fork 入口已经完成日志验收。
本阶段未启动 UI 窗口。

## 错误信道和交付边界

| ID | 分类 | 处置与证据边界 |
|---|---|---|
| MV-FRAME-01 | 新功能错误 | 未就绪、错误相机、退化姿态和图层次序损坏返回原错误，带合成、帧、阶段和可用对象 ID；不改失败为成功，不加重试。专项验证拒绝及恢复。 |
| MV-FRAME-02 | 既有失败传播 | 取样与实例映射失败只额外撤销派生资格，保留原始失败。相机、曝光、合成和 bundle 拒绝回归验证现有协议。 |
| MV-FRAME-03 | 正常分支 | 视图的根相机不同、共享子合成保持自身相机、借用未修改工程均为正常行为，不增加计数或逐帧日志。 |
| MV-FRAME-04 | 尚未接入 | 新派生入口尚未进入桌面 worker，因此不能把库的 Err 测试计作默认日志文件／Error stderr／stdout 隔离的端到端验收。未来接入须使用现有请求开始、in-flight、完成耗时和错误信道。 |
| MV-FRAME-05 | 阻塞与热路径 | 没有增加线程、等待、来源 IO 或日志站点。成功派生只在内存中准备视图；不声称已测原生批量呈现的耗时或预算。 |
