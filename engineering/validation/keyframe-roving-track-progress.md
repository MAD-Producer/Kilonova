# Roving 轨道与核心命令接入

这是 #260 的轨道接入阶段，不是 issue 完成证明。基线为
`2a92fb6a43050211de794a5e2d64e0887112c3c0`。没有新依赖、第三方资产或像素合成语义改动。

## 实际变化

- `Track` 以互斥的 `spatial_animation` 保存稳定键 ID、作者参考顺序、固定时间／Roving 约束、
  值和空间控制点。它不再同时保留一组可被误改的整数帧关键帧。预计算快照不序列化，
  保存重开时有界重建；历史快照通过 `Arc` 共享不可变预计算结果。
- `Track::sample` 使用连续时间求值；`key_frames` 返回真实 `f64` 时间。表达式键时间查询
  和运动路径采样保留小数，未将结果四舍五入回整数键。层偏移只在合成与局部时间之间转换。
- 普通参数化与弧长参数化逐区间保存。导入手动曲线、Hold 和缓动时维持原来的 `f32`
  插值算术；启用 Roving 只改变其相邻固定锚点之间的线性距离时间。关闭后保留弧长策略，
  不切回原始整数时间或原始曲线参数而产生跳变。无关区间继续使用其原有缓动与空间几何。
- `spatial_keyframes` 核心命令可从整数合成帧选区首次启用，然后按稳定 ID 固定化、修改
  连续合成时间或删除键。命令注册、合成事务、历史记账及 worker 入口均已连接。
  `Time` 明确解除所选键的 Roving 约束；仍拒绝越过其他固定键的重排。
- 数值属性在播放头处修改时保留已命中键的 ID；新时刻插入固定键。多个零长度键处于
  同一有效时间时，播放头编辑返回明确的身份歧义错误，要求调用者选择具体 ID。
- 时间轴状态通过独立的 `spatial_keys` 返回 ID、连续时间、Roving 状态及区间策略。
  既有整数 `keys` 的 JSON 形状保持原样，禁止把连续键塞进整数协议后让旧 UI 猜测身份。

距离单位是所保存属性的坐标单位，不宣称是摄像机投影或父级缩放后的世界速度。锚点
仍按模型的归一化坐标计量；面板未来若以像素声明速度，必须先提供所属图层的度量转换。

## 功能边界与错误处理

| ID | 处置 | 分类与剩余边界 |
| --- | --- | --- |
| RT-01 | 新的模型与命令校验 | 拒绝双重权威存储、无效 ID、非有限／越界时间、首尾漂移、重复选择、不可表示的移动区间，以及数值／控制点越界；保留原始 `source` |
| RT-02 | 新的真实取样 | 普通区间保持原参数化；仅 Roving span 使用有界弧长查询，固定化持久保留该策略 |
| RT-03 | 核心事务接入 | 命令候选先完成解算及校验再安装，失败不改变工程、revision、历史或 redo；冻结快照独立于后续编辑 |
| RT-04 | 既有错误信道 | 复用 `EditorAction` 的 Info start、worker in-flight、Error 文件与 stderr；新增 `operation/object/channel/phase/key` 错误上下文，不新增热路径日志或重试 |
| RT-05 | 正常分支 | 禁用动画是一次显式取样并转换为静态；普通轨道、空查询、既有未启用 Roving 的工程不产生新错误日志 |
| RT-06 | 显式功能边界 | 按整数帧移动／复制／插值编辑、预设重定时、整数烘焙的摄影机模式转换和锚点全轨补偿拒绝连续键，不悄悄丢弃它们 |
| RT-07 | 待实现 | 手动非线性时间与 Roving 同一 span 的组合、自动贝塞尔组合、跨固定键重排、稳定 ID 剪贴板、预设连续时间重映射 |
| RT-08 | 待实现／验收 | 桌面选区、拖动、曲线、右键菜单与快捷键的稳定 ID 接入；主窗／浮窗、双语言、DPI、OS 输入与真实 Roving 编码输出，以及跨平台 CI |
| RT-09 | 新的载入失败诊断 | Track 与锚点按实际 JSON 形态直接解码，保留空间身份、解算与资源上限的原始拒绝原因；拒绝重复字段和混合存储，未知字段消息不复制用户字段名或载荷 |
| RT-10 | 待验收的内存边界 | 单份预计算几何有节点／键数量上限，未改动现有“只按模型 JSON 计量”的历史预算；Arc 共享不等于修改几何后各份历史缓存的总堆内存已受该预算约束，开放产品入口前须补跨历史缓存计量或回收策略及负对照 |

RT-06 是对新存储类型的功能拒绝边界，不是观察日志，也不是“已支持该操作”。
RT-04 的本轮验证针对真实 worker 的成功与实际拒绝输出；没有以纯模型测试代替 worker，
没有把 start 字符串断言说成受控阻塞测试。既有 worker 发布 in-flight 的机制未改动。

## 验证与证据

最终冻结源码通过模型／核心 188 项、真实桌面 worker 6 项及既有菜单／时间轴／插件面板
80 项，共 274 项不同测试；两个原生截图测试保留原有 ignore，本轮没有 UI 视觉改动。
带 FFmpeg 的桌面测试程序编译成功；它不是供用户启动的发行程序。源码 SHA-256、实际
命令输出和测试明细保存在 evidence 目录。RT-09 的完整工程解码负对照在模型／核心层
验证，未把它宣称为“损坏工程通过桌面载入 worker”的专门验收。

验证结果与原始输出见同名 evidence 目录的 `manifest.json`。首次构建的借用生命周期
错误已在实现中修复，原始输出保留在会话，未另存文件；其后首次模型／轨道／核心测试输出按阶段保留。没有删除产品失败
日志，也没有为通过测试修改既有断言。`spatial_schedule` 原先拒绝所有手动非线性导入，
本轮扩展为精确保留手动取样，因此对应测试改为逐时刻与原轨道比较；对受 Roving
影响的非线性区间，另有原子拒绝测试。它不是放宽“任意结果都通过”的断言。

载入错误诊断补全期间终止了一次基于旧源码的桌面构建，保留退出 `0xffffffff` 的原始
记录，该次不计作验证。一次复测复用了先前的可选输出目录，工程包导入按设计返回
`import destination already exists`；保留失败日志，后续使用新目录，不删除目标、不添加
重试，也不修改该保护或断言。指定 `MOTION_SPATIAL_TRACK_ARTIFACTS` 时应使用新目录。

桌面错误信道测试首轮在系统临时目录创建阶段返回 Windows `PermissionDenied`，六项
均未进入 worker；保留 `desktop-worker.log`。重新运行时为测试进程设置构建使用的
`TEMP`／`TMP` 工作区目录，六项全部通过；没有修改临时目录实现、断言或产品重试策略。

新测试覆盖：完整 Project JSON 的合法重开和损坏负对照；真实 `storage::save/load` 与
`.msproj` 导出导入；101 个真实 Scene 世界矩阵与独立匀速位置对照；原始整数时间轨道
必须产生不同矩阵的负对照；历史与失败原子性；默认日志信道；预计算与重开 Track 的
10,000 次无分配查询，并保留真实 Vec 分配的计数器正对照。

Scene 证据是场景矩阵，不是 GPU 像素、屏幕截图或 MP4。本轮没有重新宣称此前自动
类型的 MP4 是 Roving 证据。没有开放桌面菜单；不据此关闭 #260 或提交可合并状态。
