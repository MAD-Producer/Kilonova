## 实现与输入边界

节点拖动丢失左键 held 时，原处理顺序先为移动后的文档建立卡片，再恢复历史文档并因节点源身份变化重建。现在仅将这种取消提前到最终卡片构建前，复用原拖动更新函数：仍先应用最新指针位置，再恢复历史，并保持原来的修订计数。已消费的输入不会再进入画布处理，因此同一事件的滚轮继续被抑制。

新按键、保持左键、显式左键释放仍走原输入顺序；小地图捕获继续优先，其他拖动类型不提前结算。正常释放、提交历史、恢复文档及端口身份校验没有删除。没有把旧文档卡片用于恢复后的文档，也没有改动样式、命中范围或图事务。

## 实际验证

- 中英文、两种面板尺寸、两种缩放、单选／多选、已有／尚无位移、held 丢失／变为右键，覆盖 **64 组事务、320 帧**。无先前位移时，最新指针仍按原顺序先写入再恢复，修订恰好增加一次；文档、语义／预览修订、选中状态、滚轮抑制及空历史栈均有独立断言。
- 同一新增夹具先运行原生产代码：完整功能和独立新鲜几何断言成功后，最终计数断言真实 exit 101；64 个恢复帧均构建两次、解析 2*N 份卡片端口规格。优化后 320 帧均单次构建、解析 N 份规格。
- 原路径与候选、最终路径的 320 帧 shapes/colors/glyphs/order、响应、EditorSnapshot、选择、视口、通知／诊断和完整活动拖动状态精确一致，没有归一化。根图事务的 undo／redo 都为空，记录长度并逐步断言为空，不宣称覆盖非空父图历史。
- 在修改原计数断言前，候选生产代码运行旧测试，实际以 `left: 1 / right: 2` 失败；上述完整对照已经通过。随后将“恢复需两次构建”收紧为“一次”，保留其工程恢复、历史和新鲜几何断言。原生产、候选和最终编译输入分别留档，不能把断言调整本身当作性能证据。
- 旧视口 312、画布外输入 64、折叠 216、数值事务 744、连线／预览 448 帧再次精确相同，合计 **2,104 帧 CPU 绘制及状态对照**。

## 错误与设计处置

| 条目 | 处置及证据 |
| --- | --- |
| NR-BUILD | 功能优化：取消时先恢复再建立最终几何，64 个恢复帧从两次整图卡片构建减为一次。 |
| NR-INPUT | 功能保持：新按键、显式释放、持续拖动与其他拖动类型不提前结算；取消事件保持滚轮抑制、最新指针处理及原修订语义。 |
| NR-ERROR | 既有覆盖：实际卡片规格继续走 `observed("canvas.sockets", ...)`，没有清除错误、吞 panic、改返回语义、增加重试或期限。减少废弃文档的重复规格解析会减少重复观察，不承诺观察次数不变。 |
| NR-NORMAL | 正常取消不是故障，不新增日志或每帧 IO；恢复仍走原 `restore_node_drag`。 |
| NR-FIXTURE | 前两次新增夹具在“未移动应保持文档相同”的严格断言失败：非精确浮点往返使位置微变。保留源码和原始输出，改用精确缩放与 8 个世界单位的标题偏移；严格不变性断言未放宽。这两次失败不是产品缺陷或性能负对照。 |
