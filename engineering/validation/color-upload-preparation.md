# Float32 色彩素材上传与按需读回

关联 #83、#126，接续 #650。这里交付的是实际 GPU 资源入口；普通 Session 的 managed 素材解码、合成和显示/输出接线仍未完成，不能关闭上述 issue。

## 实际行为

`Renderer::upload_color_image_f32` 接受明确 `ColorImageContract` 和连续二维 Float32 RGBA。它保留负值、超一高光、零透明度下的 RGB、透明度和各通道位模式，不执行传递函数、色彩转换、预乘或 8 位量化。颜色变换由已有、明确阶段的 `ColorProcessorOutput` 单独执行。调用方负责提供正确的空间身份；上传不能证明像素来自该空间。

精度、像素数量及有限值/alpha 范围先验证，失败不分配新资源或写入队列。typed `ColorImageUploadError` 同时保留在 `RenderError` 变体和 source 链，包含像素/通道或尺寸，不记录整图内容。上传使用原有准入和 pending-upload 保留机制：销毁返回的纹理包装不会提前释放尚未提交的上传预算，完成提交才回收。此接口需 renderer 独占借用，用于资源准备，不是逐帧上传方案。

`color_image_target` 现在只保留纹理。显式 `read_color_image_target` 才创建有预算准入的临时对齐缓冲，读完解除映射并释放；预算不足返回原有资源拒绝，不隐式降精度。普通 `image_capture_target` 保持预分配、可重复使用读回缓冲的契约。

实际测试用 17×2 Float32 纹理验证：纹理需要 544 字节，过去还会保留 1024 字节对齐读回缓冲；现在只给 544 字节可用预算也能创建色彩目标。显式读回仍需临时的 1024 字节。该数字是应用准入的逻辑容量，不是驱动显存或性能帧率测量。

## 错误与观察审计

| ID | 分类 | 实现与证据 |
|---|---|---|
| CUP-01 错误精度/数量/像素 | 新功能拒绝 | 真实上传入口产生 typed Err；检查原始类型、像素通道和随后正常上传；所有输入校验发生在分配前 |
| CUP-02 读回预算/容量 | 新触发点，复用拒绝 | GPU-only 创建不受未分配 staging 的设备 buffer 上限约束；显式读回重新核对上限和预算，失败不提交、不泄漏，原有 requested/failed/in-flight 计数保持 |

| CUP-04 原生 GPU 故障 | 复用 | 原有设备健康检查、错误回调和变换管线错误保持；并验原有无写入/恢复/原生 shader 失败测试 |

| CUP-06 健康变换 | 无新增观察热路径 | encode 不新增分配、IO、读回或日志；测试检查原有读回计数保持，GPU 输出另与独立 OCIO CPU 参考核对 |

## 验收

目录 `artifacts/issue-goal-current/color-upload-preparation/` 保留各次命令、完整源码前后哈希、原始 stdout/stderr 和退出码。

- 首轮新增测试因持有 renderer 的借用后再申请可变上传而编译失败；改为复制已有共享预算句柄，断言保持。原始记录 `first-upload` 保留。
- 新上传路径覆盖三份固定配置、20 个原生 OCIO CPU 色卡，含三个阶段与 alpha 组合。逐位检查上传原值；实际变换仍使用既有参考数值和容差。
- 现有 14 组两阶段参考、空间拒绝和资源生命周期断言保持；GPU-only 创建、读回拒绝/恢复、既有显式 capture、未提交上传保留分别验收。
- 冻结源码后，Vulkan、DX12 各通过 9 项图片变换测试；后者是同组断言的另一后端复验，不重复计入不同测试数量。图像 capture/output/formats 通过 19 项，布局容量 2 项，原生色彩错误 2 项，合计 32 项不同测试。带 FFmpeg 的 renderer/host/desktop 全目标检查通过；格式检查覆盖本轮 managed 接口和新增上传测试文件，未宣称全仓格式已统一。
- 三个生产代码负对照均运行到实际断言失败（exit 101）：恢复预分配 staging 会在只有纹理预算时拒绝创建；删除 pending-upload 登记会在目标 drop 后提前归还 192 字节；上传先按 8 位步长量化会破坏源像素的逐位断言。断言文件保持不变，生产源码逐字节恢复；恢复后的图片测试另行复验并收录在 `restored-after-negatives`。

DX12 原始访问冲突仍未定位。`color-dx12-isolation/quiet-native` 去掉八处诊断输出、保持断言后，5 项测试通过；它是时序对照，不是原失败二进制的重现，也不是崩溃已修复的证据。测试源码随后逐字节恢复。

没有改 UI，DESIGN.md §0.7 的每项均保持原状：本轮只涉及 GPU 资源与上传，不作视觉验收完成声明。没有新增依赖或第三方素材；现有 OCIO 配置、shader、数值表和参考文件字节保持。
