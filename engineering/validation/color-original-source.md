## 实际改动与审计处置

| ID | 类别 | 行为、证据与限制 |
|---|---|---|
| SRC-01 | 新增功能 | `image_resources::decode_color_f32` 从原始文件读 PNG/JPEG，直接返回归一化 Float32 RGBA；不读写 RGBA8 代理，不缩放，不提前执行 sRGB 或预乘。 |
| SRC-02 | 新增功能 | PNG 保留 8/16 位样本，展开灰度、调色板和透明度，逐行处理 Adam7；透明像素的未关联 RGB 保留。JPEG 明确使用实际 8 位解码结果；不声称其增加位深。 |
| SRC-03 | 资源边界 | 解码前准入 Float32 输出容量；PNG codec 另限 16 MiB，JPEG 还准入与输出共存的解码图。不是进程总内存或 VRAM 测量。原路径、尺寸、编码文件容量检查继续使用现有 Source。 |
| SRC-04 | 新增功能 | `PreparedProjectColors::prepare_source_image` 按真实工程素材 ID 路由，核对配置未过期，解码后上传 Float32，再执行已准备的 InputToWorking，成功后返回可复用的工作纹理。 |
| SRC-05 | 正常分支 | 显式 Data 路由返回 None，不打开其文件、不做颜色变换或 GPU 分配；它不是数值贴图导入器。取消保留 typed Cancelled，记 Debug，不记 Error。 |
| SRC-06 | 功能边界 | 未知 ID、视频、过期配置明确拒绝，不套用默认输入。输入空间及 alpha 由工程声明，不从 PNG 扩展名、gAMA 或 JPEG 文件名推测。APNG 明确拒绝此静态入口。 |
| GPU-01 | 新增功能 | 源、变换表和工作纹理使用既有准入与 ledger；不在生产准备路径读回 CPU。调用方可复用工作纹理接显示/输出处理器。 |
| GPU-02 | 既有边界 | 取消检查到第一次队列写入前；之后完成一次提交。GPU 准备失败时，已有排队上传仍依原规则保留到后续提交完成，不提前释放、不添加自动重试或提交。没有发布部分工作纹理，但这不等于回滚队列状态。 |
| OBS-01 | 新增观察 | 非 Present 的源准备在进入路径解析、解码、上传、原生管线构建及提交前写 Info。Observation 在调用前设为在途，可不持会话锁独立读取；包含 request、operation、asset、phase、耗时及有界原因。 |
| OBS-02 | 新增观察 | IO、PNG 原生错误及预算拒绝按 typed source 保留。默认桌面 logger 的实际文件与 stderr 同时含 Error；Info 仅入文件，stdout 保持隔离。 |
| OBS-03 | 新增观察 | 受控阻塞真实解码前检查在途状态；阻塞期间取消后进入真实解码并得到 Cancelled。panic 保留原 payload，Flight 清除状态并记录 abandoned；没有吞掉 panic 或引入产品超时。 |
| OBS-04 | 既有覆盖 | 原 CPU 准备的有界原因、数量/有效载荷上限、默认 panic hook、强制回溯与 stderr 验收继续通过。新 Flight 仅增加 operation 字段，原记录格式保留。 |

## 验证与负对照

最终源码共通过 **39 项不同 Rust 测试**：

- 原始解码 5：8/16 位 RGB/RGBA/灰度/透明度，显式 gAMA 下原始样本不变；独立生成且由 image 解码器交叉核对的大小/奇数尺寸 Adam7；2 位调色板透明度；预算、取消、终端 IEND CRC、文件删除与恢复；真实 JPEG 样本及共存容量。
- 原 RGBA8 图片资源 10：代理、缓存、原始采样和需求收集回归；另有 1 项需外部素材的原有手动测试保持 ignored，不计通过。
- 宿主准备单元 3：受控阻塞/取消/panic/恢复，原有原因容量与程序容量。
- 宿主准备集成 7：原 CPU 准备 5 加真实文件链、源路由/故障恢复 2。Vulkan 与 DX12 各通过 7，重复不累加。
- 原图片处理器 12：20 组单阶段、14 组既有双阶段 CPU 参考、原生 Scene 交接、空间身份、上传及预算生命周期回归。
- 默认桌面日志 2：原准备错误/panic 与新增真实源错误。未设置 MOTION_LOG 的子进程使用生产 logger，实际检查 Error 双通道、Info 隔离、原始 CRC/预算原因及正常取消/数据/恢复。

新增 `source_reference.json` 由固定外部 OCIO 2.6.0 与原三份配置生成，14 组
**原始 16 位 PNG → 工作空间 → 显示/输出**参考。输入含相邻整数码、不同 alpha、
零 alpha RGB 及非对称行列。工作纹理和端点分别与 CPU 比较，沿用绝对 `0.0001`、
相对 `0.0002` 容差。检查准备及重复端点绘制均无中间读回，输出仍为 Float32，
工作纹理不预留读回缓冲，GPU 完成后容量回到基线，工程未修改。

参考可独立逐字节重建，SHA-256 为
`73987f05e8159a1eae5ebd535b7122e96ef6417b97bf00e51b3841921627556e`。
原 `reference.json` 与 `chain_reference.json` 及其容差保持不变；新派生参考的
运行时、来源、版本、许可和改动范围补入 ATTRIBUTION.md。

四个生产代码负对照分别：启用 STRIP_16、漏掉输入变换绘制、移除过期配置检查、
把 Data 当默认颜色。均编译成功并触发真实断言（不是仅检查故障返回码）。
每轮只改一个生产文件，测试逐字节不变；随后逐字节恢复生产文件，再执行上述最终验证。

带 FFmpeg 的桌面全目标检查及本轮修改/新增 Rust 模块格式检查通过。既有 unused/dead-code
警告留在原始输出，没有顺带修改其他分支负责的 UI。
