# 有界 Cube LUT 与原生浮点转换

关联 #83，不使用关闭关键字。开始前逐一检查其他工作树相对 merge-base 的独有
提交和未提交源改动：UI、深度会话、跟踪、多视图分支未占用本批 LUT 实现；
共享 renderer/lib 仅增加本功能的错误类型、资源原因查询和模块导出。

## 实现范围

独立实现有界单 1D/3D Cube 导入、保真导出、显式域/用途/插值、内容语义摘要和
CPU 映射。最近邻等距取较大索引；线性为 1D 线性或 3D 三线性；四面体仅限3D。
负值及高亮保留，预乘先反关联后按目标声明关联。原生 WGSL 使用 textureLoad，
不依赖 Float32 硬件过滤、不缩放、不经过 8 位或隐式显示变换。

GPU 构造检查色彩意义、浮点精度、表大小、设备绑定容量和半精度有限范围，
再经现有 AllocationBuffer 准入分配不可变样本/域缓冲区。encode 在写入前
拒绝设备、编码器、目标声明、尺寸及别名错误。重复帧不创建新管线/缓冲区；
编码器按既有准入协议保留尚未完成的资源。没有修改原有合成、蒙版或显示算法。

## 数值参考来源

官方 OCIO 2.6.0 Windows wheel 已与官方 PyPI 摘要比较；实际安装的原生模块和
LICENSE 逐字节等于 wheel 对应成员，身份收据保留于本批 artifacts。作者、来源、
固定版本、校验值、许可和改动范围已记录于 ATTRIBUTION/PROVENANCE/NOTICE。
不分发参考运行时、上游 LUT 或商业产品素材，不新增产品依赖。

十组每组十二像素中，六组线性/四面体来自实际 OCIO CPU FileTransform。
四组最近邻使用独立的物理网格距离穷举，明确标记参考路径，保留实际 OCIO 原值。
初次 CPU 对照发现 OCIO 2.6.0 对本批文件的 NEAREST 提示仍输出线性结果；
进一步用 3D 表及关闭优化处理器复核也如此，不能将它冒称为最近邻参考。
原始两次 CPU 失败、生成器副本、原始 JSON 均保留。没有更改生产插值语义、
放宽 Float32 1e-5 容差或删减像素断言来绕过差异。

## 故障和观察账本

| 编号 | 处置、证据和限制 |
|---|---|
| LUT-CPU | 非法尺寸、域、样本、指令及超限文本返回结构化原因；非有限像素和非法 alpha 在整数组写入前拒绝，随后显式健康调用可用 |
| LUT-NATIVE | 新 NativeLutError 保留原生 wgpu 错误、关联错误及 poll 错误；若同时存在准入失败，仍保留该主错误及资源拒绝查询 |
| LUT-ADMISSION | 使用既有预算错误、无新增计数器；真实额度不足拒绝并回收已取得的 uniform，不改变目标像素，显式健康调用恢复 |
| LUT-IDENTITY | 原生设备/编码器/图像声明/尺寸/别名预检，拒绝后旧目标保持；用途、插值、域及样本改变摘要 |
| LUT-LIFETIME | 既有编码器保留语义的新增实际 GPU 验证，不是新资源退休策略 |
| LUT-PIXEL | GPU 输入由生产者满足有限色彩和有效透明度契约，不声称 GPU 会像 CPU 一样预检全部纹理或逐帧读回 |
| LUT-LOG | 无新增 handler、worker 或日志站点；本层返回 typed Err，宿主接线后沿既有信道报告。没有声称已完成新的桌面默认日志端到端验收 |
| LUT-PENDING | OCIO 配置/角色/ACES、工程接线、显示和输出资格及移动端实机仍未完成，整个 #83 保持打开 |

原生首轮新测试误用两个枚举写法导致编译失败，已按真实 ImageMeaning/DataChannels
修正新输入夹具；随后实际 WGSL 编译发现 meta 为保留字，修正生产字段命名。
失败命令和完整输出均保留。原生创建用例另外主动传入非法 WGSL，验证错误类型、
原生对象身份、预算恢复以及同一 renderer 后续健康创建，不清除设备错误状态。

DX12 进一步发现 FXC 拒绝动态数组/向量分量左值，四项用例均在真实管线编译失败。
生产 WGSL 改为显式六个四面体顶点分支、固定 RGB 读取及八角三线性组合，不更换
后端、不忽略 FXC、不中途回退其他插值。原有数值断言及容差保持，随后四项 DX12
用例通过。原失败和原始原生 Internal/FXC 信息保留；最终 shader 另跑四组负对照，
不能把修正前的负对照当作最终 shader 的验收。
