## 缺陷与功能修复

用户可见任务记录与线程存活时间不是同一件事。原来的音频导入/缓存、视频导入和工程打包均丢弃 spawn 返回的 JoinHandle；取消后释放任务记录也不能证明工作线程、源文件或暂存目录已经销毁。三个 registry 的 Drop 原来只通知取消。

现在每个 registry 独立保留线程句柄和既有的有界 TaskLog，不依赖已删除的任务 ID。原有取消/释放协议、提交决策、进程级并行预算及第三方解码行为保持原样。每个 registry 最多保留 64 个句柄，包括已取消/释放的任务；新任务在取得任务锁之前回收已完成线程，避免完成任务不断积累。句柄准入和 OS spawn 失败沿原来的任务失败路径返回，不发布悬空运行态。

析构先通知所有当前任务取消，释放 task/registry 守卫并输出既有的中毒观察，再逐个 join。已移除的任务也仍可被 join。回收已完成线程同样先取出句柄、释放句柄表锁，再等待线程真正退出；不在锁内假定 is_finished 意味着 join 绝不会等待。没有清除中毒，也没有捕获后伪造成功、重复任务、重启线程或延长生产等待期限。

关闭状态位使显式 shutdown 与字段后续 Drop 幂等，并拒绝关闭后的新工作；这同时避免中毒句柄表在两次析构入口重复输出 Error。独立子进程使用实际中毒互斥量和实际 logger 计数，验证三次关闭入口只产生一条记录，原中毒保留。这是新观察的实例计数验证，不冒充该私有中毒已由用户输入触达或额外执行了默认文件信道。

这是有行为变化的生命周期修复：Drop 现在会等待这些媒体工作线程完成清理。永久不返回的系统 IO、用户提供的解码回调或原生库仍会使 join 等待；本改动不具有强制中止能力。`DecodeTask`、视频预览 Stream、多 reader 的全局原生并发预算及 MCP stdin 线程不是本批的句柄表，不据此完成整个 #130。

## 原始复现与回归

公开 `worker_shutdown` 用例使用真实 File/Read、真实 AudioJobs/VideoJobs 复制和暂存清理，以及真实 PackageSnapshot 及归档路径；只控制一次读/解码/prepare 的调度。取消后 release 和仅由 Drop 取消均单独验证。音频 cache 使用已有 WAV 的真实解码元数据，回调释放后仍经过原来的解码与取消检查。

原产品代码编译执行六项公开关闭回归，**0 通过、6 失败，exit 101**，每项均明确观察到所属 registry 在阻塞工作尚未结束时提前析构。原有五项最先单独复现后在初步修复上全部通过；增加 cache 场景后，又恢复原六个产品文件编译运行六项反例，finally 逐字节恢复所有修复文件。恢复收据与原始输出保留，不以静态推测替代实际原版本执行。

测试初稿误用了 PackageSnapshot::capture，导致编译失败；随后依照实际接口改为 new，才运行上述真实失败。新增句柄中毒测试初稿因 unwrap_err 额外要求 Worker 实现 Debug 而编译失败，已改成显式区分 Ok/Err，继续断言原中毒没有清除。这两次是本批新测试的编写错误，不是产品失败或通过证据，原日志另行保留。

首轮完整媒体执行还有 **84 通过、1 失败**：既有 `poisoned_registry_drop_still_cancels_a_blocked_source_worker` 把 release 放在同步 Drop 之后，新的 join 必须等待该 release，于是触发原有五秒等待失败。保留该真实失败；仅将同一 release 移入控制线程，观察到原取消信号后释放源，再 join 控制线程。原有中毒断言、取消断言和五秒期限均未修改，没有靠增加等待、忽略或成功返回绕过回收。

新增池级用例实际启动 64 个受控线程，拒绝第 65 个且不执行被拒绝的工作，释放后全部 join；连续运行超过两倍容量并回收，验证不是用总任务数作永久额度；真实未捕获线程 panic 返回原生 Panic，随后仍能执行健康任务；真实句柄表中毒拒绝准入，析构仍回收已有句柄。

桌面子进程使用生产默认 logger、真实 Engine 的音频导入与原生平台回调。阻塞期间发起显式退出，在释放回调之前检查 Flight、文件中的 cleanup/join start 和 worker 未退出；另一个工程仍能完成 open/save/close。释放后线程真正退出、Flight 清除、暂存消失、原工程字节不变，并可在旧 Engine 存活时重新打开工程。

同一默认信道用例让真实视频探测先返回主要错误，再让最终回调捕获析构在 handler 之外 panic。断言 TaskStatus 原因保持不变，两个失败各自经过生产文件与 Error stderr，stdout 没有日志；正常取消的音频任务没有 Error。该真实桌面用例已在加入幂等保护前后分别执行通过，不将重复执行累加；完整组合和默认原始输出另行记录。
