# 效果时间线原生验收协议修复

基线：`4afb6cfc036393d3ec02062ae7a846a26403b1df`，主分支 CI [40198801712](https://github.com/MAD-Producer/Kilonova/actions/runs/40198801712)。

## 原因与责任边界

#499 为关键帧选择加入文档代次，并将 F9 改为带来源标识的 `EditorAction`。原生效果时间线夹具仍缺少 `document_generation`，其本地动作适配器也不支持新动作，因此 F9 被过期选择保护拦住，真实曲线断言失败。验收文件在 #499 前后、#500 前后都是 blob `4bd4bbc5b2da743e840cd551526567950f3b709f`；#500 只有 UI 裁剪分配改动。合并 #500 前未重新验证包含 #499 的完整桌面路径，属于本次集成验证遗漏。

Windows CI 的截图写入故障测试也提前遇到相同 F9 错误，尚未到达预期的 Access denied。Linux 的 missing-style 错误是原有首选项负例，不能当作本次致命原因。Rust/GPU 作业另有表达式执行预算超限，属于独立待验证项，本修复不宣称解决。

## 改动

验收引擎生命周期只拥有一个文档，快照固定文档代次为 1，并继续使用实时 revision。动作适配器比较当前来源后，用真实 `Engine::apply_batch` 执行 `EditorAction`；缺失或过期来源直接返回具体错误且不修改项目。原有 F9 真实曲线、撤销完整还原、写入故障原始原因及最小窗口恢复断言全部保留。未改生产选择保护、快捷键路由或返回语义。

快照与适配器由原生捕获和新增跨平台回归共用。新增测试覆盖中英文 × 主/浮动宿主的真实点击、F9 编辑和撤销；另一测试覆盖 root、composition、文档代次、revision 各自缺失或过期的八个拒绝案例。首次负例夹具未去除项目 composition 回退，被合法接受；记录已保留，修正的是新增夹具，没有放宽既有断言。
