# 普通窗口的受管颜色与整组呈现

本批继续 #83，将已准备的工作颜色、原生显示程序和显示传输接入普通
`Session::attach`、单视图及 1/2/4 视图呈现。#83 仍未完成，PR 保持草稿；
本批不代表完整 OCIO/ACES、全部桌面消费者或全部平台的窗口资格。

窗口必须实际声明支持相应 SDR8 格式、sRGB 色彩空间、不透明合成及请求的
usage；工程必须显式满足既有 sRGB 显示契约。不能从格式名称推断显示传递，
也不能据此推断 OS/ICC、物理监视器或 HDR 链已受管。

冷准备安装原生程序、冻结工作空间图像以及一个可重绑的显示原型。热路径
仅复用程序、表和来源，不读取文件、重新编译或回读像素。每个单元有独立
位置 uniform；整个候选组完成工作合成、显示转换、surface 编码、提交及
健康检查后才发布。候选组失败不会标记为成功，也不会用旧帧冒充新帧。
已有前组留在有界所有者中，不按窗口数创建无界缓存。

配置、源声明和实际使用的来源共同决定是否重新准备。显示程序 key 相同
不足以证明源图像的解释相同；热路径以完整不可变设置所有者的身份作
常数时间核验。冷编辑、工程替换和历史恢复先准备 GPU 候选，再安装模型
和颜色状态。普通桌面 Present 的旧视图清理不再丢弃同一个受管池。
普通单视图也通过宿主组协议携带真实窗口所有者；冻结重绘仅忽略时钟，
不会把旧图像重标为新时间。恢复普通呈现时重新渲染当前时间。
