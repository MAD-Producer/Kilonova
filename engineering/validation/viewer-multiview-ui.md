# #221：独立多视图界面接入

本阶段接通前八阶段的宿主、渲染和 worker 能力。1/2/4 视图使用原生合成面板，
每格拥有独立相机、缩放、平移、导航撤销及检查状态；工程、时钟和对象选择共享。
这不是 UI 库迁移，也没有增加插件、字体、图标或第三方资产。

## 功能与边界

- 底栏使用现有 Dropdown，按当前布局初始化选项。视角仅列出合成、自由、顶、侧及
  工程实际存在的摄影机。删除摄影机后仅对应格回到合成视图，并向用户提示。
- 活动格按按下位置/滚轮命中切换。观察相机手势、缩放和平移不进入工程撤销栈。
  导航历史每格最多 64 项；Escape、焦点/时钟/来源/几何变化取消未提交手势。
- 编辑投影与拾取使用拥有相机数据的请求，回复需匹配工程来源、时钟、窗口和活动格。
  查询最多各一项在途；旧成功回复丢弃，真实旧错误仍保留原始 cause。
- 工具只对具有正确投影的格命中。拖动携带显式视角和来源身份，失效或关闭窗口正常
  取消。工程编辑仍沿原批量命令/撤销处理。
- 每格独立检查通道、ROI、比较快照；延迟快照回复归还原格。
  效果取色读取点击格已完成的显示编码输出，不误读全局 scratch；空间点选只接受
  合成或工程摄影机，观察模式不伪造二维效果坐标。
- 工作区保留布局、活动格、模式、导航和轨道数据。既有停靠/原生浮窗管理继续负责
  面板所有权。没有新增窗口线程或重启策略。
- 默认合成单视图复用原单视图呈现，保留媒体节奏、曝光和 FrameRecorder。
  多格/显式观察模式使用独立组路径；本阶段不声称提供逐格性能采样报表。

## 验证证据

原生用例创建实际窗口、GPU surface、Engine worker 和 Shell，输入经过真实 chrome；
这不是操作系统输入注入。主窗为中文 1600×1000，浮窗为英文 900×600 逻辑尺寸、150% DPI。
截图来自产品绘制流程，包含单/双/四格、独立导航和实际打开的布局下拉框。

验证逐格滚轮、相机 Orbit/撤销/重做、共享选择、空间拖动及工程 undo、取色目标格与
错误格像素不同的见证、完整工程/全局观察状态不变、工作区保存/重新加载。
取色时先激活格 0，再点击格 3，验证请求确实携带格 3 身份；已关闭窗口取消后不能编辑。
宿主查询阶段的真实错误相机负对照、像素阶段的错误比较源负对照仍见先前证据。
不把原型 Views 的单元测试算成产品 UI 手势验证。

完整开发版 --smoke 还执行原面板预设、最大化、浮窗、重停靠、截图、时间轴滚动和
节点工程保存重开流程。具体运行结果、程序/源码 SHA-256 与截图列于本阶段证据清单。
完整程序退出后再次读取保存的工作区，viewer_views 全部字段与原原生验收保存值严格相等，
包括 four 布局、活动格 3、独立缩放与轨道；见 dev-reopen-receipt.json。
跨平台 CI、真实 OS 鼠标注入及显示器扫描输出不在本地证明范围。

## 首次失败与功能修正

1. 首次新菜单编译将输入 Key 和投影 Key 混淆，修正命名引用；保留编译失败输出。
2. 开发版主线程启动栈溢出。将 Shell 的大 Panels 状态放到 Box，未增加栈预算。
   旧阶段保留程序的独立启动探测也发生不同的 worker panic，不能当作旧版通过对照。
3. 首次独立运行使用全局 LOCALAPPDATA 遇到访问拒绝；后续验收使用隔离目录。
   截图父目录缺失导致一次路径错误，随后由验收准备步骤创建，不添加生产重试。
4. 截图夹具修改视口后直接 CaptureUi 被正确拒绝为过期组。验收适配器先显式 Present
   对应组再截图，CaptureUi 的身份校验、超时和错误语义不放宽。
5. 切走合成面板后旧底栏菜单锚点仍可抢占输入。每帧清理锚点，未绘制面板关闭菜单；
   新测试打开真实菜单再切到时间轴，断言旧区域不能发出布局命令。
6. 全套回归发现默认单视图走组路径后缺少 FrameRecorder 记录。保留默认合成单视图
   原路径；不删除/放宽原 GPU 命令身份断言。

7. 首轮广泛桌面运行使用关闭调试符号的构建，音频波形 panic 用例在要求 std 回溯
   符号处失败。未改该断言；该旧程序的广泛运行随后主动终止，保留不完整原始日志，
   不计为整套通过；正常符号构建下原断言已通过，见 viewer-ui-symbols-waveform.log。

这些属于功能/验收协议修正，与新增报错观察分开记录；保留原失败日志，不将重跑累加
为独立通过数量。样式消费者检查只证明 token 使用扫描，不代替原生验收。

## PR 首轮 CI 补验

Rust/GPU job 124501152798 在编译旧 phase_adjustments 集成夹具时因 E0596 失败：
嵌套 Scene 改为 Arc 共享，原故障注入仍直接修改克隆中的子场景。本轮只将该注入改成
Arc::make_mut，保留所有原断言和恢复验证，生产共享语义不变。

修复后实际 GPU 的 phase_adjustments 全部 9 项通过（含失败/恢复）；全工作区排除
已退役 Android 的 all-targets 编译检查通过，启用桌面 FFmpeg 和宿主 diagnostics。
该检查是类型/编译证据，不当作全部测试执行。三个平台与 software Vulkan 仍由当前
PR CI 确认；原失败、检查及运行日志逐字节压缩归档于 ci-shared-scene-fix.zip，
原始文件/程序身份见 ci-shared-scene-fix.json。去重新增 9 项，累计本地 309 项，
不将重跑、编译目标或历史失败计入通过数量。

## PR 第二轮 CI：平移后的采样精度

Rust/GPU job 124503948170 在 software Vulkan 的原逐字节断言处失败：四格相机
与独立画布对照的 cell=3、row=81 出现颜色字节 12/13 差异。保留该断言、原始日志
和相机/画布独立性的负对照，不引入像素容差或只重跑失败任务。

呈现修正：导航与检查路径改用相对视口原点的片元像素中心，再应用局部画布偏移和
倒数尺寸，避免全屏三角形插值随视口平移产生不同舍入。普通 encode/draw 的插值
路径保持不变；仍是两个 32 字节 uniform，既有精确预算/回收断言不变。没有改动
工程、合成或导出的像素语义，也没有新增 UI 样式、生产观察点、日志或重试策略。

新增实际 GPU 图案用例验证四种表面格式 × 五种通道 × 三种画布几何 × 三个原点，
共 180 组逐字节对照；另验证原始上传像素的 identity 和切换通道后的普通呈现。
将本轮新增测试与修改前的三个生产文件组合运行，旧实现实际失败于 origin=(1,3)、
缩小画布的 row=2；恢复修正后通过。负对照没有修改原有断言。

本轮 Vulkan 与 DX12 各执行相同的 **21 项不同用例**：multiview_targets 9、
presentation 8、presenter 4，全部通过。两个后端及 180 组比较不重复累计为新增
测试数。此前 UI/宿主阶段的验证仍按各自记录，不代替本轮 GPU 验证。

新增夹具首次误用了只读固定 64×64 的旧测试辅助函数，导致无效拷贝及 identity
断言失败；已改用既有的动态尺寸、行对齐读回函数。该失败也保留，未修改断言。
本机旧四格夹具在硬件 Vulkan 上本来通过，不能声称本机复现了 CI 的同一像素；
本机新增图案负对照证明的是同类位置依赖。Docker 未运行，Chrome 软件驱动不满足
当前适配器要求，额外 Mesa 下载在已有本机负对照后中止，均不计作软件 Vulkan
通过；CI 的原平台仍须由新提交验证。原始输出与源码/程序哈希见
[本轮证据](viewer-multiview-ui-evidence/ci-pixel-translation.json) 及同名 zip。
