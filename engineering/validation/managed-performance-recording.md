# 受管窗口的性能录制

本批继续 #83，替换受管渲染中 `surface_recording` 的无条件拒绝。此处录制为
预览性能数据，不是视频编码。成功提交并呈现完整受管视图组后，才向既有有界
FrameRecorder 添加记录。旧工程和用户可见面板没有变化。

| 编号 | 分类与处置 | 证据与限制 |
| --- | --- | --- |
| MPR-01 | 功能 | 普通 start_profiling / stop_profiling 可用于受管窗口；记录请求帧、真实呈现序号、CPU 墙钟、获取 surface、提交及 present 调用耗时 |
| MPR-02 | 明确计量端点 | renderWidth/Height 为完整呈现 surface 的物理尺寸，报告 metadata.frameDimensionSource=managed_surface；不借用旧 scratch 的尺寸冒充受管工作纹理 |
| MPR-03 | 计量边界 | cpuPrepareUs 使用与旧路径相同的墙钟减去 acquire / present 调用耗时；包含实际编码与提交时间，不是独占 CPU 内核时间。报告未采集的 GPU 时间和逐帧资源为 null；不填零冒充采样 |
| MPR-04 | 条件提交身份 | presentationCommand 沿已有命令分析器，仅在显式开启详细命令分析且设备具备能力时出现；普通性能录制不自动分配详细命令查询池 |
| MPR-05 | 实际窗口对照 | 单/双/四视图在开启录制前后完整 surface 字节相同；保留帧不重复记录，非法帧不进入绘制或增加计数；容量三条后第四次成功呈现仅增加既有 overflow 计数。工程严格不变 |
| MPR-06 | 两种录制模式 | 同一测试显式开启命令分析，要求提交身份对象与严格递增序号；关闭后再次普通录制，要求提交身份及 GPU 时间为空且像素一致。保留身份断言，未放宽为任意可选返回 |
| MPR-07 | 既有错误信道 | 未新增可失败 IO、回复协议、重试或日志。准备、渲染、提交和报告 IO 错误继续沿既有命令信道传播；本批不宣称重新验证所有默认错误信道。正常保留帧和 GPU 等待不是故障 |
| MPR-08 | CI 与未完成 | 新 Windows 测试位于既有 authored:: 原生门禁筛选范围内。无依赖、资产、面板和样式修改，DESIGN §0.7 各项保留。本批不修复此前原生异常；#83 仍有其他消费者和输出资格，不能关闭 |

首轮新测试遗漏“详细命令分析默认关闭”的前提，严格身份断言失败；第二轮
显式开启分析，但夹具创建 device 时仍未请求时间戳能力，能力断言失败。
修正夹具为显式 profiled device 后，原身份断言通过；其他旧窗口测试仍用
原来未开启分析的 device。没有改写既有断言以通过验收。

第三轮过程句柄已消失且输出含零字节、缺少完整结果，不计作通过，也不能
据此推断中断原因。第四轮链接器报告 LNK1285：生成的 PDB 损坏；保留该文件
及 SHA-256 后重新生成构建产物，未改源码或断言，后续窗口测试通过。

证据位于 `artifacts/issue-goal-current/color-managed-recording/`。本批只使用
常规构建、窗口集成测试和 JSON 报告核对，没有继续此前已停止的特殊诊断路线。
后端资格结果以最终测试输出及分后端保存的报告为准。#83 完成后按用户要求停止。

Vulkan / Dx12 后端名称。各保留详细命令分析和默认模式两份报告，不能将两次
后端调用计作两项不同测试。直接 rustfmt 与 diff 空白检查通过。CI 仍需验证
