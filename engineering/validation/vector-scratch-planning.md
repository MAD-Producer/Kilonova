# 矢量纹理预算与分组目标的集合复用

基于 main `9d085c0f`，接续 #126 的热路径分配工作。开工核对开放 PR 与近期本地分支：#580–#584 属于追踪，#575 属于后台预渲染，本批不修改其功能或文件。#585 视频预取独立等待 CI；本分支直接基于 main，不把它作为依赖。

## 改动与边界

`pending_vector_bytes` 原本每次新建扁平栅格尺寸集合；分组 `required_bytes` 和 `retain` 分别新建相同的尺寸／深度集合；`stage_targets` 另建去重集合。现在这些集合由各自 GPU 所有者持有，每次使用前清空键并复用容量。预算预测仍重新检查当前网格、尺寸、指纹和已有图片，不缓存上一帧的预算结论。

集合只存尺寸／深度键，不持有纹理或资源租约；容量按验证后场景的峰值工作集复用，完整释放和空矢量帧释放对应存储。暂存失败后的下一次显式调用重新清空去重集合，不能沿用失败调用的成员。没有新增重试、重启、锁、IO、缓存淘汰或 GPU 上传策略。

GPU 纹理的创建、提交、退役顺序、来源字节预算、全局分配预算、当前帧所需资源和错误返回保持既有语义。没有修改着色器、像素格式、混合或精度，不把 CPU 临时集合复用声称为减少 GPU 分配、显存或提升帧率。

## 验证口径

新增三个实际 GPU 上下文用例。分配观察器只计调用测试线程成功的 alloc／alloc_zeroed／realloc，GPU 初始化和夹具构造在统计外，不把后台线程分配算入该站点；观察器仅编译进 lib 测试程序。

最终三项新增用例通过。另执行既有矢量分组 5、上传复用 4、预算对齐 5、错误边界 2，共 16 项回归，全部通过；包含真实 NVIDIA Vulkan 像素输出、同次提交的跨编码隔离、精确预算成功／少一字节拒绝及原始错误原因与恢复。新分配用例本身调用元数据规划／纹理暂存方法，不能单独替代这些像素回归。

带 FFmpeg 和 diagnostics 的 workspace all-targets 检查通过（排除已停止维护的 Android 包），耗时 2 分 06 秒。既有 unused／dead-code 警告保留，没有增加 allow 来掩盖告警。

- 1、8、96 个网格，各重复 120 次真实预算／保留方法调用；独立有序集合核对尺寸、深度、去重及完整预算值。
- 同一尺寸的不同深度、不同尺寸、扁平与分组切换、空集合均覆盖；旧的收集方式作为正控制，实际观察到每 120 次 120／480／600 次堆分配，预热后指定操作为零。
- 真实纹理暂存先触发全局预算拒绝，核对原始资源错误、phase、已提交目标和账目不变；恢复预算后显式调用成功，目标无重复，后续 120 次暂存检查零分配，缩小／清空场景释放纹理和账目。

另将两个生产集合临时改回每次新建，实际重新编译运行：预算和分组两项零分配断言分别以 120、240 次分配失败。恢复源码后重新构建验证；不修改测试断言、预算或期限以接受回退。

最终测试、原始输出、源码与二进制哈希见[清单](vector-scratch-planning-evidence/manifest.json)和[证据包](vector-scratch-planning-evidence/evidence.zip)。只把清单内有成功退出记录的阶段计为通过；本地结果不代替后续 PR CI。

## 失败记录与观察审计
