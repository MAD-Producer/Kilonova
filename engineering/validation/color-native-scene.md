# 原生合成结果进入 OCIO 图片变换

关联 #83，追加到 #650。此处接通已有原生合成目标和明确 OCIO 图片 ABI；普通 managed Session 的配置安装、素材解释、工作空间及 OS 显示仍未完成，不能关闭整个 issue。

## 行为

`Renderer::color_image_from_render_target` 消费一个同 renderer 的原生 `RenderTarget`，保留纹理、view、资源身份及准入所有权，转成现有 `ColorImageTarget`。没有新纹理、复制、上传、提交或 CPU 读回。现有帧内容保持；后续可复用 `image().view()` 渲染，再由已有 `ColorProcessorOutput` 在同一编码器中执行显示或输出变换。

来源必须实际为 `Rgba32Float`。原生合成器的 alpha 固定为 premultiplied；不接受调用者伪造精度或 alpha。错误设备先由原有 owner 检查拒绝，其他存储返回 typed `ColorImageRenderSourceError`，保留真实格式及 source 链。转换消费输入，失败时随所有权退出释放该目标，不偷偷转换、裁剪或降精度。

宽高来自真实纹理描述符，不读取 `RenderTarget` 公开、可写的宽高缓存。新增用例把缓存改成 999×0，首轮如实失败于 `image capture 999x0 Rgba32Float: extent exceeds capture limits`；只修正生产尺寸来源，保留同一断言，仍按真实 3×4、192 字节处理该目标。没有改动其他 API 的缓存字段或历史语义。

交接前比较 view 的实际纹理身份，公开 view 换成同设备另一纹理或其他设备的纹理时，返回带明确原因的现有 `RenderError::Invalid`。先写实际替换用例，旧实现确实错误接受；保留失败及完全相同的测试源码，仅补生产检查。失败消费的目标和替换目标按原所有权释放，不增补偿复制或重新创建 view。

完整 OCIO 空间仍是生产者声明，而非像素检测结果。调用者必须先确保原生像素属于声明的空间；原生普通 Scene 当前的线性 sRGB 行为没有被改成 ACES。此接口不授权绕过 `require_unmanaged`，也不是完整工程色彩管理的启用开关。

## 实际验证

测试使用现有三份配置及未修改的原生 OCIO CPU 参考。独立编写的小型效果通过真实 Scene/effect/native compositor 生成 3×4 Float32 工作像素，不用测试画满屏的替代 pass 冒充原生合成。

- 七组 premultiplied 工作输入覆盖 display/output 和三份配置，含 HDR、负值、透明与半透明像素。
- 先渲染原生目标再转交，检查资源身份、准入量和读回计数保持，并显式资格读取验证原有像素不变。
- 同一目标、view 和变换绑定再连续使用两帧；每帧原生合成与 OCIO 变换在同一个编码器中执行，中间不读 CPU。最终像素按原参考容差核对；额外测试读回只用于资格验证。
- 使用真实 UNORM8、UNORM16、Float16 目标验证拒绝与 typed source；两个 renderer 共享同一个预算仍不能绕过 owner 检查。随后同设备 Float32 目标正常可读。
- 两种实际 view 替换覆盖同设备其他纹理与跨设备纹理；拒绝后预算回到初始值、没有读取、两个设备保持健康，再验正常目标完整读取。
- 首轮缺少 `ImageMeaning` 导入导致编译失败，修复生产代码导入；原始退出码及输出保留在 `first-native`，不改断言规避失败。

最终后端、回归、负对照与带 FFmpeg 检查记录位于 `artifacts/issue-goal-current/color-native-scene/`，由该目录的验证器核对冻结源码、原始输出和交付身份后归档。

最终生产源码的正常回归共 41 项不同测试通过：图片变换 12 项，capture/输出/格式 19 项，布局/映射清理 4 项，原生色彩错误 2 项，原生读回错误 4 项。图片组另外在 DX12 全部 12 项通过，不重复计入总数；不是仅执行新增测试。带 FFmpeg 的 render/host/desktop 全目标 `cargo check` 与本轮 managed 模块、原生 Scene 测试的 rustfmt 检查通过。既有警告保留，没有为了通过而屏蔽。

四个独立生产代码负对照分别新建替代纹理、移除真实存储检查、恢复缓存宽高和漏检替换 view。测试源码保持不变，四次均在实际运行的目标断言处失败退出 101；之后恢复生产源码原字节，三个原生 Scene 用例全部复验通过。缓存宽高和 view 的两次原始缺陷分别与修复后记录核对，冻结源文件的变化均仅为生产 `image_capture.rs`，不靠修改断言通过。此前初次导入错误、格式整理前的 view 失败和中间验收记录也保留，不覆盖首轮证据。

本轮追加九个交付文件，整个 #650 相对所验收 main 基线共 32 个文件，暂存区字节另与工作区、交付副本及后续提交核对。验证器逐项检查命令退出、完整冻结源码、参考字节、负对照范围和前一阶段不可变归档；最终压缩包摘要保存在目录外层的 `archive.json`，不把自身摘要写进被归档内容。
