## 问题与实现

`PanelHost::draw` 每次创建局部 PaintList，消费式 append 随后释放它的容量。
Dropdown 的打开菜单也沿用同一模式，按钮箭头还每次创建三个点的 Vec。

- 新增 crate 内 `append_reusing`，移动全部命令及正确的跨类型索引，并保留源缓冲容量；
  公开消费式 append 复用同一逻辑，仍消费所有权，不保留外部引用。
- PanelHost 只持有一份顺序使用的缓冲，不按 panel/window ID 增加缓存。
  每次绘制前清空并安装当前样式，成功后排空命令；绘制 panic 继续传播，
  下一次绘制不会发布前一次的残留命令。图像资源随命令移走，不被空缓冲续持。
- 每个 Dropdown 保留其打开菜单的空缓冲，样式仍从当前目标列表继承。
  这里是真实桌面面板使用的控件；PanelHost 本身目前用于框架 API/示例，
  不把它的独立场景测量冒充桌面 shell 全帧数据。
- 三点箭头存为内联 Line3，沿用原坐标计算、连接描边、抗锯齿与裁剪。
  相邻重合点沿用普通 line 的去重路径，非法坐标/透明色保持原来的正常空结果。
  节点画布、插件缩略图的坐标/clip 变换和图元统计同步识别新表示。

这会保留各 owner 已经需要过的空 Vec 容量，换取稳定绘制时免于反复申请；
并非释放缓存内存的改动，也没有新增按用户文本建立的全局缓存。

## 分配红绿对照

线程本地全局分配器记录成功 alloc/alloc_zeroed/realloc 的次数及请求字节，
先用真实 Box 验证计数器生效。预热三次后量测二十帧，包括背景、文字和图像。
这些行复用相同短标签，测试绘制命令存储，不覆盖独立长标签的缓存淘汰。

| 两个面板各自的行数 | 旧实现请求次数 / 字节 | 修复后请求次数 / 字节 |
|---|---:|---:|
| 20 | 1,000 / 1,237,120 | 0 / 0 |
| 200 | 1,600 / 10,125,440 | 0 / 0 |
| 1,000 | 2,040 / 60,260,480 | 0 / 0 |

打开的三项下拉菜单旧实现二十帧请求 200 次 / 60,320 字节。
初次缓冲修复仍剩 20 次 / 480 字节，原零分配断言继续失败；追到箭头的三个点后，
新增内联表示才使其通过。修复后 3、20、200 项菜单分别均为 0 / 0，
菜单超过视口的显示数量、滚动和选择规则保持不变。

同一四项回归在旧源 2 通过、2 失败，首次缓冲修复 3 通过、1 失败，
加上内联箭头后 4 通过、零失败。三次的测试源码哈希相同；随后只格式化新测试。
未调整既有断言、容差、命中区、生产预算或错误返回以换取成功。

  包含原有菜单、按钮、主题、裁剪、字素编辑、默认故障信道及 compile-fail 文档测试。
- 真实 FFmpeg 桌面测试程序成功编译。原节点控件组 **24 通过**，缩略图组 **2 通过**，
  均零失败/忽略；包含两条新增内联/原 line 的六档缩放与有/无 clip 精确比较。

- FFmpeg 桌面 all-targets 类型检查通过，36.634 秒；不是全桌面测试执行。
- 原样的工作流策略测试 **15 通过**。CI 复用 #613 / `86ee291d` 的同一 60 分钟
  Rust/GPU job 预算，保留后续 release 检查；没有另创一套时限实现。
