## 当前范围

- `Layout` 只允许 1、2、4 个视图；分割区域不重叠，间隔不参与命中，
  空窗口和无法表达的极小分割正常返回空集合。非有限几何与负间距返回原始错误。
- 每格独立保存模式、画布倍率/中心及观察摄影机的有界标量；不保存工程、轨道、
  完整场景、缓存纹理或用户文本。命名摄影机仅保存身份，尚未提供解析或渲染入口。
- 手势捕获绑定窗口、工程、合成、修订、时间和窗口几何。其他窗口不能接管或取消；
  原 owner 的上下文失效、布局或模式切换会先回滚未完成的导航。
- 设置可随应用 Workspace JSON 保存、读取；缺失可选设置使用单视图默认值。
  非法布局、活动格、模式、部分导航和越界观察参数拒绝反序列化。
- 使用既有 serde_json 1.0.151 的 `float_roundtrip` 功能，保证导航 f64 保存恢复。
  没有升级版本或添加依赖；该功能在桌面依赖图中统一启用，最终整套 CI 仍需验证。
  默认解析器下严格往返断言失败的日志保留，未改为容差比较。

此处只是状态与输入基础。设置尚未连接到真实合成面板，当前用户界面仍为单视图。
CPU 场景测试验证独立观察矩阵，不等于完成多视图 GPU 呈现、真实相机选择或视角拾取。

## 必须继续完成的交付项

1. 显式多视图宿主 API：同一工程与时间、独立相机/观察模式和预算内的输出，
   不把循环切换全局 observer 作为独立视图，不重复发布全局选择状态。
2. 一次原生表面呈现中的 1/2/4 视图、每格 zoom/pan、活动格反馈及真实可用模式选择。
   模式无效或已删除相机必须保留原因，不得静默显示合成相机。
3. 绘制、拾取、钢笔、蒙版、变换手柄和摄影机手势使用同一活动格映射；
   失焦、松键、取消、窗口 owner 转移和过期结果不能恢复旧手势。
4. 连接 shell 保存/恢复、命名布局与工程切换，确认主窗/浮窗均只有一个面板 owner。
   仅 Workspace 类型的往返测试不能证明这些生产路由已接入。
5. 实际中英文主窗/浮窗截图、独立视角 GPU 像素与拾取负对照、撤销/保存重开、
   持续故障默认信道和准确提交的跨平台 CI。完成前不关闭 #221。

## 故障与观测处置

| ID | 分类 | 处置和边界 |
|---|---|---|
| MV-OBS-01 | 既有覆盖 | 畸形 Workspace 经现有 `workspace.load` 处理；输入文件保持原字节，原因含 JSON 阶段及原始校验错误。没有新增日志站点或放宽错误语义。 |
| MV-OBS-02 | 阈值验证 | 独立进程在默认 Info 下运行两轮各 61 次非法加载，中间成功读取恢复；分别校验第 60 次 Error 同时写文件和 stderr、后续抑制、恢复重置及 stdout 隔离。现有 Counter 首次为 Warn，仅写文件；本阶段保留该既有行为。 |
| MV-OBS-03 | 正常分支 | 空窗口、分割间隔、外窗输入、取消、过期捕获和不存在的活动格均为正常不执行，不新增逐帧告警或文件 IO。 |
| MV-OBS-04 | 功能边界 | 新几何/观察解析错误尚无生产调用点；接入宿主和 UI 时必须沿其现有错误信道上报，不把本阶段返回 Err 当作完成端到端观测。没有增加 worker、重启或超时恢复机制。 |
| MV-OBS-05 | 构建失败留证 | 首次构建在未修改的 motion-host 上发生 rustc STATUS_HEAP_CORRUPTION；保留日志并关闭本次增量编译验证，不能据此认定缓存是根因。后续类型错误、系统临时目录访问失败及精度失败日志也独立保留。 |
