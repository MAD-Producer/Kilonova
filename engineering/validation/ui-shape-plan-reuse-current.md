# 塑形计划复用与不同标签分配复核（#129）

## 问题和最终行为

既有缓存热命中测试重复绘制同一标签，不能覆盖工作区中大量不同属性名。
在现有 128 项标签缓存被淘汰后，每个文字段落仍会经过 HarfRust 的默认
ShapeOptions，重新构建 ShapePlan。本批将计划保存在拥有同一不可变字体的
RunShaper 中，最多八个；匹配使用引擎自身的 ShapePlanKey，包含实际解析后的
方向、脚本、语言、默认特性与字体变体状态，正常淘汰按 FIFO 处理。

没有提高标签缓存的 128 项/1 MiB 预算，没有改变 16 KiB 输入上限、字体、
塑形特性、断言或生产编译参数。组合标记、连字、RTL 与缺字处理仍经原引擎。
此次没有实现布局向量池，也没有宣称完整帧已达到非线性分配验收。

开始前读取 AGENTS.md，检查开放 PR 及相关 text/font/UI worktree 的未提交
改动，没有发现他人占用本批文字路径。既有独立提交的标签页显式样式 API
也在此分支上；完整说明见 ui-tab-theme-current.md。父 PR #607 的 650477e4
保持冻结，本批没有取消其 CI。

## 原始结果与对照

本机 Windows 线程分配计数；标签在计数前构造，完成预热后每种文本读取一次。
这些是组件分配计数，不是整帧时间、跨平台结论或原生窗口验收。

| 默认语言 | 200 个不同标签 | 原实现分配 | 复用计划后分配 | 降幅 |
| --- | --- | ---: | ---: | ---: |
| 英文 | 截断至 7 em | 59470 | 26638 | 55.21% |
| 英文 | 完整 100 em | 23800 | 7000 | 70.59% |
| 中文 | 截断至 7 em | 48060 | 19418 | 59.60% |
| 中文 | 完整 100 em | 23600 | 7000 | 70.34% |

32 个不同标签在四种上下文都维持零分配。200 次纯 Latin 段塑形：同字体、
同保留 Buffer 下，默认新建计划需要 3000 次分配，复用计划为 0。正式测试
要求复用确实少于默认路径，没有设跨字体不可靠的固定计数或时间阈值。

反向对照只还原 shaping.rs 到 92593eb7，保留测试与断言：3000 对 3000，
新增性能断言实际失败（退出 101）。随后恢复生产修复，原断言通过。
七种文字/脚本 × 两方向 × 两轮 × 首次/重复调用，与没有计划缓存的原始
HarfRust 参考逐字形比较 ID、源 cluster、advance 与 offset；组合数超过
八个，覆盖淘汰后重建。保留 Arc 的布局经过 200 种不同标签淘汰后仍保持
原字形、字素边界、宽度及截断位置，重新构建的结果相同。

第一次双目标编译因新增参考测试传入 Arc<Arc<[u8]>> 而未满足 Font::new 的
Source 类型约束失败，未运行该轮测试；改为明确的共享字节 trait object 后
两目标共八项通过。错误日志独立保留，没有改测试断言。

最终格式化后完整 UI 回归：29 个目标、254 项通过（253 项运行测试和一项
compile-fail 文档测试），零失败、零忽略、零过滤，耗时 329.22 秒。
保持默认 gpu-tests，实际 GPU 路径、字形/截断、图集边界、默认观测与主题/输入
检查均包含在完整结果中。八项聚焦测试与此前标签页 11 项均为其子集，不累加。
带 FFmpeg 的桌面 cargo check 退出 0，耗时 32.69 秒；它不生成 EXE，
不作为 release 或原生窗口验收。35 条既有桌面警告保留，没有为其改配置。

## 错误处理与完成边界

E1（已有覆盖）：无效字体、超长段、非法方向、原引擎 ShapeError 继续返回
原错误。长度和方向守卫仍在改动 Buffer 和计划缓存之前；现有拒绝及健康
恢复测试未改断言。UI 边界已有 layout/raster 缺陷计数与默认日志信道，本批
未新增错误类型、吞错、重试、线程等待或日志路径。

N1（正常分支）：计划命中、FIFO 淘汰和新字体第一次构建是正常缓存行为，
不新增逐帧警告或文件 IO。缓存仅随所属字体 owner 保留，最多八项，没有
按用户文本建立新键或保留完整输入。

完整路径不是零分配。#129 的“每帧分配量不随控件数线性增长”继续未勾选；
复杂双向文本 caret/选择、完整 emoji 编辑绘制测量和最终跨平台 CI 也不能
由这组塑形计划测试替代。整个 issue 继续开放。
