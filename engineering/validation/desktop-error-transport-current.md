## 原始失败

首次命令因 PowerShell 丢失参数分隔符而未执行测试。随后首轮专项为 3 通过/1 失败：实际子进程通过，但新收集器错误读取 logs/motion-studio.log，真实 logger 写在初始化目录本身。只修正新测试路径，并让子进程失败先保留其输出，不修改生产返回值或既有断言。初次编译被中断且没有完成记录，保持不完整，不计通过。最终专项完整执行通过，源码前后哈希一致。

首次完整带 FFmpeg 桌面回归在观察到八项失败后停止，保留原始输出及实际终止记录，不能称为完整运行或通过。
其中六项视频替换共用的等待辅助函数误将 JSON `state` 转为序列化文本，
把 `running` 变成了带引号的字符串；现恢复原始 JSON 值比较。
另一个 atlas 用例原先收集 `String` 并比较两次错误文字，迁移后误收集成
按原生实例身份比较的 `Error`；现在收集器显式保留 Display 文字，
原断言、预算、期限与回收验证全部保持。原生实例身份由本批独立专项验证，
不将原来的文字相同断言冒称指针身份相同。
异步电影冻结的 panic 用例还在原 5 秒接收期限处失败；未修改期限或忽略该失败。
同一实际测试二进制单独运行受控子进程（保留默认文件日志）和完整父测试均通过，
分别耗时 1.437 秒和 1.047 秒；这仅证明单独执行未再现，不证明首次超时根因已修复。
新编译二进制的六项视频替换测试和图集回收测试随后均通过，原始失败保留。

冻结 panic 在新二进制上再次失败。临时阶段诊断实际记录：原生回溯采集约 605 微秒，Display 符号解析/格式化 11,291,950 微秒；因此原五秒等待包含了同步符号处理。诊断源已逐字节恢复，SHA-256 与原文件相同。主线对照该测试通过只作对照，不代替当前分支通过，也不证明所有差异都来自冷缓存。

用户明确允许修正该日志契约测试的同步范围并补负对照后，保持原五秒接收断言、错误原因和请求上下文检查，先等待 worker 完成，再检查交付结果；整个子进程增加二十秒看门狗，与既有真实 panic-hook 控制的总期限一致，并覆盖原来未设期限的 join。新增仅限测试的“不回复”“错误原因不对”控制。该修正改变测试同步范围，不是生产 panic 提速、线程重启或返回值修改。

同步修正首轮正向退出 101，保留为失败：父线程立刻 Drop 活跃 worker 会记录并 flush 关闭日志，与 panic hook 的 try_lock 竞争。请求 22 的 panic 上下文实际回退到 stderr，文件中未出现该条，原文件断言因此失败。没有将文件断言改为“文件或 stderr 任一存在”；后续改为先观察已发布的在飞状态清空，再 join，避免测试观察者制造这次竞争。该等待同样由父进程看门狗约束，原始 stderr 回退与文件输出均保留。

修正观察者同步后，以一次 Cargo 编译产生的同一测试二进制执行三种模式：正向 1 通过（4.26 秒）；错误原因负对照实际退出 101，在原 `controlled freeze panic payload` 内容断言处失败；不回复负对照实际退出 101，由二十秒看门狗终止子进程，并保留输出与 kill/wait 结果。两个负对照不是编译失败，也没有靠忽略或预期成功包装成正向通过。随后同一二进制的五项原生错误专项全部通过（21.79 秒）。每项均保存固定源码清单的前后 SHA-256、默认日志环境和实际父/子进程输出。新源码完整桌面/宿主回归正在执行；PR 保持草稿，不把专项通过称为完整回归。

后续完整命令 `complete-desktop-host-verified` 在执行测试前因 `preview_memory` 的调试数据库损坏而退出 101：MSVC `LNK1285`，耗时 598.734 秒。保留编译/链接原始输出，不计测试运行或通过。只隔离链接器点名的一个 PDB，移动前后 SHA-256 一致；没有因此改动测试、生产代码或断言。整份已完成构建缓存的递归清理被自动审批拒绝，未执行；另对已完成验收缓存中的八个非占用 PDB 使用可逆 NTFS 压缩保留文件，以缓解磁盘余量不足。恢复后完整命令单独记录，不能覆盖或改称本次编译失败为通过。

`complete-desktop-host-pdb-recovered` 同样未进入测试，114.032 秒后在 `session_concurrency` 链接阶段退出 101，报告 `LNK1318 LIMIT (12)`；同期 E 盘可用空间一度降到 37 MB。该 PDB 也单独保留并校验哈希。另压缩四十个已完成验收的 PDB，保留原文件；随后按用户要求独立清理已完成且干净的工作树，保留活跃分支、未提交内容和本地证据。没有将链接错误归为测试失败或修改生产日志掩盖它。当前分支已同步主线的 #618/#620，完整回归及该组合的冻结正负对照仍待终态，后续归档需保留两个链接失败，不复用旧源码的完整通过结论。

## 范围

界面提示、MCP JSON 的显示文字在现有文本边界格式化。异步控制器及原测试辅助接口同步接受新类型；原来比较文字的断言显式格式化，预期内容保持。没有依赖、资产、渲染语义或 panels 生产排版改动；DESIGN §0.7 的视觉整改项全部保留，原因是本批仅调整信道与测试接口，不声称截图/交互整改验收。

导出、插件准备等提供方本身的 String 协议、现有文本型 UI 提供方及未穷举的模型输入仍有边界。旧清单 remaining-text-boundaries.json 是当时的源码盘点，工程锁和能力 JSON 包装现已进一步修复；不能把该旧清单当作当前缺陷数或运行验收。不要将本批当作 #138 整体完成。

继续按当前源码复核后，边界还需区分以下几类，不将一次文本搜索全算成未修缺陷：

| 路径 | 分类与后续范围 |
|---|---|
| 工程锁、能力 JSON、PNG/冻结 worker spawn | 本批已保留原生原因；前两者有实际失败与默认信道验证，OS 线程耗尽没有实际注入。 |
