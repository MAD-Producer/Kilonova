# 原生内置配置与 ACES 版本一致性

本批继续 #83，补足先前目录核验未覆盖的内置来源及 ACES 声明。没有新增配置
资产、依赖、兼容层或用户可见 UI。开始前已核对其他工作树：深度、跟踪、
多视图及属性分支未占用本批颜色实现，不审查其他 agent 的 PR。

| 编号 | 分类与处置 | 证据、正常分支及限制 |
| --- | --- | --- |
| CBI-01 | 功能 | 从固定 OCIO 2.6.0 的 BuiltinConfigRegistry 查找精确配置名，用原生 Config::serialize 比较原始解析配置与注册表配置的完整规范化内容，再进行资源闭包改写。只比较名称或所选处理器不能证明未选中内容一致 |
| CBI-02 | ACES 声明 | 原生目录新增可选内置身份行。Builtin 清单必须与实际匹配的完整配置 ID 相同；再按官方版本化 ID 核对 ACES major/minor/patch，当前注册表的 major.minor 对应 patch=0。不存在的 ID、default/latest 别名和自行填写的其他 ACES 版本不触发替代配置 |
| CBI-03 | 独立身份 | 原工程内容 SHA-256、完整清单 key 和选择 key 保持不变。规范化只证明内置内容来源，不替换字节身份；增加注释后的文件仍有不同工程 key，但可代表同一内置配置 |
| CBI-04 | 正常分支 | 显式 Authored 配置没有匹配内置内容时正常使用，不推断或补写 ACES 声明，不为该正常未命中记录 Error。保留原空间、角色、视图及数据声明核验 |
| CBI-05 | 新拒绝 | 不一致返回原有类型化 Catalogue，字段 builtin_id 或 aces_version，包含有界配置名、预期及实际值。准备结果在核验后才发布，失败由既有所有权守卫释放；无部分替换、重试或回退 |
| CBI-06 | 既有观察 | 仍处于 prepare_project_colors 的 Info start/in-flight 范围，原始原因沿 Provider 链进入既有文件/Error stderr。没有新 logger、线程、锁、热路径 IO 或 Present 日志 |
| CBI-07 | 有界数据 | 注册表最多 64 项，规范化结果最多 8 MiB；每个目录字符串最多 256 UTF-8 字节。原 2,720 行目录容量加一个内置来源行成为 2,721；Rust 和桥接上限一致。序列化流启用失败异常，避免两个不完整结果误判相同；沿用原异常边界，不另造成功值。此处不把结果限额当作原生峰值内存测量；OOM 实际路径未新造故障验证 |
| CBI-08 | 实际原生 | 三份既有 ACES 1.3/2.0/2.1 配置，18 个错误 ID/别名/ACES minor/patch/内容拒绝。改变未被所选 RGB 处理器使用的 luma 仍须拒绝；显式 Authored 改动和只增加注释的配置正常。每次拒绝后原配置显式健康请求保持原 CPU 值 |
| CBI-09 | 默认信道 | 实际宿主准备分别拒绝错误 ACES、latest 名称及修改内容后仍标为内置的配置；检查完整工程不变、状态清理、后续健康请求及原始原因。默认级别下文件先有 start 再有 Error，stderr 保留相同错误正文，stdout 隔离；篡改文件或 stderr 的版本、移除 stderr、降级 Error 或污染 stdout 的负对照必须失败 |
| CBI-10 | 不变与待验证 | 不修改旧断言、数值容差、golden 或渲染表达式。此核验说明来源一致，不是任意作者配置的颜色数学认证，也不实现受管视频/效果/三维/曝光等剩余消费者。原有 native/编译器异常根因仍未解决，跨平台资格仍须当前提交的 CI；#83 保持未完成 |

依据为固定版本的公开 [OCIO Config API](https://opencolorio.readthedocs.io/en/v2.6.0/api/config.html)
和随已核验运行时分发的头文件。上游代码、原始配置和许可证未修改，继续使用
ATTRIBUTION.md、PROVENANCE.md、NOTICE 中已有来源记录。

本地证据目录为 `artifacts/issue-goal-current/color-native-origin/`。
仅重新编译生产 bridge install 目标，MOTION_OCIO_BOUNDARY_TESTS=OFF；复用原
固定核心并逐字节核对核心与许可证。该本地资格前缀不是一次完整依赖重建或
生产发布配方资格，单独收据明确记录边界。未启动特殊故障工具。

前两次常规 CMake 配置失败已保留：先是 MSVC 的 D8050，再是缺少 rc.exe。
采用既有短临时目录、Release 编译探测以及本地原有 SDK 的 rc/mt 后生产桥接
正常编译安装；没有下载工具、绕过编译探测或修改产品运行策略。

首轮新增原生来源测试通过；原有 20 个 CPU/GPU 程序描述和 240 个外部 CPU
数值样本通过。后续最终代码的 GPU、默认信道和回归结果须单独记录，不能由
首轮通过或此前提交的 CI 结果替代。原有 native 异常未复现不代表已经修复。

最终启用序列化异常的版本已重新编译实际桥接并更新本地资格清单，两项不同
新增测试通过：18 组内置来源拒绝及健康对照（1.01 秒）、实际桌面默认信道的
三类错误（0.51 秒）。首轮代码、桥接及其清单独立保存，不与最终版本混用。
原有数值参考一项通过（20 程序/240 样本），未选中目录变异一项通过（12 组
拒绝及恢复），作者配置资源一项通过（180 样本、全部三阶段）。

实际 GPU 重新准备并执行 20 个原生程序、240 个像素的同一项回归在 Vulkan
和 DX12 分别通过（10.38/16.67 秒），保留错误着色器及查表的负对照。使用
最终桥接的受管 MP4 三项回归通过（33.88 秒），严格检查实际 Vulkan 适配器，
保留六份完整 MP4、首尾解码 PNG 和独立参考。原数值、shader 结构比较及像素
容差保持；两种后端或首轮重跑不能算作更多不同测试。合计九项不同 Rust
测试及十五项现有工作流测试，跨平台与整个 #83 验收仍未完成。

另复用了本机已有 PyYAML 6.0.3，工作流十五项现有工具测试全部通过。此前
MP4 批次的可选 YAML 检查未运行记录仍保留；本批证据补足当前工作流验证，
不改写该冻结批次。DESIGN §0.7 的面板整改项全部保留，本批不改面板或样式。
