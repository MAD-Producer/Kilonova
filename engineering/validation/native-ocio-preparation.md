# #83 固定原生 OCIO 准备接口

## 交付范围

桌面运行时方案采用随包分发固定原生 OCIO，用户已明确选择。
本批实现固定源码构建、C ABI、Rust 所有权、宿主准备入口和错误信道验收；
尚未启用普通 Session 的 managed 渲染，也尚未修改桌面发布工作流。
外部 Python 仅保留为独立数值参考，不成为产品运行条件。

- `tools/ocio_sources.json` 固定 OCIO 2.6.0 及六个静态依赖的官方提交、
  归档字节数、SHA-256、作者、许可证和原始许可证 SHA-256。
- `tools/prepare_ocio.py` 要求原生工具链和新的输出目录，关闭 OCIO 自动
  安装依赖、Python、应用及 GPU 后端，构建共享 OCIO 和独立编写的桥接库。
  构建日志、开始事件及 in-flight 状态在进入原生构建进程前写入；失败不
  发布清单、不重启、不重试、不替换保留的错误归档。
- 成功清单包含共享库、全部七份原始许可证及其实际字节身份。
  归档路径和链接接受数据过滤；损坏缓存、越界路径和构建期间源码变化均拒绝。
- Rust 在准备阶段验证前缀内容和固定源码声明，然后使用绝对路径加载。
  清单用于内容校验，不是对不可信原生代码的签名认证；调用方必须提供
  受信任构建或分发的运行时。每个进程只保留一份运行时，避免卸载 OCIO
  全局 `std::function` 的管理函数所在桥接库。更换运行时前缀须重启进程。
- C++ 所有权、异常分类和有界原因经过独立 C ABI；Rust 不释放 C++ 分配。
  CPU RGB 与 GPU 原始着色器/数值表均来自真实处理器，无默认配置或角色回退。
- 外部 FileTransform、动态上下文、环境目录覆盖、3D 表、动态 uniform
  及超容量程序明确拒绝。完整配置中的颜色空间、look、view transform 和
  named transform 均在处理器编译前扫描，包括未选中的变换。
- `prepare_native_project_colors` 在已有宿主 provider 的 Info 开始记录及
  in-flight 发布后加载运行时。返回的原生错误通过 `Error::NativeColor`
  保留类型和原始 IO/OCIO 原因；不修改失败的工程，也不移除 Scene 拒绝边界。

## 实际验收

本机 Windows x86_64，MSVC 19.44、CMake 3.31.10、Ninja 1.13.0。
开发工具只用于构建，不进入产品资源。源归档全部按锁文件校验。
本机便携 SDK 缺失 rc/mt 时的失败日志保留；补取官方 SDK 的指定文件并验证
其原始下载 hash 后继续构建，没有安装 MSI 或修改系统注册表。

完整配方已从固定归档构建所有七个组件和桥接库。随后桥接库增加初始化
版本检查，用原清单逐项验证并复用未变化的原生核心，再重新构建桥接库、
复制原始许可证并生成新清单。两次运行的原始事件、命令和失败记录分别保留。

| 项目 | 证据与边界 |
| --- | --- |

原有 `reference.json`、`chain_reference.json` 及 `source_reference.json`
没有重新生成或修改，数值语义和容差没有放宽。

加入独立编写的未选中文件变换，不改动参考文件本身。
新增默认信道测试首轮把 provider 阶段记录误当成最终 Error 的字段，
该新断言已按实际错误结构修正为检查原始 `provider failed` 上下文，
原始失败输出保留。

## 两条已有 CI 测试的授权修订

上一提交 `4df0bae2` 的 CI run `42445054164` 在 Linux/macOS 均显示：

1. 实际强制回溯存在，但 Unix 不保证包含 `Backtrace::force_capture` 函数名。
2. 两条自定义 Error 与必须保留的原始 panic hook 合计报告四次原因，
   媒体测试却要求 stderr 中总共只有两次。

本机直接执行两个真实 child 分支得到同样的信道事实：颜色日志文件一条
panic、stderr 两次原因；媒体日志文件两条 panic、stderr 四次原因及两条
自定义 Error；stdout 不含这些原因。原始 CI、子进程输出和修订草案保留。
用户随后明确授权“允许修订并补负对照”。生产日志 hook 未修改。

最终本地两条原测试均通过；新增原生运行时错误信道测试也通过。

- 颜色测试为 child 显式设置 `RUST_BACKTRACE=0`，验证文件和 stderr 仍有
  实际栈帧，避免依赖优化器保留某个函数符号。负对照从真实捕获日志移除
  栈帧、保留原因和上下文，必须拒绝。
- 媒体测试严格保留两条文件 panic、两条 Error、四次 stderr 原因和 stdout
  隔离。负对照分别删除真实 Error 记录标记和最后一次原始 hook 原因，
  必须拒绝。它们是捕获日志的负对照，不宣称进行了生产 hook 代码变异验收。

## 剩余边界

审计处置区分实现与验收，不把记录下来视为缺陷已修复：

| ID | 分类 | 处置 |
| --- | --- | --- |
| NOC-01 | 新增观察 | 构建进程开始、退出、受控阻塞、原始输出及 in-flight 清除已实测；下载本身未新增独立的阶段观察 |
| NOC-02 | 复用已有覆盖 | 原生 provider 复用宿主 Flight；默认 sink 的真实 NotFound、文件/stderr 和 stdout 隔离见本批桌面验收 |
| NOC-03 | 正常分支 | unmanaged 返回 None，不加载运行时、不报故障；没有把正常缺省当成缓存故障 |
| NOC-04 | 功能/协议边界 | 加载受信任原生代码、资源闭包拒绝、CPU/GPU 程序准备；不改变工程和现有 Scene 拒绝行为 |
| NOC-05 | 待注入验证 | C++ 分配失败、未知异常、初始化锁中毒及日志回调内的 logger panic 尚未故障注入；已编码的边界不计作实测通过 |
| NOC-06 | 未解决 | 旧 GPU 原生访问冲突保留原始记录，未归因为本批运行时、未宣称修复 |
| NOC-07 | 已授权测试修订 | 原始日志和输出数量已复核；加入真实捕获日志的缺帧/缺 Error/缺原始 hook 原因负对照；跨平台新 CI 仍须验证 |
