# #83 RGB 有限码值范围执行

本批给显式图片处理器和工程准备增加码值范围执行。它不移除普通 managed
Session/Scene 尚未接线的拒绝边界，也不改变既有全范围参考或渲染基线。

## 行为与身份

- `CodeValueRange` 只接受有限的 `0 <= black < white <= 1`，端点转换为
  Float32 后必须仍有正规正数宽度；归一化负零，私有位表示保证身份可比较。
- 输入先反预乘，再执行 `(RGB-black)/(white-black)`；输出先编码为
  `RGB*(white-black)+black`，再按声明预乘。Alpha 原值不变，不裁剪负值和高亮。
  预乘输入的零 Alpha 以解码后的黑色查询 OCIO，不把码值零误当有限范围黑色。
- `compile_image` 保持原全范围路径；新编译入口显式接收两端范围。范围进入
  生成程序身份及宿主准备去重键。默认输入、创作输入、素材覆盖、工作、显示
  和输出角色都传递实际范围，不把某个角色单独忽略。
- `ColorImageContract` 带范围身份。分配和上传保留完整声明；创建绑定前检查
  源和输出声明，编码前再检查目标。失败返回 `ColorRangeMismatch`，不分配表
  或写目标。原始纹理包装 API 声明全范围；有限范围生产者须使用完整 contract
  的分配或上传入口。
- 工程准备在资源读取及 provider 调用前拒绝不可表示的范围。typed 错误保留
  角色、原始黑白码值和原始 Float32 拒绝原因，沿用既有开始/在途/失败信道。
  没有增加逐帧日志、重试、重启或同步读回。

## 验证范围

- 独立 Python 工具使用固定官方 OCIO 2.6.0、原三份配置和显式 Float32 边界，
  单独生成 60 组、720 个像素的 CPU 参考：输入 8 位有限范围→全范围，
  全范围→输出 10 位有限范围，以及两端有限范围。覆盖三个阶段、透明度组合、
  负值、高亮和零 Alpha。生成器固定原参考 SHA-256，输出独占创建；CI 不重生参考。
- Windows 实际 Vulkan 图片处理器 14 项全部通过，包括新 60 组参考各复用两次。
  80 个实际 GPU 负对照故意省略输入解码或输出编码，都在原有容差下被检出。
  源/输出声明/目标范围错误实际拒绝；预算不增加，目标原始像素保持不变。
  既有全范围单阶段、两阶段、原生场景目标和上传/资源生命周期测试同时通过。
- effects 7 项通过；宿主工程准备 9 项通过，包含三份配置、两种 Alpha 的全部
  角色身份、默认素材共享、不同范围不共享、数据旁路和六个角色的不可表示拒绝。
  原生 OCIO 数值/拒绝 4 项、宿主原生准备与容量 3 项通过。
- 桌面真实默认日志 4 项通过。新范围错误的文件 Error 与 stderr Error 都包含
  request、角色、黑白码值、elapsed 及原始原因；Info 开始先于失败，stdout
  无日志，工程不变且在途状态恢复。五个实际捕获输出的负对照分别移除文件
  Error、清空 stderr、丢掉原始原因、污染 stdout、倒置开始/失败顺序，均被拒绝。
- 首轮宿主测试编译因新断言多借用一层字符串失败；修正测试代码的解引用后
  通过。保留首轮输出，不改变生产数值或容差来适配测试。
- 原先测试“全部 Limited 均拒绝”的输入改为“f64 合法但 Float32 端点重合”，
  因为正常 Limited 现在确实被实现并经真实 GPU 正面对照验证；provider 不可
  调用、typed 错误和工程不变断言仍保留。没有将旧失败改为成功返回。
