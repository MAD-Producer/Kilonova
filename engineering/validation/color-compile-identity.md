# 颜色编译失败的源码身份

本批只继续 #83，补足真实解析失败暴露的诊断缺口。此前独立诊断发生过
WGSL 解析错误，但缺少失败源码及该次二进制，不能补造缺失证据，也不能将
后续通过视作修复。访问冲突、栈溢出和解析错误是否同源仍未确定。

| 编号 | 分类与处置 | 证据和限制 |
| --- | --- | --- |
| CPI-01 | 新观察 | 已有冷准备的 Info compile 记录增加配置身份、选择身份、原始 GLSL 的完整 SHA-256 和字节数；进入编译前记录，沿用独立准备刷新和 Session 延迟日志的锁规则。没有着色器正文、用户文本、每帧日志或文件捕获 |
| CPI-02 | 原始失败 | Compile 错误保留同一个 ColorProcessorError 为 source，附加指纹和字节数。请求、目标、变换阶段、耗时及默认文件/stderr 信道沿用既有机制，不改返回值或错误分类 |
| CPI-03 | 身份对照 | 两份不同的真实非法 GLSL 分别产生独立预计算哈希，严格匹配类型化 GLSL 解析错误、原工程不变与在途状态清理。不是成功返回的 mock；原拒绝/身份/alpha/阶段用例继续验证 |
| CPI-04 | 默认信道 | 真实原生 SurfaceDisplay 准备返回非法 GLSL，既有两条 Error、完整原原因、阻塞前发布、stdout 隔离及恢复检查全部保留；另检查 compile Info 身份、Error 指纹与解析阶段，正文不进入日志 |
| CPI-05 | 功能边界 | 仅补观察；没有改变编译器、原生所有权、线程栈、重试、预算、窗口行为或旧断言。指纹标识的是提供者 GLSL，不冒充失败时生成 WGSL 的副本。未来定位仍需失败 WGSL 或可复现调用 |
| CPI-06 | 未完成 | 20 次独立进程各 60 次调用通过，保存进程/源码/二进制身份及输出，但仍未捕获旧失败。#83 和 PR #650 保持未完成，PR 仍为草稿；完成 #83 后按用户要求停止 |

本批证据目录为 `artifacts/issue-goal-current/color-compile-identity/`；后续
解析诊断位于 `color-managed-composition-crash/`，没有改写此前冻结的合成
切换证据。`cargo fmt --all --check` 在 Windows 因命令行长度报 os error 206；
改用直接 rustfmt 对本批三个 Rust 文件检查，未变更格式规则或测试断言。

三项不同测试通过：新源码身份与原始解析错误、原拒绝行为回归、真实原生准备的
默认日志信道。后一项仍要求原两条 Error 完整出现在文件及 stderr、stdout
隔离、阻塞前发布及恢复；新增的身份与正文隔离检查也通过。直接 rustfmt 与
diff 空白检查通过。构建保留了既有 render 两条及桌面二十六条 warning，
本批没有修改这些代码，也没有把 warning 计作修复。

本批不增加依赖、资产或用户可见 UI；DESIGN
§0.7 各整改项均保留，不涉及本批，不将编译通过当作界面验收。
