# 受管显示组的截图消费者

本批继续 #83，把已经完成的原生显示图像接入普通桌面截图。
原生 surface 与截图附件可以使用不同的通道排列/编码格式；截图按自身
附件准备一个合格的显示传输管线，并为每个单元保留独立位置 uniform。
全部单元准备成功后才编码，资源所有者保留至提交和读回完成。

截图携带文档、合成、修订、时间、窗口、surface、质量、摄影机和尺寸的
完整键。不能捕获其他窗口的组、旧时间的组或未完成候选；不重新采样，
不读配置/来源文件，不推进播放时钟，不发布预览帧。PNG 保存的是已完成
的窗口显示码值，工程输出变换、浮点导出及 HDR 输出仍须分别接入。

| 项目 | 类别与处置 | 证据与边界 |
| --- | --- | --- |
| MDC-01 | 新增截图消费者 | `encode_managed_view_capture` 复用完成组的显示图像，以明确所有者和完整键准入；目标为类型化 `ImageCaptureTarget`，编码前验证 renderer 所有者和完整截图契约，避免依赖驱动 panic。返回的资源所有者须保持至提交，资源账本包含实际显示图像及数值表 |
| MDC-02 | 新增实际像素资格 | Windows 实际窗口准备后，三配置、两输入 Alpha、单/双/四视图，53760 个截图内部像素对照原生 CPU，容差仍为一个 SDR8 码值；同时比较实际 surface 与截图的全图分量差异 |
| MDC-03 | 新增所有者负对照 | 未发布、其他窗口、过期时钟均拒绝；恢复原时间可再次捕获相同字节。另以实际其他 renderer 的目标，以及 Straight、Float32、Data、错误尺寸目标验证五次拒绝后恢复。删除原配置后截图仍成功，完整工程及采样/已呈现计数保持不变 |
| MDC-04 | 功能边界变更 | 普通单视图 Color 从上一批的明确拒绝改为已接入；原“不生成不合格截图”和默认 Error 信道断言保留，其输入显式使用仍未接入的 Alpha 通道。新增 Color 正向像素与工程不变性检查；不是放宽原像素容差或把失败改成成功 |
| MDC-05 | 桌面协议资格 | 实际 worker 单/双/四视图 PNG、原生 CPU、默认文件/stderr、stdout 隔离及失败后恢复通过；另有 96×64 浮动窗口对 64×64 主窗口，验证捕获浮动组时无需借用主窗口尺寸。原同尺寸窗口所有者隔离断言保留。四张 PNG 及独立 CPU 数值/manifest 均保存在证据目录 |
| MDC-06 | 新增错误上下文及既有观察复用 | 截图错误附带有界的文档/修订/窗口/时间、目标契约和已发布组数字标识，保留原始原因。过期组实际 worker 失败与恢复、错误文件/stderr 通过。截图为显式非 Present 命令，复用原在途状态、Info 开始、捕获阶段和耗时；热 Present 未添加日志或 IO。未新增重试、线程重启或 panic 吞没 |
| MDC-07 | 正常分支 | 正常预览等待与缓存未命中仍沿既有语义；用户请求截图却没有完整、当前、正确所有者的显示组时返回明确错误，不写文件或假装成功 |
| MDC-08 | 待完成 | Alpha/分量检查、ROI、比较、取色、录制和工程输出变换；其余平台实际窗口资格、完整 ACES 2、3D LUT、OS/HDR 和其他创作消费者仍未完成。不能关闭 #83 |
