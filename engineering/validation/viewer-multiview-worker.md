# 多视图进入桌面 Present／截图协议（#221，第六阶段）

基线 `a1c20442`。开始前核对开放 PR／工作树：#575 继续由其他分支处理原生预渲染，
本轮不修改其工作树、缓存协议或预渲染任务。沿用 #221 自有分支。

## 接入和约束

`UiFrame.views` 携带拥有独立相机／observer 和物理 viewport／canvas image 的整组载荷。
现有帧构造处仅显式填 `None`，原来单视图、插件、节点和验收窗口的布局不变。
生产 `Present`／`PresentFrozen` 根据载荷路由到宿主批量入口，沿用一个 overlay、
原生浮窗的 surface/config 交换及无条件错误恢复交换；没有新增命令、worker 或日志站点。

- 普通整组复用要求文档 generation、合成、revision、窗口 owner、surface、质量、
  各格相机和输出尺寸一致。平移重绘使用各格新 placement，不重新取样。
- 冻结允许已完成组的 frame 与共享时钟不同，其他身份仍须一致。
  直接呈现已有组，不改 Session.frame、不调用 sample，也不把旧组重新标成新帧。
  取消冻结后必须按当前时钟渲染；截图严格要求当前帧，拒绝保存冻结的过期组。
- `CaptureUi` 使用完成的多视图输出，继续通过显示编码目标导出 PNG。
  浮窗 capture 明确使用其目标尺寸；不会误取原单视图 scratch 或其他窗口的组。
  未完成／过期／其他 owner 的组返回原错误，不生成输出文件。
- 回到原单视图呈现前取消该组的 sampling 接收器并释放其输出／任务／presenter；
  取消失败沿原 cause 返回。单 Session 只有一个 GPU 组，不保留每个窗口的无限 GPU 缓存。
  多视图入账仍包含保留的单视图容量；切回单视图时先退休组，再进入原目标分配路径。
- 多视图暂不支持逐格通道、ROI 和快照比较。带这些设置的载荷明确报错；
  不偷偷改成 Color、全画面或其他窗口的比较。旧 `CaptureViewerSnapshot` 没有可用的
  单视图 stamp，因此不会从旧 scratch 抓到与屏幕不符的多视图快照。
  这些接口还需完成后才能开启产品布局菜单。

## 原生验证

新增用例经生产 `Present`、`PresentFrozen`、`CaptureUi`、`FloatWindow` 和 `CloseWindow`
运行，真实窗口 surface 隐藏；不通过 `TestStudy` 绕过呈现路由。

1. 使用前后两台真实相机、合成相机及独立 observer，导出四格实际像素；
   两台相机的输出必须不同。第一格 pan 后只有该格像素变化，renderAttempts 不增加。
2. seek 到第 10 帧后，冻结重绘不增加内容尝试、时钟仍为 10；当前帧截图拒绝旧组，
   文件不存在。正常 Present 再完成后，输出必须不同于第 0 帧。
3. 主窗 96×96／浮窗 128×96 往返；浮窗输出尺寸正确、相机不同，主窗不能冒用
   浮窗 front。缺失相机、尚未支持的 inspection、关闭的浮窗均产生实际错误。
4. 恢复后实际像素与第 10 帧一致。切回原单视图后旧组截图失败，再切回四格仍恢复
   原像素。除显式 seek 外，共享工程、revision 和撤销状态不变。
5. 默认 Info 日志与 Error stderr 含原始 cause，stdout 不含错误；健康 Present 无
   无条件 start 日志。其他回归仍运行原预算、阈值、抑制／恢复及输出断言。
