# 节点创作与手机效果包导出

状态：N1 单 pass 编译、N2 桌面节点编辑与实时预览已实现；节点图现可绑定图层效果。多 pass、自定义 WGSL 与移动图像验收仍按后续阶段推进。

完整输入、数学、颜色、纹理、SDF、程序化生成、PBR 与输出节点目录见 [节点目录与实施分期](NODE-CATALOG.md)，包括移动出口、SDK / 渲染前置能力和 PC 专用策略。

目标是让用户在桌面搭建效果节点图，生成 WGSL 与效果计划，导出 Android 可加载的 `.msfx`。手机运行编译结果；桌面保留可继续编辑的节点源文件。

## 在工程中编辑图层节点效果

1. 选中可视图层，在效果控件点击 **新建节点效果**。默认图把图层输入原样输出，不会改变已有画面。
2. 节点工作区同时显示节点画布、主合成、效果控件和时间轴。画布标题标明绑定图层；切换图层选择不会把同一节点图自动移到另一图层。
3. 修改节点后自动编译并更新该图层的效果实例。公开参数进入效果控件，可用原有参数动画操作；相同参数 ID / 类型的已有值与动画会保留。
4. **编辑节点**可重新打开该效果的图。**返回效果控件**回到常规工作区，**节点草稿**返回原来的独立图。
5. **保存**保存工程，包括节点源与编译配置。未接完的图仍可保存，运行时继续使用上一次有效 shader；工程重新打开后可以继续接线。

节点源存储在工程格式 17 的 `EffectInstance.node_graph` 中；旧工程只在第一次加入节点源时升级。主合成使用私有、内容版本化的 `.msfx` 依赖，最后一次有效编译的 `.msfx` 原始字节以十六进制嵌入节点源，保留准确的归档 hash；保存和 `.msproj` 打包因此可在无插件缓存的环境恢复运行时，并校验其版本与 hash。私有效果不会出现在效果库 / 效果搜索的公共分类里。普通 `.msfx` 没有节点源时不会显示“编辑节点”。

CPU worker 处理校验和编译；GPU 创建、验证和图层安装仍由 engine worker 负责。旧文档的异步结果，以及已删除或替换效果的结果，会被拒绝。图层效果更新与源更新使用既有工程命令 / 撤销机制。临时端口预览只影响节点预览，不会替换主合成输出。

独立节点草稿仍可保存 `.msgraph` 或导出 `.msfx`；点击 **应用到当前图层**可把草稿加入当前图层的效果链。

## 第一版范围

先做效果节点，覆盖标量、向量、颜色和图像。节点包括素材输入、UV、时间、公开参数、数学、渐变、噪声、颜色处理、混合及输出。自定义 WGSL 作为高级节点接入。

合成图层、摄影机父级和效果内部节点拥有各自的语义。效果图先对齐现有效果 pass 与资源 ABI；完整的 3D 几何、物理模拟及通用计算图不在首版范围内。

```text
节点文档 → 类型与连接校验 → 中间表示 → pass 规划 → WGSL
                                                ↓
                        manifest + shader + 资源 + 参数界面
                                                ↓
                                      .msfx → Android
```

## 文档与端口

节点源文档单独保存为版本化 `.msgraph`：稳定节点 ID、节点版本、端口类型、连接、参数、节点位置、公开参数和资源引用。布局信息与执行语义分开，移动节点不改变着色器行为。

端口先支持 `float`、`vec2`、`vec3`、`vec4/color` 与 `image`。只允许明确定义的转换；错误指出节点与端口。图必须有输出，无隐式递归。图层图像来源遵守目标 SDK 支持的资源引用和依赖校验。

节点图的保存、编译与 `.msfx` 导出是独立操作。首版使用源文件与效果包并列保存，不假设现有包读取器允许任意新增文件。

## 编译和性能

- 纯数学及颜色节点融合成单个 fragment pass，消除重复纯表达式、折叠常量。
- 模糊等需要中间图像的节点生成多个 pass；复用既有 scratch、padding、output bounds、working space 与 alpha 合约。
- 自定义 WGSL 节点采用明确的输入输出函数模板，复用现有校验。高级代码默认作为优化屏障，不擅自重写其语义。
- 编译错误映射回节点；重编译异步进行，失败时保留上一次有效预览。
- 成本报告保留 `loop_work`、pass 数、实际 4K scratch 和资源用量。预算提示与不支持的能力分别报告，不用静态成本声称已达到某个 FPS。

## 手机导出

导出以所选手机 SDK / portable profile 为准，检查 shader 校验、资源类型、参数 ABI、循环上界、纹理能力和实际 scratch 预算。无法移植的节点给出原因与替换建议；桌面可用不自动等于手机可用。

公开参数映射到现有效果参数和原生编辑器声明，手机可调整参数并添加动画。发布时生成明确的包版本和内容 hash，保留已有工程依赖的旧版本；资源与代码来源信息随导出保留。

验收需要把导出包交给现有 `.msfx` 读取器和 Registry 重新加载，分别跑桌面 wgpu 与 Android GLES 的图像对照。验证小数帧、动画参数、透明度、颜色空间、分辨率、边界扩展和连续预览，避免只验证包能压缩出来。

## 实施顺序

1. **N1**：节点文档、类型校验、单 pass 编译器，先做输入 / 参数 / 时间 / UV / 数学 / 颜色 / 输出；导出一个真实可加载的 `.msfx`。
2. **N2**：可停靠的节点面板、连线、搜索、撤销、公开参数，接通实时预览和保存重开。
3. **N3**：多 pass 图像节点、WGSL 高级节点、移动 profile 与成本报告；增加 Android 图像验收。
4. **N4**：将 `graph_validate`、`graph_compile`、`graph_export_msfx` 接入既有 agent / MCP 工具入口，复用版本检查和权限，不增加另一套工程写入路径。

MCP 与节点编辑器共用节点文档协议，后续 agent 可以生成和修改节点 JSON，用户可在图中继续编辑。编译器与普通桌面编辑会话保持同样的错误和撤销边界。
