# UX 规格与 UI 基础设施集成

本分支 `codex/desktop-ux-styles-20261012` 处理 #162–#168，基于 `main` 的 `a3759dc`（包含 #169、#172、#173、#174）。GPU 能力检查、编译和预览安装沿用 #174 的 worker 边界。UI 不持有新的 Device/Queue。

用户的 [UX 规格](Motion-Studio-UX.md) 和 [基线对比](Motion-Studio-UX-vs-Code.md) 是设计输入；快照中的未实现功能、建议与测量结论需要与当前代码区分。

保持已确认的桌面约定：节点画布 Ctrl+滚轮、Ctrl+Space FX Console、图层／时间轴／曲线联动；轨道区不添加参考竖线，不添加斑马纹；属性分隔线整行覆盖，0.5px、低透明度。默认色板保持已有更深灰黑，设计稿的较亮色板可通过覆盖文件验证。字体保留 Microsoft YaHei 及平台回退。

核验纠正：现有 Motion 已使用 cubic-out，此次加入选项，而非从线性改为缓动。旧对比报告将 palette 字面量视为权威；本批完成后唯一色值来源是 `desktop/ui/styles/dark.json`。

完整 UX 的其他功能仍需独立交付和验收：工程主页／最近项目、命名工作区预设／管理对话框、独立合成多实例查看器，以及曲线的 AE 式速度观察模式、影响百分比、修饰键矩阵和多通道编辑。本批基础设施覆盖这些界面所需的主题与控件，但不把控件存在视为功能已完成。原快捷键 issue #107 的剩余清单也不由本批自动关闭。

后续曲线规格需要避免数学冲突：速度显示是值随时间的导数（帧导数乘 fps）；缓入缓出的速度通常为中间高、两端低；两端各 33.3% 的影响不意味着二者相加恒为 100%。Hold 的跳变处没有有限导数。不能为了模仿图形把速度直接当数值重映射，也不必为只读百分比换算修改工程格式。
